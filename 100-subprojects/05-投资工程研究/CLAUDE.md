# CLAUDE.md（100-subprojects/05-投资工程研究 子项目）

本目录是 AOS 大项目下的**投资工程研究子项目**——**产出型子项目**，工作路径为「材料准备 → 输出」，两个阶段：

- **当前阶段：材料准备期**（2026-09-19 起）。广积材料，不求产出。
- **后续阶段：输出**。产出形态（研究报告书／方法论提炼／培训材料等）**待后续确定**，届时在此补写产出清单与目录。

材料源为 `00-投资工程研究报告/`（播客/访谈转写稿、读书笔记、专题研究稿），按 `NN-` 顺号编号，新增材料直接落入该目录。

## 材料体例（沿用首份材料，2026-09-19 定）

首份材料（`00-知行小酒馆E251-…md`）确立的**整合版**体例，后续材料照此办理——单文件自足，要点与逐字稿并存，可单独阅读也可检索：

| 区 | 内容 |
|----|------|
| 标题 | `<来源> <期号> · 对话<嘉宾>：<话题>` |
| 元信息表 | 播客／主播／嘉宾／时长／链接／转写方式 |
| 说明注 | 转写保真声明（机器转写、清了什么、没改什么、校正依据） |
| 目录 | 三部分锚点链接 |
| 第一部分 · 要点摘要 | 一句话主旨／时间轴（表格：时间｜内容；**内容每行 30–90 字**，为扫读上限）／核心观点（编号小标题＋段）／值得记住的一段 |
| 第二部分 · 完整逐字稿 | `**<说话人>**：` ＋ 段落（**按说话人切分**，不用时间戳） |
| 附录 · 术语校正清单 | 校订留痕（识别串→校正为／处数／依据）＋存疑待核；分节或整表两种版式均可，**处数合计必须等于声明总数** |

**材料保真原则**：转写稿保留口语原貌（重复、语气词不删改），只做两件事——清除语音识别的复读幻觉、校正专有名词；每处校正须在说明注与「术语校正清单」中留痕，可回溯。清单属**校订工件**而非阅读材料，故置于文末附录，不打断要点摘要的阅读。

**对话体例（2026-09-20 用户定，改自首版）**：逐字稿**按说话人排版**——每轮以 `**雨白**：`（主播）或 `**方言**：`（嘉宾）开头，**不再逐段标时间戳**；只在句末标点处换人，句中的附和与应声并入正在说话的一轮，宁可粗一点也不猜。原始时间码由同名 SRT 与「时间轴」承载。**本目录材料由 [`.tools/podcast2md`](../../.tools/podcast2md/README.md) 生成**（2026-09-19 起）：播客音频一条命令跑成上述体例的 md/srt——取源 → 下载 → 本地转写 → 缺口质检补转 → 补标点 → LLM 摘要＋专有名词校正 → 组装。**体例以本节为准**，工具按此实现（说话人标注一步尚未进工具，现由人工/代理完成）；人工新增或改动材料时照此对齐。

**材料稿的 PDF 按需转**（2026-09-20 用户定，改自 09-19 的「定稿前不转」）：材料稿的常备形态是 md，PDF **不自动生成、也不随每次改动重转**——人类点名要 PDF 时再转，与 AOS 根记忆 [`feedback-no-pdf-for-drafts`](../../.claude/memory/feedback-no-pdf-for-drafts.md)「等人类说定稿/转 PDF 再跑」一致。已转出的 PDF 一经 md 再改**即视为过期**，随即重转或删除，不留不同步的旧件。转法见 AOS 根 CLAUDE.md §七（[`.tools/md2pdf`](../../.tools/md2pdf/md2pdf.js)）。

## 报告纪律（必须遵守 · 2026-09-21 用户定）

**① 一轮对话 ＝ 两份同号文件。** `NN-对话记录-…md` 与 `NN-…（研究报告）.md` **共用同一编号**（如 03），文件名不同即已区分，**不加 `-1`／`-2` 之类子序号**。

**② 两份都只在人类指令下生成。** 指令形态如「整理成对话记录和研究报告」「落盘，追加到 03 文档中」；**AI 不得自行判断收口时机**。

**③ 追加为主。** 同一议题的后续场次**追加进同一份文件**（对话记录加一场、研究报告加一部分），**不另立新文件**。

**④ 过程稿不得自成文件。** 每轮问答只在对话内作答；为落地临时生成的过程稿，收口时**删除**，实质并入正式报告。

**⑤ 每份报告自带声明。** 研究报告封面盒保留「本节追加的纪律」一行，使打开文件的人（含后续 AI）当场看到④②两条。

**判定口径**：一份文件是否该存在，问一句——**用户发过整理指令吗？** 没有，就不该存在。

**反例（有案可查）**：2026-09-21 会话中，04 号（需求资产）、05 号（复利结构）两份稿**未经指令落盘，已删除**；更早的 05–10 号七份过程稿同因删除。**教训是"何时收口只有人知道"**，AI 无法自行判断一轮对话是否结束。

**细则、判准与边界情形**见 [`claude-memory/feedback-reports-two-per-round.md`](claude-memory/feedback-reports-two-per-round.md)（含"用户点名要别的文件"与"素材类文件"两个除外情形）。

> **加载边界（重要）**：本子项目的 `claude-memory/` **不会被自动加载**（Claude Code 的自动记忆锚在 git 根；DSH 无记忆机制）。故**本节的强制力来自"CLAUDE.md 自动进上下文"，细节点查靠上面那条指针**——只把纪律写进记忆，等于没写。

## 子项目边界（项目集内 · 操作互不干扰）

本子项目是 AOS 项目集内子项目区（`100-subprojects/`）的一员，各子项目共同指向「**把不同专业的工作或事项工程化**」这一目标；本子项目负责该目标在 **投资**上的展开。**自包含在本目录内**（AOS 主 CLAUDE.md §九）：

- **处理本子项目**：工作目录 = 本目录（`100-subprojects/05-投资工程研究/`），读本文件 + `claude-memory/`。
- **处理 AOS 主项目**：工作目录 = 仓库根，读 AOS 根 CLAUDE.md + 主记忆 `.claude/memory/`——**不擅自改动其内容**，除非明确要求。
- **主题上可互引、操作上自包含**：本目录的方法与结论可被其他子项目引用，反之亦然；改动落在谁家由谁做。

## 记忆隔离协议（必须遵守）

本子项目的记忆**独立存放**，与 AOS 项目根记忆（`.claude/memory/`）**互不干扰**：

- 本子项目的记忆位于 [`claude-memory/`](claude-memory/)：`claude-memory/MEMORY.md`（索引）+ `claude-memory/投资工程研究项目.md`（主记忆）。
- **处理本子项目内容时**：先读 `claude-memory/MEMORY.md` 与相关记忆文件，写入 `claude-memory/` 目录。
- **禁止**把本子项目内容写入 AOS 根 `.claude/memory/` 或 AOS auto-memory。AOS 根 MEMORY.md 只保留一行指向本目录的指针。
- **本目录记忆不会被自动加载**，故须**主动读**：Claude Code 的自动记忆加载点锚在 **git 根**、不在工作目录，本项目拿不到自己的自动记忆（边界见 AOS 根 CLAUDE.md §八）。`claude-memory/` 的加载完全依赖本节的协议。
- 每个会话结束时，把最新状态同步回 `claude-memory/`；跨设备共享走 git（机制见 AOS 根 CLAUDE.md §八）。

## 提交边界（单仓库 + 约定分区）

仓库是 AOS 单一 git 仓库，本子项目不建独立 git。提交时按目录语义分区：

- 本子项目改动与 AOS 主线改动**分别 commit**（commit message 以 `[投资工程]` 标注归属）。
- 处理本子项目时，不把 AOS 主线改动混入本次提交；处理 AOS 主线时，不把本子项目改动混入（除非明确要求）。
