# 报告纪律：同轮同号两份，且须经指令

**2026-09-21 用户定，长期有效。**

## 一、纪律本身

1. **一轮对话 ＝ 两份同号文件**：`NN-对话记录-…md` 与 `NN-科技越发达…（研究报告）.md` **共用同一编号**（如 03），文件名不同即已区分，**不加 `-1`／`-2` 之类的子序号**。
2. **两份都只在人类发出指令后才生成**。指令形态如「整理成对话记录和研究报告」「落盘，追加到 03 文档中」。
3. **追加为主**：同一议题的后续场次**追加进同一份文件**（对话记录加一场、研究报告加一部分），**不另立新文件**。
4. **过程稿不得自成文件**：每轮问答只在对话内作答；为落地而临时生成的过程稿，收口后**应删除**，实质并入正式报告。

## 二、为什么（判准，供边界情形判断）

- **报告是给人读的结论载体，不是工作日志。** 每轮一份报告＝制造噪声文件，稀释"哪一份才是结论"。
- **同号是分类信号**：一眼看出这两份是同一议题、同一轮对话的产物（一份过程、一份结论）。
- **须经指令是因为"何时收口"只有人知道**：AI 无法判断一轮对话是否已经结束——这正是本会话出现的反例（04／05 号稿未经指令落盘）。

## 三、反例与后果（有案可查）

**本会话（2026-09-21）出现两次违规**：

| 反例 | 情形 | 后果 |
|------|------|------|
| 04 号需求资产、05 号复利结构 | 用户只在对话中追问，AI 却各落一份稿 | **两份均已删除**，实质并回对话并留档记忆，收口时并入研究报告第九部分 |
| 05–10 号七份过程稿（更早） | 同题逐轮迭代，各成一份 | **七份均已删除**（其中七份从未进入 git 历史，删除后工作区与索引自洽） |

**判定口径**：一份文件是否该存在，问一句——**用户发过整理指令吗？** 没有，就不该存在。

## 四、执行落点（谁来保证它被执行）

| 层 | 文件 | 作用 |
|----|------|------|
| **① 权威规则源** | 本子项目 `CLAUDE.md`「报告纪律（必须遵守）」节 | 打开本目录即自动加载；AI 的可见约束 |
| **② 细则与判准** | 本文件（`claude-memory/feedback-reports-two-per-round.md`） | 为什么、反例、判定、边界情形 |
| **③ 文件自带声明** | 每份报告的封面盒（研究报告的「本节追加的纪律」一行） | 打开报告的人（含后续 AI）当场看到 |
| **④ 索引** | `claude-memory/MEMORY.md` 一行摘要 | 保证这条不被埋没 |

**注意**：子项目的 `claude-memory/` **不会自动加载**（Claude Code 的自动记忆锚在 git 根；DSH 无记忆机制），故**必须由 ① 承载强制力、③ 承载当场可见性**——只写进记忆等于没写。

## 五、边界情形

- **用户明确点名要别的文件**（如"给我一份可打印的工具表单"）→ 照办，不受本纪律限制；
- **素材类文件**（播客转写稿、图书全文）→ 属另一类，编号规则见 `CLAUDE.md`「编号规则」节，不受本纪律限制；
- **收口时是否需要删除过程稿**→ 是；删除前先确认其实质已并入正式报告（本会话两次删除均如此处理）。
