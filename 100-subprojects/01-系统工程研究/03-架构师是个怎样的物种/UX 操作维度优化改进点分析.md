UX 操作维度优化改进点分析
总结论
操作层最伤体验的是五件事：关键操作没有安全网（编辑无离开保护、删除有无确认直删）、反馈不可预期（错误会叠弹、存在假成功、warning 轰炸）、返回现场不可靠（keep-alive 疑似 bug + 缓存键设计问题 + 401 硬跳转丢现场）、同类任务操作路径不统一（编辑四种形态、双击行为不一致、关键功能藏在右键）、等待没有叙事（导出无任何反馈、下载失败弹原生 alert）。以下按操作旅程分七类展开。

一、检索与浏览操作（找数据）

1. 主力列表页的搜索可发现性依赖 hover。 全站主交互是 ag-common-table 表头搜索（hover 才浮现过滤入口），对熟练用户高效，但新用户找不到“搜索框在哪”；而独立的高级搜索组件（AdvancedSearch，AND/OR 条件构建器）只接了 8-9 个配置弹窗场景，bpmn 和 entity 还各自手写了一套重复的 advanceSearchPanel。三套搜索体验割裂。 → 建议：表头搜索保留为主交互，但给列表加一个常驻的“搜索/筛选”入口按钮（点开聚焦首个表头过滤），并把 AdvancedSearch 确立为唯一的“高级条件”形态，删掉两套手写副本。

2. 空态无区分、无引导。 EmptyState 组件（无数据/筛选无结果两态 + 清除筛选按钮）已建好但 0 使用；全站依赖 el-table 默认“暂无数据”，用户筛选后看到一片空白，分不清“没数据”还是“筛错了”。筛选条件也没有统一的“已筛选 N 项，清除”提示条。 → 建议：接入 EmptyState 到 ag-common-table / base-table 封装层（改 2 个组件覆盖全站），筛选空态提供一键清除。

3. 返回列表后查询条件保留不可靠。 这是后台系统最核心的体验之一，目前有三层隐患：

page/index/index.vue 里被 keep-alive 缓存的是 !$route.meta.keepAlive 的页面（反直觉写法），而 permission.js 维护的字段叫 meta.$keepAlive——字段名对不上，疑似 bug，配置了缓存的页面可能实际没缓存；
缓存 key 用 $route.fullPath 且 :max="4"——同一页面带不同 query 会各占一个缓存槽，4 个槽很容易被挤掉，从详情页返回列表时查询条件“有时在有时不在”，行为不稳定；
64 个文件靠 activated() 里 refresh() 重新拉数兜底，刷新会重置回第一屏数据。
→ 建议：先修字段名 bug；缓存 key 改为路由 name + 受控 query 白名单；明确“列表页默认缓存、详情页不缓存”的规则，让“点进详情再回来还在原位”成为 100% 可预期的行为。

二、编辑与提交操作（改数据）

4. 同类“编辑”任务四种操作形态。 实体编辑是全页跳转（entity 右键→push /entity/detail）、主数据字段编辑是 1000px 弹窗、buildEntity 选实体是另一种 el-dialog、formLabel 运行时按配置在弹窗/右窗/双窗/内嵌面板间切换。用户在 A 模块学会的“编辑怎么打开、关掉后去哪”到 B 模块全部作废。 → 建议：在交互规范里定“弹层使用矩阵”（轻量编辑≤弹窗、结构化维护→右窗/双窗、深度配置→整页），新功能强制对表，存量按矩阵渐进归位。

5. 表单无未保存离开保护。 beforeRouteLeave 全站只有 2 个文件、onbeforeunload 只有 1 个——用户在长表单里填了半屏，误点页签“关闭其他/关闭全部”、或切换菜单，输入直接丢失且无任何提示。这和多页签外壳（页签右键可批量关闭）组合起来风险放大。 → 建议：在整页编辑（entity/detail 等已存在的 formTitleCls 表单页）统一接 mixin：脏检查 + $confirm 拦截；弹窗编辑统一 close-on-click-modal=false（这点已做得好，见文末“做对的”）+ 关闭前脏检查。

6. 校验反馈双轨且时机抖动。 同一系统里校验失败有时是行内红字、有时是 toast 弹出（12+ 处手动 $message.warning(errors[0])），subBizPage.vue:303 还套了 setTimeout 300ms 补偿时序——用户看到的提示顺序、样式、时机都不可预期；校验文案还有“请填把数据填写完整”“不能为为空”这类错别字。 → 建议：统一为 el-form 行内提示为主 + 提交时滚动到第一个错误字段并聚焦；文案收进 rules.js 统一维护。

7. 保存成功后的行为有四种，包括假成功。 关弹窗回传 / 只 toast 不关不刷 / toast+刷新 / 前端本地 splice 后直接弹“删除成功”不发请求（business.vue:639-652）。假成功会让用户以为删了，刷新后又出现，属于信任级伤害。 → 建议：定死三种标准收尾（保存并关闭 / 保存并继续 / 删除后刷新），伪成功分支改为真实请求；那个校验失败却弹“操作成功！”的分支是 bug，直接修。

三、破坏性操作（删数据）

8. 删除操作零危险视觉 + 确认缺失。 base-button（986 处使用）不支持 type，全库 danger 样式仅 1 处；basecomsout.vue:361 / basecomsin.vue:372 两处删数据不弹确认；有确认的 166 处文案 4+ 种写法、不带对象数（“确定要删除选中记录吗？”而不是“将删除 3 条记录”）。 → 建议：confirmDanger('删除', n) 统一封装（含数量、后果说明）；base-button 透传 danger；批量删除按钮在未选中时置灰而非点击后警告。

四、反馈与等待（知道系统在干什么）

9. 错误会叠弹。 axios 拦截器（request.js:102 Notification.error / :120 Message.error）+ 页面 53 处 catch 自己再弹 → 一次失败经常弹两个内容相似的错。尤其 401：每个并发请求各弹一个 MessageBox（request.js:85-99 无 once 去重），会话过期瞬间可能弹出 N 层“登录状态已过期”。 → 建议：拦截器做错误去重（同 2 秒内相同文案只弹一次）；401 加 pending 标志只弹一个。

10. 长操作无反馈叙事。 导出下载无 loading、无进度（download.js 超时设 0=无限等），失败弹的是原生 alert()——与整个 element 视觉体系割裂；全站 element-loading-text 只有 1 处使用，loading 遮罩全是干等；导入这种可能几十秒的操作同样没有阶段反馈。 → 建议：导出统一“按钮 loading → 完成 toast（含文件名）→ 失败 $ux.error”；导入加进度条或至少阶段文案。

11. warning 轰炸。 $message.warning 859 处是全站最高频反馈，超过 success 和 error——大量本应用行内提示/表单校验表达的信息都弹成了 warning toast，用户操作几步就弹好几个，注意力被切碎。 → 建议：归位语义——表单问题行内提示、结果确认用 success、只有“阻断性风险”才用 warning/error toast。

五、导航与页签（去别处再回来）

12. 关键功能藏在右键菜单里。 entity 列表的“编辑”只在右键菜单里（index.vue:628-636），22 个文件依赖 contextmenu。右键对高级用户友好，但可发现性为零，且和触控板/窄屏用户绝缘。 → 建议：右键菜单保留为快捷方式，但每个右键功能必须在显性位置（工具栏或行内按钮）有对等入口。

13. 页签能力缺一角。 tags.vue 右键菜单里“刷新”功能被注释掉了——用户想刷新单个页签内容只能按 F5 整页刷新（丢其他页签状态）；面包屑组件存在但顶栏被注释，列表页基本无页头，深层级页面用户不知道自己在哪。 → 建议：恢复页签“刷新”（配合 keep-alive 的 key 重置即可）；面包屑接回（组件已有，成本极低）。

六、键盘与效率操作

14. 回车提交覆盖零散。 keyup.enter 全站 27 处/16 文件，集中在登录页和树搜索；业务搜索区、弹窗表单基本不支持回车提交/搜索。 → 建议：弹窗确定按钮加 native-type="submit" 或统一监听回车；搜索输入框回车触发查询做成封装默认行为。

15. 双击行打开行为不一致。 23 个文件有 dblclick 处理（有的双击行开详情、有的双击单元格进编辑），但覆盖面不到列表页一半——用户会“习惯性双击”然后发现有的页面有反应有的没有。 → 建议：在 ag-common-table 封装层提供 row-dbl-click 统一配置（双击行=打开详情/编辑），一次性对全站生效。

七、会话与异常恢复

16. 会话过期后现场全丢。 401 确认“重新登录”后走 location.href = "/index"（request.js:97）硬跳首页——用户正在填的表单、所在页面全部丢失，登录后也回不到原页面（没有 redirect 参数）。 → 建议：登录态失效先静默尝试续期；必须重登时记录 redirect 参数，登录成功回跳原路由；表单类页面配合第 5 条的草稿/脏数据保护。

17. 拦截器里遗留 console.log(code, res, "code")（request.js:64）——每个响应都打日志，大数据量表格时控制台刷屏且有小幅性能损耗，也属于调试残留。

做对的（保持并推广）

弹窗误关保护已统一：74 处 close-on-click-modal 全部显式 false——这是很多项目都做不到的一致性。
分页选项集中在 pageSizes 变量/pagingOptions 下发，未碎片化。
表头搜索（熟练用户效率高）、侧栏菜单搜索 + 收藏 + 最近浏览、页签右键批量关闭——导航效率基建是好的。
