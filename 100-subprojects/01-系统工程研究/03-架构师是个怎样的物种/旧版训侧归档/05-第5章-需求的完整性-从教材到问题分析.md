## 第 1 步 · 剖章立骨：核心内容地图

**这一章回答的问题**：产品需求要"全"，全在哪三类？为什么"样机验证通过"不等于"产品成功"？三类需求各自来自谁、为什么可实现性需求客户根本不关心？承制方为什么是需求的主导方？一个组织怎么才能不反复踩"可实现性缺失"的坑？

### 核心概念

1. **需求完整性**（completeness of requirements）：产品需求要全 = 功能 + 环境适应性 + 可实现性三类，每类"及其指标"；缺一类交付物降一级（原理样机/环境样机/产品）。
2. **功能需求**（functional requirement）：系统所具备的行为特征，以 IPO（输入/处理/输出）定义；**客户/使用者在问**；自带四层展开分解链。
3. **环境适应性需求**（environmental adaptability requirement）：对气候、国家、文化、风俗、法律等各类环境的适应；统一句式"在 X 环境下，产品必须 Y"；**使用环境在问**。
4. **可实现性需求**（realizability requirement）：全生命周期"方便实现" + 经济可承受，共八项；**承制方在问**；实现方案是它的符合性解答。
5. **验证载体**（validation vehicle）：每类需求的专属验证交付物——原理样机 / 环境样机 / 真正的产品；需求类别 → 验证条件 → 交付物。
6. **承制方主导**：产品需求开发由承制方主导（捕获、分析、建模、引导范围、形成条目），相关方只保留确认终审权。

### 对立概念

| 核心概念 | 对立面 | 问什么 |
|---|---|---|
| 需求完整性 | 功能清单 | 把"产品需求"当"功能清单"——最常见的伪全 |
| 三类需求 | 功能 / 非功能二分 | "非功能需求"是一个大筐，装着两类主人、来源、验证载体都不同的需求 |
| 验证载体 | 用一个载体验全部需求 | 用原理样机的通过宣布产品成功 |
| 可实现性需求 | 后续工艺/实现的事 | 它是产品的固有特性，必须体现在相关方需求中，不是实现阶段才出现 |
| 承制方主导 | 客户主导 | "客户说、承制方记"——承制方更专业，是主导方而非转述方 |
| 环境适应性需求 | 仅自然环境 | 环境是广义的：法规环境、社会文化环境都算 |

### 关联概念（近界 · 辨析）

- **功能/非功能二分 ⊂ 三类需求**："非功能需求"大筐里装着环境适应性和可实现性——两类主人、来源、验证载体都不同的需求。
- **验证载体 × 评审/验证/确认（第7章）**：载体回答"每种需求用什么证明"，看门人回答"验证动作怎么分、对照什么"——载体是"拿什么验证"，看门人是"验证时对照什么"。
- **需求完整性 × 需求工程（第4章）**：ch4 立"标尺从哪来"、ch5 立"标尺要全"——认知链上紧挨的两格。
- **需求完整性 × 需求定义（第3章）**：三类各"及其指标"，落地 ch3"需求必须可判定——不可衡量则不成为需求"。
- **功能需求四层展开 × 第6章分解**：业务用例 → 业务场景 → 系统用例 → 用例场景，是第6章"分解"在需求侧的源头。
- **可实现性需求 × 实现方案**：三对齐（过程→需求→方案锁死），实现方案是可实现性需求的符合性解答。
- **承制方 × 来源方 × 确认方**：主导（加工）vs 来源（原料）vs 确认（终审）——三分工；引导可以激进、确认不能缺席。
- **可实现性需求资产 × 第11章/第12章**：基于资产开发方法论（ch11 架构决策、ch12 配置管理依赖的那套）在需求侧最重要的落点。
- **需求资产 × 配置信息**：四步闭环是"产品数据的运维反馈反哺下一代设计"在需求层的体现（ch12 展开配置信息怎么被记录）。
- **经济可承受性 × 设计期决策**：成本是需求不是结果；控制成本的杠杆全是设计期决策，等发现贵了架构与物料清单已冻结。

### 核心原理

1. **三类全原理**：产品需求要全 = 功能 + 环境适应性 + 可实现性三类，每类"及其指标"；缺功能连原理样机都算不上、缺环境停在原理样机、缺可实现停在环境样机。
2. **同构原理**：构件需求与系统需求完全同构——同一模板在两级上的复现。
3. **谁在问原理**：分类的判据不是特性本身，而是"谁在问"——客户问功能、环境问适应、承制方问可实现；同一特性（测试性）两个主人、两种归类。
4. **及其指标原理**：三类需求各"及其指标"，没有指标的需求都退化成愿望。
5. **因果链原理**：需求类别 → 决定验证条件 → 决定交付物形态——三对三不是巧合，是因果。
6. **验证条件互斥原理**：三类需求需要的验证条件互不相容（原理要剥离环境单独验、环境要上真实环境、可实现要量产经济性约束下验），一个载体替不了另一个。
7. **专属验证原理**：每类需求有且只有一个专属验证载体；可实现性需求只有真正的产品——量产、交付、运维跑过一遍——才能验证。
8. **逐级完备 ≠ 专属验证原理**：交付物逐级完备（环境样机必须先把功能做全）让人误以为三段累加，但关键在"每类需求一个专属载体"。
9. **功能自带分解链原理**：功能需求是三类里唯一"自带分解通道"（业务用例→业务场景→系统用例→用例场景）；环境/可实现的通道分别是环境分析和实现方案。
10. **功能陷阱原理**：功能需求的陷阱不是"没人提"，而是"提了但没提对"——客户自信满满说出的往往是方案，不是需要，需求分析师要穿透到"真正的需要"。
11. **环境广义原理**：环境是广义的（法规、社会文化都算）；捕获关键不是技术，是先决定产品将投放的完整环境集，再逐项确认。
12. **八项三对齐原理**：可实现性需求 = 八项 + 三对齐（过程→需求→方案锁死）；实现方案是对可实现性需求的符合性解答，一条缺了对应方案和过程没有依据。
13. **可实现来源第一原理**：可实现性需求的相关方都是承制方——不是客户提的，是组织对自己提的；客户不在乎你制造方不方便。
14. **三角原理**：来源方提供原料、承制方主导加工、相关方执行验收；内容由承制方主导、成立由相关方确认。
15. **承制方专业四因原理**：客户知道要什么，但不知道四件事（什么技术可能/行业横向视野/标准与环境/资产沉淀），而这四件事都是承制方强项，故承制方主导。
16. **主动引导原理**：承制方主动引导——把客户"想要的"穿透成"需要的"、提出客户没想到的需求、建议技术路线和范围、把可实现性约束主动注入需求。
17. **引导边界原理**：承制方引导（可以激进）+ 相关方确认（不能缺席）；一旦越界替相关方做决定，需求就失去"对需要或期望的规范性陈述"的本质。
18. **责任承制方原理**：需求全不全、明不明确、可不可度量，是承制方责任，不是客户的——客户可以说不知道，承制方不能说"客户没提，所以需求不全"。
19. **可复用性最高原理**：可实现性需求可复用性最高——组织的供应链、工艺、设备、人员约束跨产品持续存在，痛点几乎是常量，最适合基于组织资产开发。
20. **四步闭环原理**：问题/经验/建议 →（转化）→ 可实现性需求资产 →（复用）→ 新产品需求 →（产生新问题）→ 回到起点；关键是"转化"——问题被提炼成规范性需求条目，不是照抄。
21. **自觉机制原理**：判断组织自不自觉只看一条——有没有制度化的回路：问题 → 分析 → 转成需求条目 → 入库 → 新产品复用 → 复盘更新。
22. **无资产必然缺失原理**：没有资产库、没有自觉积累机制的组织，天然捕获不到全面的可实现性需求——不是承制方代表不肯说，是组织没有可复用的资产可提。
23. **四错位原理**：相关方错位（相关方是承制方不是客户）/ 时间错位（延迟爆发、最晚最贵）/ 话语权错位（采购制造运维没有在需求阶段发声的机制）/ 认知错位（把可实现性当后续工艺的事）——四个结构性错位让团队"不太考虑可实现性"。
24. **症状=缺失需求原理**（逆向诊断）：每个"不方便"都对应一条当初没写进相关方需求的可实现性需求——症状不是执行问题，是需求缺失问题。
25. **成本是需求原理**：产品成本是相关需求及其分解、分配、分析的结果，不是设计出来的；没有成本相关需求，设计没有依据和目标，成本自由落体。
26. **成本相关方原理**：经济可承受性的相关方是市场代表（基于对竞品/替代产品的价格成本研究给出建议），不是财务、不是客户。
27. **成本验证最晚原理**：成本要到全生命周期成本记录才能验证，几乎不可逆；控制成本的杠杆（标准外购件/避免定制外包/自研核心模块）全是设计期决策，等发现贵了架构和物料清单已经冻结。
28. **问题不转资产原理**：当一个团队说"下次吸取教训"，先问这次的问题有没有变成一条可复用的需求——问题不转成资产，教训就永远是教训，而不是护城河。

### 对立误解（喂给第 3 步误解库 / 第 4 步陷阱清单）

1. "原理样机验证通过了，产品就成功了。"（× 只验证了功能需求；环境未验、可实现没进需求清单）
2. "需求写全了 = 功能写全了。"（× 功能只占三分之一；缺可实现交付物停在环境样机）
3. "可实现性需求是后续工艺的事，不归需求管。"（× 它是产品固有特性，必须体现在相关方需求中）
4. "成本是算出来的，设计完再核算。"（× 成本是需求分解分配分析的结果，没设成本需求设计没有优化目标）
5. "客户不关心的需求，就是不重要的需求。"（× 可实现性客户根本不关心，但它决定组织能不能活）
6. "承制方就是听客户要什么就做什么。"（× 承制方是主导方，引导范围、塑造需求）
7. "需求不够全，是客户没提清楚。"（× 需求全不全是承制方责任；客户可以不知道，承制方不能说"没提所以不全"）
8. "量产翻车是制造/采购/运维没做好。"（× 每一个"不方便X"都是一条当初没写进需求的可实现性需求）
9. "一个特性（测试性）是哪一个类，看特性的名字。"（× 分类判据是"谁在问"；同一特性两个主人两种归类）
10. "样机、环境样机、产品是需求逐级累加的三段，做完三段就全了。"（× 逐级完备 ≠ 专属验证）
11. "环境需求就是适应自然环境的。"（× 环境是广义的：法规、文化、社会）
12. "可实现性需求客户会提，客户在乎你造得方不方便。"（× 客户不在乎，是组织对自己提的）
13. "我们组织经验很丰富，口口相传，就是在自觉积累。"（× 散/隐/无法复用的资产不是资产）
14. "量产时发现物料难买、零件难造，是执行环节该改进。"（× 症状=缺失的需求，逆向诊断）
15. "降本大会开完了，成本问题就解决了。"（× 每次降本动作都等于承认经济可承受性需求当初没写）
16. "成本是财务的事，控成本找财务。"（× 经济可承受性的相关方是市场代表）
17. "需求分析就是访谈客户，客户说什么记什么。"（× 承制方主导加工）
18. "组织说'下次吸取教训'，就是在积累。"（× 问题不转成资产，教训永远是教训）

### 本章判据（七把尺子）

1. **三类全判据**：需求要全 = 功能 + 环境适应性 + 可实现性，每类"及其指标"，缺一类交付物降一级（原理样机/环境样机/产品）。
2. **专属验证载体判据**：每类需求一个专属验证载体——功能→原理样机、环境适应性→环境样机、可实现性→真正的产品；"样机通过≠产品成功"。
3. **谁在问判据**：分类的判据是"谁在问"——客户问功能、环境问适应、承制方问可实现；同一特性（测试性）两个主人、两种归类。
4. **承制方主导判据**：承制方主导 + 相关方确认——引导可以激进、确认不能缺席；需求全不全、明不明确、可不可度量，问责承制方。
5. **八项三对齐判据**：可实现性需求 = 八项 + 三对齐（过程→需求→方案锁死）；实现方案是可实现性需求的符合性解答。
6. **资产机制判据**：没有资产库、没有自觉积累机制的组织，天然捕获不全可实现性需求——问题不转成资产，教训永远是教训。
7. **逆向诊断判据**：团队每抱怨一个"不方便X"或"成本大"，就反推一条缺失的可实现性需求；降本大会 = 承认经济可承受性需求当初没写。

## 第 2 步 · 量学立标：掌握清单

### 概念层（应能定义与辨析）

1. 能定义"需求完整性"（三类 + 指标）并说出缺一类的交付物降级后果。
2. 能定义"功能需求"（行为特征、IPO 定义）并说出是"客户/使用者在问"、自带四层展开。
3. 能定义"环境适应性需求"（对气候/法规/文化等环境的适应）并说出是"使用环境在问"、统一句式"在 X 环境下必须 Y"。
4. 能定义"可实现性需求"（全生命周期方便实现 + 经济可承受，八项）并说出是"承制方在问"。
5. 能辨析 功能/非功能二分 ⊂ 三类需求（"非功能需求"大筐装着两类主人不同的需求）。
6. 能定义"验证载体"并背出三对三（功能→原理样机、环境适应性→环境样机、可实现性→真正的产品）。
7. 能辨析 逐级完备 vs 专属验证（三段累加 vs 每类一个专属载体）。
8. 能定义"承制方主导"并辨析 承制方/来源方/确认方 三分工。
9. 能说出功能需求四层展开链（业务用例→业务场景→系统用例→用例场景）。
10. 能背出可实现性需求八项 + 各自对应全生命周期过程 + 对应方案 + 提出者。
11. 能定义"经济可承受性"（八项里的总账）并说出相关方是市场代表。
12. 能说出四个错位（相关方/时间/话语权/认知）各自让哪类需求漏掉。
13. 能定义四步闭环（问题→资产→复用→新问题）并说出关键是"转化"。
14. 能定义"自觉积累"判据（制度化回路：问题→分析→条目→入库→复用→复盘）。
15. 能说出"逆向诊断"操作（症状"不方便X"→ 反推缺失需求条目）。

### 原理层（应能解释为什么）

1. 能解释为什么"需求写全了 = 功能写全了"是伪全（功能全只够造原理样机）。
2. 能解释为什么分类的判据是"谁在问"、为什么同一特性有两个主人。
3. 能解释为什么每类必须"及其指标"（没有指标的需求退化成愿望）。
4. 能解释为什么三对三是因果不是巧合（需求类别→验证条件→交付物）。
5. 能解释为什么一个载体替不了另一个（三类验证条件互不相容）。
6. 能解释为什么"样机通过≠产品成功"（可实现性只有真正的产品能验证）。
7. 能解释为什么功能需求是三类里唯一自带分解链的（第6章分解在需求侧的源头）。
8. 能解释为什么功能需求的陷阱是"提了但没提对"（客户说出的往往是方案不是需要）。
9. 能解释为什么环境是广义的、为什么捕获关键是先决定完整环境集（法规是"摘录"动作）。
10. 能解释为什么实现方案是可实现性需求的符合性解答（三对齐锁死）。
11. 能解释为什么可实现性需求是组织对自己提的（客户不关心、组织要活下去）。
12. 能解释为什么承制方更专业（客户不知道四件事）从而主导需求。
13. 能解释为什么引导可以激进、确认不能缺席（越界=一厢情愿，失去规范性陈述本质）。
14. 能解释为什么需求全不全问责承制方（客户可以说不知道自己要什么）。
15. 能解释为什么可实现性需求可复用性最高（痛点跨产品是常量），最适合基于资产开发。
16. 能解释四步闭环为什么关键在"转化"（问题照抄进需求不是资产）。
17. 能解释为什么没有资产库的组织天然捕获不全可实现性需求（没有资产可提）。
18. 能解释四个错位为什么让团队"不太考虑可实现性"（最晚最贵最没话语权）。
19. 能解释为什么成本是需求不是结果、为什么降本大会=承认当初没写。
20. 能解释为什么"下次吸取教训"要先问问题有没有变成需求（不转资产教训永远是教训）。

### 判据层（应会用）

1. **三类全判据**：需求文档拿来，先问"三类都全吗、每类带指标吗"——缺一类，交付物降一级。
2. **专属验证载体判据**：每一类需求问"用什么交付物验证它"——答不上来的那类，就是需求没写全的证据。
3. **谁在问判据**：一条需求分类时问"谁在问"——客户/环境/承制方；分不清的那条，往往是两类混淆点。
4. **承制方主导判据**：需求全不全、明不明确——问责承制方；引导可以激进、相关方确认一次不能省。
5. **八项三对齐判据**：八条可实现性需求各配对应方案吗——一条缺了，对应方案和过程没有依据。
6. **资产机制判据**：组织有没有制度化回路——没有资产库的组织，天然捕获不全可实现性。
7. **逆向诊断判据**：听到"不方便X/成本大"就反推缺失需求条目——不补就再踩一遍。

### 纠错红线十条

1. **先表态后翻案**：先让学员说出判断（"样机通过=成功，你们信吗"），再翻，不让结论先入。
2. **反转精确不造新误解**：反转不说"功能需求不重要"——功能是第一类、最先验证、客户第一关心；不说"客户不重要"——成立以相关方确认为准，只是内容不由客户主导。
3. **判据配机制**：每条反转都有"为什么"（因果链/验证条件互斥/四错位/成本是需求）和"怎么当场验证"（判据）。
4. **归责到可对照动作**：不归咎"小林/老陈"，落到"八条需求写没写 / 谁在问 / 用什么载体验证 / 有没有资产库 / 谁在需求阶段发声"这类可查动作。
5. **教机制不教断言**：教"为什么样机证明不了量产、为什么客户说不出四件事、为什么降本大会是承认没写"，不教"小林是错的"。
6. **先立尺子再翻案**：先给判据（三类全/专属载体/谁在问/承制方主导/八项三对齐/资产机制/逆向诊断），再翻冰链案例。
7. **拉开强度层次**：★★★ 常识（样机通过=成功 / 需求全=功能全 / 量产翻车是制造没做好 / 承制方听客户的）重点翻，★★ 次之。
8. **每个纠正落到可操作动作**：讨论完给"回去做一件事"。
9. **单一权威不另立标准**：判据引用书七把尺子，不发明新尺子。
10. **网搜当佐证**：N1~N7 只作"这不是我一个人说的"佐证，药与判据全在书内。

## 第 6 步 · 化尺为用：落地工具

### 作业指南（主产出）：给部门最近一次产品/项目做"需求完整性体检"

> 目标：用七把尺子检查"需求起点全不全"，产出三件可执行改进。
> 场景：回部门落地。时长：2 小时内完成一次体检，两周后复查一至两项。

1. **查三类全（尺1 · 三类全判据）**：拿一份需求文档，每条标"谁在问"（客户/环境/承制方）——三类各有多少条？缺哪一类？最近一次"翻车"，翻的是哪一类？产出：三类覆盖一句话。
2. **查指标（尺2 · 三类全判据·及其指标）**：每类挑一条，"有指标吗"（功能：吞吐/响应/精度；环境：目标值/条件/单位；可实现：目标成本/公差/交期/服务周期）？没有指标的那类退化成愿望。产出：无指标需求清单。
3. **查专属载体（尺3 · 专属验证载体判据）**：每一类问"用什么交付物验证它"——功能→原理样机、环境适应性→环境样机、可实现性→真正的产品。答不上来的那类，就是欠账。产出：载体缺口一行。
4. **查承制方主导（尺4 · 承制方主导判据）**：需求全不全、明不明确，问责对象是谁？访谈对象里有没有采购/制造/测试/交付/部署/运维/市场代表在需求阶段发声？产出：相关方清单。
5. **查八项三对齐（尺5 · 八项三对齐判据）**：八条可实现性需求（可采购性/可制造性/可测试性/可交付性/可部署性/可运维性/可回收性/经济可承受性），每条对应方案有没有？一条缺了，对应方案和过程没有依据。产出：缺项清单。
6. **查资产机制（尺6 · 资产机制判据）**：组织有没有制度化回路（问题→分析→转条目→入库→复用→复盘）？最近一次事故/问题，变成一条可复用的需求条目了吗？产出：回路现状 + 卡点。
7. **查逆向诊断（尺7 · 逆向诊断判据）**：团队最近一次"不方便X"或"降本大会"，反推出哪条需求当初没写？补写了吗？产出：缺失需求条目。

**卡住怎么判断**：任一尺子打不出勾，就是该尺子说的缺口——不用全打完，找到第一个"否"就能开工。产出三件最该改进事项（每条 = 一个可检查动作）。

### 工作检查单（配套素材）

| 检查项 | 是/否 | 否 → 可讨论发现 |
|---|---|---|
| 需求文档三类都覆盖（功能/环境适应性/可实现性）？ | □ | 缺可实现 → 交付物是环境样机不是产品 |
| 每类需求都"及其指标"？ | □ | 没有指标的需求退化成愿望 |
| 每类需求答得出"用什么交付物验证"？ | □ | 答不上来的那类 = 需求没写全的证据 |
| 承制方各业务代表（采购/制造/测试/交付/部署/运维/市场）在需求阶段发声？ | □ | 相关方错位 → 可实现性需求系统性漏失 |
| 八项可实现性需求各配对应方案？ | □ | 一条缺了，对应方案和过程没有依据 |
| 组织有制度化回路（问题→资产→复用→复盘）？ | □ | 没有资产库 → 天然捕获不全可实现性需求 |
| 最近一次"不方便X"反推出缺失需求并补写？ | □ | 症状=缺失的需求；不补就再踩一遍 |

## 第 7 步 · 淬问成题：题卡（10 题 2×5）

### 第一组 · 概念与原理（5 题）

**Q1（见树见林① · 概念本身 · 破题）**
"小林宣布：『原理样机验证通过，我们的产品成功了。』老陈反问：『你们管这些叫成功？定制芯片买不到、注塑做不出来、精度靠手工校准。』——产品需求要'全'，全在哪三类？把'需求写全了'当成'功能写全了'，错在哪？"
追问：① 三类各自缺一项，交付物停在什么等级（缺功能→连原理样机都算不上 / 缺环境→停在原理样机 / 缺可实现→停在环境样机）？② 每一类为什么必须"及其指标"——没有指标的需求退化成什么（愿望）？③ 反身：你们最近一次需求评审，讨论的是"功能写全没写全"，还是"三类都全没全"？

**Q2（见树见林② · 概念关系）**
"请给出 三类需求、三个验证载体、三个主人 的对应关系（一句话）。再把'承制方主导'放进整条链——它站在哪一环？"
追问：① 功能→原理样机、环境适应性→环境样机、可实现性→真正的产品——这个三对三是巧合还是因果（需求类别→验证条件→交付物）？② 三个主人各问什么（客户问"做不做得到"、环境问"守不守规矩"、承制方问"造不造得出、造不造得起"）？③ 可实现性需求为什么是"八项 + 三对齐"——实现方案和需求是什么关系（符合性解答）？④ 三类需求各自来自谁——哪一类最依赖组织长期自觉积累的资产（供应链/工艺/设备/人员约束跨产品持续存在）？

**Q3（谁在问判据 · 概念层）**
"『测试性』为什么既出现在环境适应性需求里、又出现在可实现性需求里？同一个特性，怎么会是两个类？"
追问：① 分类的判据是特性的名字，还是"谁在问"？② 可测试性在"使用环境"下被问（在役可测、维修可达）和在"承制方生产交付"里被问（产线方便测、出厂可测），各指什么？③ 真悖论收束："测试性就是测试性（特性名字只有一个）" vs "同一个特性两个主人（谁在问决定归类）"——两个都对，靠什么判据分清？④ 反身：你们文档里有没有一条特性同时出现在两个"类"里？当时是按名字分的，还是按谁在问分的？

**Q4（专属验证载体 · 真悖论收束）**
"老陈说：『原理样机验证通过，只能证明它是一台好的原理样机。』——这句话精确在哪？小林把'样机验证通过'当'产品成功'，做对了一件事、漏掉了一件事，分别是什么？为什么一个载体替不了另一个？"
追问：① 老周做对了什么（原理样机验证了温控 2℃±1℃ 的功能原理成立，这一关他过得漂亮）？② 漏掉了什么（环境适应性还没验——冷链车振动、温差、-20℃ 环境曲线还平不平；可实现性根本没写进需求清单——定制料断供、注塑结构做不出、手工校准没人会）？③ 为什么"一个载体替不了另一个"——三类需求的验证条件为什么互不相容（原理验要剥离环境、环境验要真实环境、量产验要量产经济性约束）？④ 真悖论收束："样机验证通过（功能原理成立）" vs "产品成功（三类都全）"——两个都对，靠什么判据分清？⑤ 反身：你们的产品/系统最近一次"验证通过"，验证的是哪一类需求？

**Q5（承制方主导 · 真悖论收束）**
"需求的内容到底谁定？'客户说了算'和'承制方说了算'——两个都对，怎么分？"
追问：① 来源方/主导方/确认方三角——各是谁、干什么（原料/加工/验收）？② 客户知道要什么，但不知道哪四件事（什么技术可能/行业横向视野/标准与环境/资产沉淀）？③ 承制方引导的边界在哪——"引导可以激进"和"确认不能缺席"为什么缺一不可？④ 真悖论收束："需求成立由相关方确认（客户说了算）" vs "内容由承制方主导、需求全不全问责承制方（承制方说了算）"——两个都对，靠什么判据分清？⑤ 归责：你们说"需求不够全"的时候，归给谁了——客户没提清楚，还是承制方没写全？

### 第二组 · 落地与实践（5 题）

**Q6（逆向诊断 · 真悖论收束 · 冰链量产翻车）**
"老陈会后列了八条'不方便'：定制芯片最小起订量五万片、注塑结构和壁厚做不出来、手工校准没人会、电源适配器没认证、固件没有远程升级通道、备件库里没有温控模块、电池按环保新规要回收、成本超预算 40%。小林说：『这是制造/采购/运维没做好。』老陈说：『这是需求当初没写。』——谁对？"
追问：① 八条"不方便"分别对应哪八条可实现性需求（可采购性/可制造性/可测试性/可交付性/可部署性/可运维性/可回收性/经济可承受性）？② 真悖论收束："症状在量产（执行层确实难做、团队确实尽力）" vs "根子在需求起点（当初没写、八条全是缺位需求）"——两个都对，靠什么判据分清？③ 为什么团队会犯"相关方错位"——可实现性需求的相关方是谁（承制方），团队却只访谈谁（客户）？④ 反身：你们最近一次"量产翻车/上线翻车"，症状是哪个"不方便"？当时的需求评审为什么没人提？

**Q7（判据运用 · 恒信镜照）**
"恒信没有物理样机。Ada 发现公司里反复出现'系统上线后一堆问题'。恒信的'原理样机、环境样机、真正的产品'各对应什么？'原型跑通'为什么验证不了部署、运维、成本？"
追问：① 功能需求（合同要能发起、审批、归档）→ 原型；环境适应性需求（月末 500 并发、审计留痕、内网安全合规）→ 试点；可实现性需求（可部署/可运维/可升级/成本可承受）→ 正式投产。恒信大部分"上线翻车"翻的是哪一类？② 为什么"原型跑通"那天这些全都看不出来（部署文档缺失、运维没人接、升级要停机、运维成本是预算两倍）？③ "上线成功"和"产品成功"之间差了什么（上线只验证了功能，部署/运维/成本是可实现性的验证）？

**Q8（判据运用 · 组织资产 · 真悖论收束）**
"老周说：『我们组织经验很丰富，老师傅多，问题都是口口相传的。』小林问：『那为什么下个产品还踩同一个可实现性的坑？』——经验丰富的团队，为什么也会漏掉可实现性需求？"
追问：① 真悖论收束："组织经验丰富（隐性资产确实多）" vs "没有资产可提（没有制度化回路）"——两个都对，靠什么判据分清？② 四步闭环（问题/经验/建议 →转化→ 资产 →复用→ 新产品需求 → 产生新问题 → 回到起点）——关键在"转化"，"转化"指什么（问题被提炼成规范性需求条目，不是照抄）？③ 判断组织自不自觉只看哪一条（有没有制度化回路：问题→分析→转需求条目→入库→新产品复用→复盘更新）？④ 归责：没有资产库的组织捕获不到可实现性需求，是谁的责任（承制方——无资产可提是组织知识管理缺位的必然结果）？

**Q9（判据运用 · 经济可承受性 · 真悖论收束）**
"成本超预算 40%。小林说：『成本是算出来的，设计完再核算。』老周说：『成本是需求，不是结果。』——成本到底是设计出来的，还是需求？"
追问：① 真悖论收束："成本由选型、定工艺、定测试深度决定（设计确实决定成本）" vs "没有成本需求，设计没有依据和目标（需求先于设计）"——两个都对，靠什么判据分清？② 经济可承受性的相关方为什么是市场代表，不是财务、不是客户（基于竞品/替代产品的价格成本研究给出建议）？③ 为什么说控制成本的杠杆全是设计期决策（优先标准外购件/避免定制化外包/自研核心技术模块）——等发现贵了，什么已经冻结（架构和物料清单）？④ 反身：你们设成本需求了吗？谁提的、有没有指标、经没经市场代表确认？没有的话，降本大会是不是每隔一段时间就开一次？

**Q10（落地生根 · 回部门需求完整性体检）**
"结合你们部门现状，用七把尺子（三类全 / 专属验证载体 / 谁在问 / 承制方主导 / 八项三对齐 / 资产机制 / 逆向诊断）给最近一次产品/项目做一次需求完整性体检——给出最该改进的三个事项，每个落到一个动作。"
追问：先做哪把尺子？为什么？两周后回来报告什么？

- **见树见林**：① 概念本身 = Q1；② 概念关系 = Q2。
- **落地生根**：Q10（回部门需求完整性体检，与课后作业"回部门落地"呼应）。
- **真悖论收束六处**（两端皆真、靠判据和解）：
  - Q3 一个特性 vs 两个主人："测试性就是测试性" vs "同一个特性两个主人" → 判据 = 谁在问（客户/环境/承制方）；
  - Q4 样机通过 vs 产品成功："功能原理成立（这一关他过得漂亮）" vs "三类都全（产品才算成功）" → 判据 = 专属验证载体（可实现性只有真正的产品能验证）；
  - Q5 客户说了算 vs 承制方说了算："需求成立以相关方确认为准" vs "内容由承制方主导、全不全问责承制方" → 判据 = 主导-来源-确认三角（内容承制方主导、成立相关方确认）；
  - Q6 执行问题 vs 需求问题："症状在量产（执行层确实难做）" vs "根子在需求起点（当初没写）" → 判据 = 逆向诊断（每个"不方便"对应一条缺失需求）；
  - Q8 经验丰富 vs 没有资产可提："隐性资产确实多" vs "没有制度化回路" → 判据 = 自觉机制（问题→分析→条目→入库→复用→复盘）；
  - Q9 成本是设计出来 vs 成本是需求："选型/工艺/测试深度决定成本" vs "没有成本需求设计没有依据" → 判据 = 成本是需求不是结果（经济可承受性是八项里的总账）。
- **设题九检全过**：①无直觉能秒答（每题翻案）；②追问链齐（机制 / 判据 / 归责 / 反身）；③概念锚点在导读给足；④题面依据全在书内（冰链 M3 量产翻车八条 / 恒信原型-试点-正式产品 / 测试性两主人 / 降本大会 / 组织四步闭环）；⑤靶子皆"从没怀疑"的常识；⑥每题落回判据或动作；⑦全部"信了相反"非知识盲区；⑧八条"不方便"的细节全写进题面（前提自证）；⑨六处升级为真悖论收束。
