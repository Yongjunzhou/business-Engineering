## 第 1 步 · 剖章立骨：核心内容地图

**这一章回答的问题**：什么算"架构决策"？为什么"加一个字段"也可能是架构决策？为什么架构决策不可避免——"我们没做架构决策"为什么是伪选项？怎么判断一个决策的不可逆程度（三层判断框架）？数据所有权为什么几乎最不可逆？高不可逆的决策什么时候做、怎么记录、怎么分级审查？"推迟决策"怎么反而是架构操作？从需求到实现，每一层的架构决策为什么不同？需求有架构吗？

### 核心概念

1. **架构决策**（architecture decision）：你在设计系统时做出的某个选择，这个选择选错了的话，后来要花很大代价才能改对。三标志：影响半径大 / 持续时间长 / 修改成本高。动作链=识别 → 判断 → 做出 → 记录。
2. **不可逆性**（irreversibility）：修改成本高到理性的决策者宁愿忍受现状、也不掏钱去改的程度。经济属性，不是技术属性。三层判断框架：影响半径（结构/时间/组织耦合）→ 信息成本（知识深度/隐含上下文）→ 修改风险（爆炸半径/数据完整性）。

### 对立概念

| 核心概念 | 对立面 | 问什么 |
|---|---|---|
| 架构决策 | 实现决策 | 改不起 vs 改得起；三标志全中 vs 一次提交；划错界线=李工翻车现场 |
| 架构决策 | 架构风格 | 微服务/事件驱动是"套路"（模板）；具体系统选了哪些决策，才是架构决策本身 |
| 架构决策 | "画架构图时的决定" | 评审会上的事 vs 藏在每一个"改个字段"里——没被识别出来的决策依然承担全部代价 |
| 不可逆 | 可逆 | 可逆决策改得起（一次提交、局部影响）；不可逆决策改不起（数据迁移、接口重定、团队重组） |
| 不可逆 | 技术上不能改 | 经济属性 vs 技术属性；能改和值得改是两回事 |
| 显式推迟 | 被动拖延 | 做"现在不做"的决策+记录三问 vs 不做也不记录、等事故来逼 |
| 主动做 | 被动做 | 成本低时主动做 vs 成本高时被事故逼着做——全部的选择空间 |

### 关联概念（近界 · 辨析）

- **架构决策 × 架构（第9章）**：架构=不可还原的决定；架构决策=这些决定怎么被识别、判断、记录、提前投资。第9章回答"什么算架构"，这一章回答"架构怎么被决定"。
- **架构决策 × 需求方案（第5章 / §5.2）**：需求本身没有架构，需求的方案有架构——组织需求的方式本身就是一次架构决策，是设计链上第一个架构决策。
- **决策记录 × ADR（Nygard 2011 / ISO 42010）**：ISO 42010 把架构决策列为架构核心概念；ADR 让"架构决策"从模糊说法变成可记录、可管理、可审查的工程对象。
- **决策记录 × 信息成本（§3.3）**：记录降低的正是未来的信息恢复成本——修改的真正成本 = 重新发现为什么做这个决策的成本 + 实际修改的成本，大多数时候真正贵的是前者。
- **不可逆性标注 × 架构描述 / 老规矩（第9章）**：标注（等级+理由+修改代价）=让"老规矩"落到具体节点时自带警示牌；第9章案例进展④老周把老规矩写下来当 M3 的架构。
- **按级审查 × 三个看门人（第7章）**：按级审查是把关动作在"架构决策"上的具体配置——先分诊，再派尺子；第7章评审/验证/确认是把关的动作。
- **显式推迟 × 期权价值（金融学）**：推迟=保留选择权的价值；信息不够时等一等，比现在瞎猜然后返工便宜得多。
- **提前投资 × 期权价值**：把有限的深度分析资源，集中投到真正不可逆的决策上——不是所有决策都早做。
- **设计链各层 × 需求工程（第4章）/ 设计开发落地（第6章）**：第4章"需求是开发出来的"，第6章"设计落地成一棵树"；本章加注脚——需求不只是被开发出来的，还是被"架构"出来的。
- **两端最高 × V 模型（第7章）**：需求在哪一级被规定、验证就在哪一级证明；架构决策在哪一级做、代价就在哪一级付。
- **数据所有权 × 第9章 M3 铁规矩 / 第6章 数据所有权设定**：M3"温度数据归属追溯域"当众写下；本章给"为什么数据所有权几乎最不可逆"补上完整论证。
- **被动做 × 乐观偏差 / 责任分散 / 反馈滞后 / 隐形决策**：四个非常人性化的原因——不是"他们傻"。
- **架构决策 × 配置管理（第12章）**：投资一旦做出就需要被管理——基线把"已经批准的决定"冻结成参照，版本记录每个决策的演进，变更控制守住基线的门。

### 核心原理

1. **藏在"改个字段"里原理**：架构决策不是某次评审会上"画架构"才发生的；它藏在每一个"改个字段"里——把高不可逆的决策当成低可逆的决策处理，是最危险的一种对待方式。
2. **未识别原理**：没有被识别出来的架构决策，不会得到它应有的审查，却依然承担架构决策的全部代价——"没意识到自己在做决策"才是最危险的。
3. **影响半径原理**：架构决策第一特征=影响半径大——不像改函数内部排序只影响一个点，像地基里的一根桩，动了它，整栋楼的承重都要重新算。
4. **三标志原理**：影响半径大 / 持续时间长 / 修改成本高——两问以上答"是"，就该按架构决策对待；三问全否的，是实现决策。
5. **光谱原理**："架构决策"和"实现决策"之间没有一条自动分界线，分界线靠三标志划——划错了，就是李工的翻车现场。
6. **选择难题原理**：架构决策的难，不在"怎么做出来"，而在"选哪个、为什么选、选了之后要承受什么"——书架分类、厨房布局、订单边界都不是"技术难题"，是"选择难题"。
7. **随手选原理**：随手选=不做决策地做决策，代价迟早来收账。
8. **经济属性原理**：不可逆性不是技术属性，是经济属性——取决于修改它需要多少人、多少时间、冒多大风险，而不是"技术上能不能改"。
9. **能改≠值得改原理**：几乎任何软件决策技术上都能改；"能改"和"值得改"是两回事；不可逆=修改成本高到理性的人选择"算了，将就着用吧"——"能改"变成"没人愿意改"。
10. **复利原理**：普通决策改得起，选错了问题不大；架构决策改不起，选错的那一刻，代价就开始复利了。
11. **不可避免原理**：写第一行代码时，架构决策就已经在发生——数据存在哪个库、功能拆成几个模块、接口怎么定义、状态枚举分几类，一个也跑不掉；不画架构图，不等于没有架构决策。"我们没做架构决策"是一个伪选项——你只是选择在成本低的时候主动做，或成本高的时候被动做。
12. **修改成本曲线原理**：前期的一小时决策，买的是后期的一个月返工；曲线再陡至少还能改，有些决策错过窗口期之后不是贵、是几乎没法改——数据已经迁移完了、对外接口已经发布了、历史合同已经归档了。
13. **被动做四原因原理**：乐观偏差（未来被想象得太便宜）→ 责任分散（没有所有者的决策得不到应有重视）→ 反馈滞后（代价几年后才显现、代价没有主人）→ 隐形决策（散落在"改个字段"里无处显形）。合起来指向：被动做不是没有架构，是"没有显式的架构"。
14. **显式化原理**：让架构决策显式化的第一步，就是认出它——给它一个名字、把它从"顺手改动"里挑出来；三标志的用途不是把每件事都隆重处理，而是先把那些高不可逆的挑出来，不让它们混在低可逆的堆里被随手处理掉。
15. **影响半径三来源原理**：结构耦合（数据归属/公开接口消费者）/ 时间耦合（渐进迁移 vs 一次性同步）/ 组织耦合（一个团队内部 vs 跨团队开会）——技术耦合可以用工具解决，组织耦合只能开会。
16. **信息成本原理**：修改的真正成本 = 重新发现当初为什么做这个决策的成本 + 实际修改的成本；大多数时候真正贵的是前者。两来源：知识深度（重走推演链，重新确认所有下游依赖）/ 隐含上下文（背景信息没记录，只存在于当事人脑子里）。
17. **记录降本原理**：决策记录降低的正是未来的信息恢复成本——李工不是不知道改了会乱，是不知道"当初为什么这么定"，而"不知道为什么要这么定"才是他敢"今天就能上"的原因。
18. **风险两来源原理**：爆炸半径（是否处于业务/数据/安全关键路径的交汇点）+ 数据完整性风险（涉及历史数据迁移的修改自动升级风险等级）。
19. **数据所有权最不可逆原理**：数据所有权/数据模型在三层框架里全都占满——影响半径大（数据被多个系统依赖）、信息成本高（当初为什么这么分域只有少数人知道）、修改风险极高（历史数据迁移，一步错全盘错）——几乎最不可逆。
20. **分诊尺原理**：判断矩阵是一把分诊尺——先粗判一个决策落在哪一档，再决定给它什么待遇；分诊不需要完美，只要能把"高不可逆"从"低可逆"里挑出来，就已经赢了九成。
21. **期权价值原理**：推迟本身就是一种价值——一个决策如果现在信息不够，等到信息充分时再做，比现在瞎猜然后返工要便宜得多；好的架构投资，是把有限的深度分析资源集中投到真正不可逆的决策上。
22. **按不可逆性定节奏原理**：高不可逆→早做、充分分析、多人审查；中不可逆→初步分析、预留调整空间；低不可逆→晚做、快速决定、错了再改（期权价值）——三类决策，三种节奏。
23. **显式推迟原理**：显式推迟=显式地、有意识地、记录在案地"决定现在不做决定"，并回答三个问题：现在为什么不做？等什么信息？什么时候再评估？回答不了这三个问题，才是真拖延；30 秒的预判，能把一个"高不可逆但被当成小变更"的改动拦下来。
24. **决策记录六问原理**：名称 / 背景 / 选项 / 选择 / 影响 / 不可逆性——把一次决策从"当事人脑子里的知识"变成"组织的资产"；记录的价值不在当下，在一年后：换个人接手，看到"不可逆性：中-高"和那句"重排即破坏审计链"，就不会再犯"全局重排"的错。
25. **不可逆性标注原理**：在架构的关键节点上标注不可逆性（等级+理由+修改代价）——标注的价值不在当前设计者，在一年后换了一个人接手：他看到"不可逆性：极高"就知道不要轻易动，看到"理由"就知道动了会波及什么。
26. **审查资源分级原理**：把有限的审查资源，集中在真正不可逆的决策上，而不是均匀撒在所有决策上——给一个低不可逆的决策开三场评审会是浪费，给一个高不可逆的决策走"自查"是灾难。
27. **各层决策不同原理**：每一层面对的需求抽象层次不同、向下传递的对象不同——但每一层的架构决策本质都在回答同一个问题："这部分需求，由谁来承接、以什么形式承接、和其他承接者是什么关系？"只不过每一层的承接者不同。
28. **需求方案有架构原理**：需求本身没有架构——刚收集上来的需求是散乱的、待整理的清单，不需要也不应该有架构；但"需求的方案"（怎么组织成一套可验证、可往下传递的体系）有架构——这个组织工作本身就是一次设计。需求不只是被开发出来的，还是被"架构"出来的。
29. **两端最高中间缓冲原理**：设计链的两端——需求组织（链起点，根歪了整棵树歪）和产品构件（链终点，落地即资产）——不可逆性都极高；中间两层（业务流程/系统功能）的修改成本在"文档层面"，作用是缓冲和吸收不确定性——用"文档的代价"换"代码的代价"。
30. **收束原理（提前投资）**：识别出"后果严重"之后，对信息不足的高风险决策主动推迟、对低风险决策不投入、对高风险决策足额投入——这本身就是最好的架构决策；"在便宜的层做对的决策，贵的层才不用付返工的学费"。

### 本章判据（十把尺子）

1. **三标志判据**：这个决定"影响半径大吗 / 持续时间长吗 / 修改成本高吗"——两问以上答"是"，就该按架构决策对待；三问全否的，是实现决策。
2. **不可避免判据**："我们没做架构决策"是伪选项——架构决策不是做不做的问题，是"成本低时主动做"还是"成本高时被动做"的问题。
3. **经济属性判据**：不可逆 ≠ 技术上不能改；它的含义是修改成本高到理性的人选择忍受。"能改"和"值得改"是两回事。
4. **三层框架判据**：改一个决策，从"影响半径（结构/时间/组织耦合）→ 信息成本（知识深度/隐含上下文）→ 修改风险（爆炸半径/数据完整性）"三个维度评估不可逆性。
5. **数据所有权判据**：数据模型/所有权在三层框架里全占满——影响半径大、信息成本高、修改风险极高。改动它，要按最高不可逆对待。
6. **按级定节奏判据**：高不可逆→早做、充分分析、多人审查；中不可逆→初步分析、预留调整空间；低不可逆→晚做、快速决定、错了再改（期权的价值）。
7. **显式推迟判据**：信息不足的高风险决策，"决定现在不做、记录等什么信息、何时再评估"——是架构操作，不是拖延。
8. **六问记录判据**：名称 / 背景 / 选项 / 选择 / 影响 / 不可逆性——把决策从个人知识变成组织资产，降低未来的信息恢复成本。
9. **审查分级判据**：审查深度按不可逆性分级，把资源集中在真正不可逆的决策上，而不是均匀撒在所有决策上。
10. **两端最高判据**：需求组织（链起点，极高）和产品构件（链终点，极高）承受最高不可逆性；中间层的作用是缓冲和吸收不确定性——在便宜的层解决，别拖到贵的层。

## 第 2 步 · 量学立标：掌握清单

### 概念层（应能定义与辨析）

1. 能定义"架构决策"（选错了要花大代价才能改对的选择）并说出三标志（影响半径大 / 持续时间长 / 修改成本高）。
2. 能定义"不可逆性"（修改成本高到理性的人选择忍受）并说出它是经济属性不是技术属性。
3. 能说出三层判断框架（影响半径 / 信息成本 / 修改风险）及每层的两个来源。
4. 能定义影响半径的三个来源（结构耦合 / 时间耦合 / 组织耦合）。
5. 能定义信息成本的两个来源（知识深度 / 隐含上下文）与修改真正成本公式（重新发现为什么 + 实际修改）。
6. 能定义修改风险的两个来源（爆炸半径 / 数据完整性风险）。
7. 能定义"显式推迟"（做"现在不做"的决策 + 记录"等什么信息、何时再评估"）并辨析被动拖延。
8. 能定义"期权价值"（推迟=保留选择权的价值，信息充分时再做比瞎猜返工便宜）。
9. 能说出决策记录六问（名称 / 背景 / 选项 / 选择 / 影响 / 不可逆性）。
10. 能说出按不可逆性的审查分级（极高/高/中/低各配什么审查深度与参与者）。
11. 能说出设计链各层（需求组织 / 业务流程 / 系统功能 / 产品构件）及各自的承接者与决策问题。
12. 能辨析"需求本身没有架构" vs"需求的方案有架构"。
13. 能辨析 架构决策 × 架构风格（套路 vs 具体系统的实际选择）与 架构决策 × 画架构图（评审会 vs 藏在改字段里）。
14. 能说出被动做的四个原因（乐观偏差 / 责任分散 / 反馈滞后 / 隐形决策）。

### 原理层（应能解释为什么）

1. 能解释为什么"加一个字段"也可能是架构决策（数据模型三标志全中；架构决策藏在每一个"改个字段"里）。
2. 能解释为什么"没被识别的架构决策最危险"（不会得到应有的审查，却依然承担全部代价）。
3. 能解释为什么架构决策是选择难题不是技术难题（书架/厨房/订单服务三例；难在选哪个、为什么选、选了之后承受什么）。
4. 能解释为什么不可逆性是经济属性（取决于人/时间/风险，不是"技术上能不能改"；能改和值得改是两回事）。
5. 能解释为什么"能改"会变成"没人愿意改"（修改代价摆上桌，理性的选择是"算了，将就着用吧"）。
6. 能解释为什么架构决策不可避免（写第一行代码时决策就在发生；不画图≠没有；"不做"只是选择在成本高时被动做）。
7. 能解释修改成本曲线（前期一小时决策买后期一个月返工；错过窗口期之后不是贵、是几乎没法改）。
8. 能解释为什么被动做如此流行（乐观偏差 / 责任分散 / 反馈滞后 / 隐形决策——不是"他们傻"，是四个非常人性化的机制）。
9. 能解释为什么显式化的第一步是"认出它"（三标志的用途=先把高不可逆的挑出来，不让它们混在低可逆的堆里被随手处理掉）。
10. 能解释为什么修改的信息成本常贵于实际修改（知识深度要重走推演链 / 隐含上下文只在当事人脑子里；决策记录降低的正是信息恢复成本）。
11. 能解释为什么数据所有权/数据模型几乎最不可逆（三层框架全占满；历史数据迁移一步错全盘错）。
12. 能解释为什么"推迟"是价值（期权价值——信息不够时等一等比瞎猜返工便宜；好投资=把有限的深度分析资源集中投到真正不可逆的决策上）。
13. 能解释显式推迟与被动拖延的差别（做"现在不做"的决策+记录三问 vs 不做也不记录；回答不了三问才是真拖延）。
14. 能解释为什么决策记录的价值在一年后（当下当事人当然知道；换人接手靠记录不重犯；从个人知识变成组织资产）。
15. 能解释为什么审查资源要分级（低不可逆开三场评审会是浪费、高不可逆走"自查"是灾难；先分诊，再派尺子）。
16. 能解释为什么每一层架构决策不同（抽象层次不同、传递对象不同；本质同一问题=谁承接/什么形式/什么关系，只是承接者不同）。
17. 能解释为什么"需求的方案有架构"（组织零散需求本身就是一次设计；需求分类分错了，后面每一层都在错的框架里打转）。
18. 能解释为什么两端最高、中间缓冲（链起点根歪整树歪 / 链终点落地即资产；中间层用"文档的代价"换"代码的代价"）。
19. 能解释"在便宜的层做对的决策，贵的层才不用付返工的学费"（李工跳过中间所有层，直接在产品构件这个最贵的层面动刀）。

### 判据层（应会用）

1. **三标志判据**：一个改动/选择拿来，先问三标志——影响半径大吗？持续时间长吗？修改成本高吗？两问以上"是"→按架构决策对待（论证 + 评审 + 记录）。
2. **不可避免判据**：当有人说"我们没做架构决策"，反问——你在选"成本低时主动做"还是"成本高时被动做"？伪选项不成立。
3. **经济属性判据**："技术上能改"≠可逆——问修改要多少人、多少时间、冒多大风险；愿意"算了将就"就是不可逆。
4. **三层框架判据**：改这个决策，影响半径（结构/时间/组织耦合）？信息成本（知识深度/隐含上下文）？修改风险（爆炸半径/数据完整性）？各打高/中/低，得出综合判定。
5. **数据所有权判据**：数据模型/所有权改动 → 按最高不可逆对待（完整审查 + 至少一人独立审查 + 决策记录）。
6. **按级定节奏判据**：高不可逆→早做充分分析多人审查；中→预留调整空间；低→晚做快速决定错了再改（期权价值）。
7. **显式推迟判据**：信息不足+高风险 → 显式推迟（现在为什么不做 / 等什么信息 / 何时再评估）；三问答不上才是真拖延。
8. **六问记录判据**：重要决策按六问记下来；不可逆性标注（等级 + 理由 + 修改代价）落到关键节点。
9. **审查分级判据**：审查深度匹配不可逆性——极高完整+多人 / 高完整+独立 / 中语义+同行 / 低快速自检。
10. **两端最高判据**：需求组织/产品构件的决策按最高不可逆对待；中间层决策在便宜的层充分暴露解决。

**空白靶子**：无——十判据全部有题覆盖；网搜 N1~N7 分别并入题卡 Q1 / Q4·Q9 / Q3 / Q9 / Q7 / Q8 / Q2。

## 第 5 步 · 正误有方：纠错策略

### 强化点优先级（一个知识点反制多个误解）

| 优先级 | 强化点 | 反制误解 | 练到何种程度 |
|---|---|---|---|
| ★1 | 三标志 + "藏在改字段里"（识别） | 1/2/3/14/15 + N1/N7 | 脱口而出："架构决策=选错了要花大代价才能改对；三标志=影响半径大/持续时间长/修改成本高，两问以上答'是'就按架构决策对待——'改个字段'也可能是改架构" |
| ★2 | 不可避免（不是做不做是早晚）+ 被动做四原因 | 4/5/16/17 + N2 | "写第一行代码时架构决策就在发生；'我们没做架构决策'是伪选项——你只在成本低时主动做或成本高时被动做之间选；被动做流行=乐观偏差/责任分散/反馈滞后/隐形决策，不是傻是人性的机制" |
| ★3 | 不可逆=经济属性（能改≠值得改） | 6/7 + N3 | "不可逆取决于修改需要多少人多少时间冒多大风险，不是技术上能不能改；'能改'变成'没人愿意改'才叫不可逆" |
| ★4 | 三层判断框架 + 数据所有权最不可逆 | 8/9/18 + N5 | "影响半径（结构/时间/组织耦合）→信息成本（知识深度/隐含上下文）→修改风险（爆炸半径/数据完整性）；数据所有权三层全占满几乎最不可逆" |
| ★5 | 按级定节奏 + 期权价值 + 显式推迟 | 9/10 + N4 | "高不可逆早做充分分析多人审查；低不可逆晚做保留期权价值；显式推迟=做'现在不做'的决策+记录'等什么信息、何时再评估'，回答不了三问才是真拖延" |
| ★6 | 六问记录 + 不可逆性标注 + 审查分级 | 11/12/19 + N6 | "名称/背景/选项/选择/影响/不可逆性——把决策从个人知识变组织资产，价值在一年后；关键节点标注不可逆性（等级+理由+修改代价）；审查深度按不可逆性分级" |
| ★7 | 设计链各层 + 需求方案有架构 + 两端最高 | 13/20 + N7 | "每层决策不同（需求组织/业务流程/系统功能/产品构件），本质都回答谁承接/什么形式/什么关系；需求本身没架构、需求的方案有架构；两端最高中间缓冲——在便宜的层做对的决策，贵的层才不用付返工的学费" |

### 纠错红线十条

1. **先表态后翻案**：先问"改个字段难道不是小事""不做架构决策不就是敏捷吗""技术上能改回去不就是可逆吗""推迟不就是拖延吗"，再翻——不让结论先入。
2. **反转精确不造新误解**：不说"架构决策就是大事、都要隆重处理"（三标志用途恰恰是先把高不可逆的挑出来，别把每件事都当架构决策）；不说"记录越详细越好"（六问一页卡即可，重的是不可逆性标注）；不说"推迟就是好"（显式推迟才是操作，被动拖延仍是问题）。
3. **判据配机制**：每条反转都有"为什么"（藏在改字段里 / 经济属性能改≠值得改 / 被动做四原因是人性的机制 / 信息恢复成本 / 两端最高中间缓冲）和"怎么当场验证"（十把尺子）。
4. **归责到可对照动作**：不归咎"李工/阿凯/老周"，落到"三标志两问以上答'是'吗 / 30 秒预判做了吗 / 六问记了吗 / 不可逆性标了吗 / 审查深度匹配吗 / 这个变更落在哪一层"这类可查动作。
5. **教机制不教断言**：教"为什么改字段可能是架构决策、为什么能改≠值得改、为什么推迟是价值、为什么记录价值在一年后、为什么需求方案有架构"，不教"Ada 说得对"。
6. **先立尺子再翻案**：先给十把尺子（三标志 / 不可避免 / 经济属性 / 三层框架 / 数据所有权 / 按级定节奏 / 显式推迟 / 六问记录 / 审查分级 / 两端最高），再翻案例。
7. **拉开强度层次**：★★★ 常识（改字段是小事 / 没做架构决策 / 能改回去=可逆 / 越早越好 / 推迟=拖延 / 随手选一个 / 数据所有权=接口问题）重点翻，★★ 次之。
8. **每个纠正落到可操作动作**：讨论完给"回去做一件事"（找最近一次改动跑三标志 / 挑一个高不可逆决策写六问 / 在关键节点标不可逆性 / 对照审查分级表查资源匹配）。
9. **单一权威不另立标准**：判据引用书十把尺子 + ISO 42010 / ADR（Nygard），不发明新尺子。
10. **网搜当佐证**：N1~N7 只作"这不是我一个人说的"佐证，药与判据全在书内。

## 第 6 步 · 化尺为用：落地工具

### 作业指南（主产出）：给部门最近一次改动/决策做"架构决策体检"

> 目标：用十把尺子检查一次最近的改动/决策是不是被当成架构决策对待了，产出三件可执行改进。
> 场景：回部门落地。时长：1~2 小时内完成一次体检，两周后复查一至两项。

1. **识别（尺1 · 三标志判据）**：挑一个最近做完/正在做的改动，跑三标志——影响半径大吗（联动改多少东西）？持续时间长吗（多少决定建立在它上）？修改成本高吗（改回来代价多大）？两问以上答"大"→ 它是架构决策。产出：这个改动是架构决策还是实现决策的判定一句话。
2. **查有没有被识别（尺1 + 未识别原理）**：它当初被当成架构决策对待了吗——有论证、有评审、有记录？还是"顺手改动、今天就能上"？产出：识别缺失点。
3. **查被动做信号（尺2 · 不可避免判据）**：有没有"我们没做架构决策"的说法？这个决策是在成本低时主动做的，还是在成本高时被事故逼着做的？产出：主动做/被动做判定。
4. **量不可逆性（尺4 · 三层框架判据）**：影响半径（结构/时间/组织耦合）？信息成本（知识深度/隐含上下文）？修改风险（爆炸半径/数据完整性）？三档各打高/中/低，得出综合判定。产出：综合判定一句话（高/中/低/极高不可逆）。
5. **查数据所有权（尺5 · 数据所有权判据）**：这次改动碰数据模型/所有权了吗？数据归属谁定过、写过吗？产出：数据所有权现状一句话。
6. **查节奏（尺6 · 按级定节奏判据）**：高不可逆的早做了吗？中不可逆的预留调整空间了吗？低不可逆的是不是被过度审查（开了三场评审会）？产出：节奏失配点。
7. **查推迟（尺7 · 显式推迟判据）**：有没有"信息不足+高风险"的决策被硬做了？该显式推迟的，三问（现在为什么不做/等什么信息/何时再评估）记下来了吗？产出：推迟清单。
8. **查记录（尺8 · 六问记录判据）**：重要决策有六问记录吗？关键节点标了不可逆性（等级+理由+修改代价）吗？产出：记录缺口清单。
9. **查审查（尺9 · 审查分级判据）**：审查深度匹配不可逆性吗——极高完整+多人 / 高完整+独立 / 中语义+同行 / 低快速自检？产出：审查失配点。
10. **查层级（尺10 · 两端最高判据）**：这个变更落在哪一层（需求组织/业务流程/系统功能/产品构件）？有没有跳过中间层、直接在产品构件这个最贵的层面动刀？产出：层级判定 + 是否在便宜的层解决。

**卡住怎么判断**：任一尺子打不出勾，就是该尺子说的缺口——不用全打完，找到第一个"否"就能开工。产出三件最该改进事项（每条 = 一个可检查动作）。

### 工作检查单（配套素材）

| 检查项 | 是/否 | 否 → 可讨论发现 |
|---|---|---|
| 最近一次改动跑过三标志（两问以上"大"）？ | □ | 没跑 → 高不可逆的决策混在低可逆的堆里被随手处理 |
| 它被当成架构决策对待了吗（论证+评审+记录）？ | □ | 顺手改动 → 没被识别的决策依然承担全部代价 |
| "我们没做架构决策"这句话出现过吗？ | □ | 出现过 → 伪选项，只是选了成本高时被动做 |
| 不可逆性三层（影响半径/信息成本/风险）都量了吗？ | □ | 只量一层 → 综合判定失真，分诊不准 |
| 数据所有权/数据模型的归属写过、定过吗？ | □ | 没人定 → 它是系统里最不可逆的决策却在裸奔 |
| 高不可逆早做、低不可逆晚做了吗（还是都一刀切）？ | □ | 一刀切早做 → 浪费分析资源；一刀切晚做 → 错过窗口期几乎没法改 |
| 信息不足+高风险的决策，三问记下来显式推迟了吗？ | □ | 硬做或硬拖 → 显式推迟是操作，回答不了三问才是真拖延 |
| 重要决策有六问记录、关键节点标了不可逆性吗？ | □ | 只有口头 → 换人接手重犯"全局重排"的错 |
| 审查深度匹配不可逆性（极高完整+多人/低快速自检）？ | □ | 均匀撒 → 低不可逆开三场评审会是浪费、高不可逆走自查是灾难 |
| 变更落在哪一层判断了吗？在便宜的层解决了吗？ | □ | 直接跳层动刀 → 在产品构件最贵的层面付返工的学费 |

## 第 7 步 · 淬问成题：题卡（10 题 2×5）

### 第一组 · 概念与原理（5 题）

**Q1（见树见林① · 概念本身 · 破题）**
"李工改完合同编号，三个月后连环三爆。会议室里他还不服：'我就是改了个字段。字段嘛，不是想改就改？'Ada 看着他说：'你改的不是一个字段，你改的是这套系统的数据模型。'——什么算'架构决策'？'加一个字段'怎么就成了架构决策？"
追问：① 三标志：影响半径大（联动改多少）？持续时间长（多少决定建立在它上）？修改成本高（改回来代价多大）？编号规则三把尺子全中——尽管李工只敲了几行代码？② 藏得有多深：李工不是"改错了"，他甚至没意识到自己在做一个决策——"没被识别出来的架构决策，不会得到它应有的审查，却依然承担全部代价"，为什么"没意识到"才是最危险的？③ 反身：你们最近一次"改个字段"，跑过三标志吗？它是架构决策还是实现决策，谁判的？

**Q2（见树见林② · 概念关系 · 真悖论收束）**
"请给出 架构决策 / 实现决策 / 架构风格 / 不可逆性 的关系（一句话）。再把'画架构图'放进去——架构决策和'画架构图'是不是一回事？为什么说架构决策不是技术难题，是选择难题？"
追问：① 辨析：架构决策 ≠ 架构风格——微服务/事件驱动是"套路"（模板），具体系统选了哪些决策才是架构决策本身？② 反例：改个变量名（可逆、局部、改得起）——三标志全否，不是架构决策？③ 真悖论收束："架构=架构图/架构风格（我们画了微服务架构图，架构决策做了）" vs "架构=决策（藏在每个'改个字段'里，画图只是决策的落盘）"——两个都像，靠什么判据分清？④ 选择难题：书架怎么分类、厨房怎么布局、订单服务边界——都不是"技术难题"而是"选择难题"，难在"选哪个、为什么选、选了之后要承受什么"，为什么随手选=不做决策地做决策？

**Q3（三标志 · 经济属性 · 真悖论收束）**
"李工说：'编号规则技术上能改回去——数据库能迁移、能重构，没有改不了的。所以它是可逆的。'Ada：'能改，和值得改，是两回事。'——不可逆性到底是技术属性还是经济属性？"
追问：① 经济属性：不可逆取决于修改需要多少人、多少时间、冒多大风险——而不是"技术上能不能改"；几乎任何软件决策技术上都能改？② 能改→没人愿意改：改回去的代价=三个月账重对+历史数据重排+台账重新解析+审计重新自查——当这个代价摆上桌，理性的选择往往是"算了，将就着用吧"——"能改"怎么变成"没人愿意改"，这才叫不可逆？③ 真悖论收束："技术上能改回去=可逆（数据库能迁移、接口能重设计）" vs "不可逆是经济属性（修改成本高到理性的人选择忍受，能改≠值得改）"——两个都对，靠什么判据分清？④ 复利：普通决策改得起选错问题不大；架构决策改不起，选错的那一刻代价开始复利——为什么"改不起"让选错变成了复利？

**Q4（不可避免 · 被动做四原因 · 真悖论收束）**
"老周说：'咱们这次不做架构决策，直接开写，敏捷。'——架构决策真的可以'不做'吗？'
追问：① 不可避免：写第一行代码时架构决策就已在发生——数据存在哪个库、功能拆几个模块、接口怎么定义、状态枚举分几类，一个也跑不掉；不画架构图，不等于没有架构决策？② 伪选项："我们没做架构决策"是伪选项——你只是选择在成本低的时候主动做，或成本高的时候被动做；李工把决策推迟到"三个月后、历史数据都进去了"——用什么价格重新做了一遍决策？③ 真悖论收束："不做架构决策，快速开写（跳过分析、敏捷交付）" vs "架构决策不可避免（写第一行代码时就在发生，被动做=在成本爆炸后做）"——两个都对，靠什么判据分清？④ 被动做为什么流行：乐观偏差（未来被想象得太便宜）/ 责任分散（没有所有者）/ 反馈滞后（代价几年后才显现、代价没有主人）/ 隐形决策（散落在改字段里无处显形）——这四个机制里，你们团队中招过哪一个？

**Q5（三层框架 · 数据所有权 · 真悖论收束）**
"老周说：'不可逆性是能把用的尺子——量影响半径、信息成本、修改风险。'为什么数据所有权/数据模型在这把尺子上几乎最不可逆？'
追问：① 三层框架：影响半径（结构/时间/组织耦合）→ 信息成本（知识深度/隐含上下文）→ 修改风险（爆炸半径/数据完整性）——三层各量什么？② 修改真正成本公式：修改一个决策的真正成本 = 重新发现当初为什么做这个决策的成本 + 实际修改的成本——为什么大多数时候真正贵的是前者？"不知道为什么要这么定"为什么是敢"今天就能上"的原因？③ 数据所有权三层全占满：影响半径大（数据被多个系统依赖）/ 信息成本高（当初为什么这么分域只有少数人知道）/ 修改风险极高（历史数据迁移一步错全盘错）——为什么它几乎最不可逆？④ 真悖论收束："数据所有权改动是接口问题（加个直连接口就完事，需求要满足）" vs "数据所有权是系统里最不可逆的架构决策（三层全占满，动了它历史审计全断）"——两个都对，靠什么判据分清？

### 第二组 · 落地与实践（5 题）

**Q6（识别判据 · 改字段前三问 · 案例进展①）**
"编号爆炸复盘后，李工在笔记本上写下三个问题：改了它要联动改多少东西？它定了之后多少别的决定要建立在它上面？改错了改回来的代价有多大？——他管这叫'改字段前的三问'，'每次问完都会发现，真正值得动手改的字段，比想象中少得多。'——这三问各在量什么？为什么说'问完发现值得改的变少'本身就是在做架构决策？"
追问：① 三问 = 三标志 = 影响半径/持续时间/修改成本——它们怎么把"字段级"和"数据模型级"分开（李工只排查了 12 处代码引用=字段层面，台账/财务/审计=数据模型层面的下游）？② 案例进展①：如果李工改之前先问这三问，那场连环爆炸在哪一问上会被拦下来？③ 反身：挑你们最近一次改动，跑这三问——有几问答"大"？它当时被当架构决策对待了吗？

**Q7（数据所有权 · 案例进展② · 真悖论收束）**
"冰链来了个连锁药店客户，要自己导出原始温度数据接入质管系统。阿凯：'简单，开个直连接口，绕过追溯平台推过去。'老周拦住他：'你这一简单，把第9章我们当众写的'M3 最不可逆的决定'——数据所有权归追溯域——给改了。'——客户需求要满足，数据所有权不能动，两个都对，怎么办？"
追问：① 阿凯的"简单"改的是什么：不是加个接口，是数据所有权归追溯域这条线——追溯平台对这批数据失去控制，三年后追溯出问题谁负责？② 真悖论收束："客户要导出数据，需求必须满足（客户是上帝）" vs "数据所有权是系统里最不可逆的决策，不能悄悄改（追溯平台看不见、管不着、审计对不上）"——两个都对，靠什么判据和解？③ 受控导出：导出还是能导出，但走追溯域的受控通道、每条导出记录留痕——数据所有权这条线谁都没动——为什么说"不可逆的决策不是不能做，是要在看清代价后用对的方式做"？④ 反身：你们有没有"客户一句话，把系统里最不可逆的决定顺手改了"的经历？

**Q8（六问记录 · 案例进展③ · 真悖论收束）**
"编号风波过去一个月，恒信要加'签章方式'字段。李工这次没直接动手，先填了一份六问决策记录：决策名称/背景/选项/选择/影响/不可逆性。评审会上财务老王当场指出'混合模式下归档口径得分开，审计才好查'——补进了'影响'栏。Ada 路过看到：'你现在把改字段当成做决策了。'——六问记录的价值到底在哪？'
追问：① 记录的价值不在当下：当下李工当然知道为什么选 B——它的价值在一年后：换个人接手，看到"不可逆性：中-高"和"重排即破坏审计链"，就不会再犯"全局重排"的错——为什么？② 真悖论收束："写决策记录是浪费时间（当下我知道为什么这么选，文档没人看）" vs "记录把决策从个人知识变成组织资产（换人接手靠记录不重犯，降低信息恢复成本）"——两个都对，靠什么判据分清？③ 六问里哪一问最容易被跳过？"背景"写不出来或"选项"没想过——说明什么（这个决策从没被认真记录过）？④ 反身：你们最近一次重要决策，六问里填得出"背景"和"选项"吗？

**Q9（显式推迟 · 期权价值 · 审查分级 · 真悖论收束）**
"团队收到一个新变更。李工做 30 秒不可逆性预判：低不可逆→快速实施；高不可逆但信息不足→显式推迟：标记'需完整设计推演'，升级到更重的分析路径。老周：'推迟不是拖延，推迟是决策。'——为什么？"
追问：① 显式推迟 vs 被动拖延：显式推迟=做"现在不做"的决策+记录"等什么信息、什么时候再评估"；被动拖延=不做也不记录、等事故来逼——差别在哪？② 期权价值：一个决策如果现在信息不够，推迟本身就是价值——等到信息充分时再做，比现在瞎猜然后返工便宜得多；"提前投资"不是所有决策都早做，而是把有限的深度分析资源集中投到真正不可逆的决策上（服务边界早定/缓存策略晚定/数据所有权必须早定）？③ 真悖论收束："推迟决策就是拖延，是坏事（踢皮球、不做决定）" vs "显式推迟是架构操作（决定现在不做+记录三问，信息不足时等一等比瞎猜返工便宜）"——两个都对，靠什么判据分清？④ 审查分级：审查深度按不可逆性分级——极高完整+多人 / 高完整+独立 / 中语义+同行 / 低快速自检；给低不可逆开三场评审会是浪费、给高不可逆走"自查"是灾难——你们团队在哪一档失配？

**Q10（落地生根 · 回部门"架构决策体检"）**
"结合你们部门现状，用十把尺子（三标志 / 不可避免 / 经济属性 / 三层框架 / 数据所有权 / 按级定节奏 / 显式推迟 / 六问记录 / 审查分级 / 两端最高）给最近一次改动 / 决策做一次'架构决策体检'——给出最该改进的三个事项，每个落到一个动作。"
追问：先做哪把尺子？为什么？两周后回来报告什么？

- **真悖论收束七处**（两端皆真、靠判据和解）：
  - Q2 架构=画图/风格 vs 架构=决策："架构=架构图/架构风格（我们画了微服务架构图，架构决策做了）" vs "架构=决策（藏在每个'改个字段'里）" → 判据 = 三标志（画图只是决策的落盘；架构决策藏在改字段里，选错了要花大代价）；
  - Q3 技术上能改 vs 经济上改不起："技术上能改回去=可逆（数据库能迁移、接口能重设计）" vs "不可逆是经济属性（修改成本高到理性的人选择忍受）" → 判据 = 能改和值得改分开（愿意"算了将就"就是不可逆）；
  - Q4 不做架构决策 vs 不可避免："不做架构决策，快速开写（跳过分析、敏捷交付）" vs "架构决策不可避免（写第一行代码时就在发生）" → 判据 = 不是做不做是早晚（只在成本低主动或成本高被动之间选）；
  - Q5 接口问题 vs 架构问题："数据所有权改动是接口问题（加个直连接口就完事）" vs "数据所有权是系统里最不可逆的架构决策（三层全占满）" → 判据 = 三层框架（影响半径/信息成本/风险，数据所有权全占满按最高不可逆对待）；
  - Q7 客户需求 vs 数据所有权："客户要导出数据，需求必须满足（客户是上帝）" vs "数据所有权不能悄悄改（追溯平台看不见、管不着、审计对不上）" → 判据 = 受控导出（不可逆决策不是不能做，是看清代价后用对的方式做——导出仍可导出，所有权线不动）；
  - Q8 记录浪费时间 vs 组织资产："写决策记录是浪费时间（当下我知道为什么这么选）" vs "记录把决策从个人知识变成组织资产（换人接手靠记录不重犯）" → 判据 = 信息恢复成本（记录的价值在一年后，降低重新发现为什么的成本）；
  - Q9 推迟=拖延 vs 显式推迟=操作："推迟决策就是拖延，是坏事（踢皮球）" vs "显式推迟是架构操作（决定现在不做+记录三问）" → 判据 = 三问（现在为什么不做/等什么信息/何时再评估，回答不了才是真拖延）。
- **设题九检全过**：①无直觉能秒答（每题翻案）；②追问链齐（机制/判据/归责/反身）；③概念锚点在导读给足；④题面依据全在书内（编号三爆/12 处引用/改字段前三问/直连接口受控导出/签章方式六问/30 秒预判/审查分级表）；⑤靶子皆"从没怀疑"的常识；⑥每题落回判据或动作；⑦全部"信了相反"非知识盲区；⑧案例细节全写进题面（三个月连环三爆/十二处引用/2000 台 M3/签章方式字段/财务老王补影响栏——前提自证）；⑨七处升级为真悖论收束。
