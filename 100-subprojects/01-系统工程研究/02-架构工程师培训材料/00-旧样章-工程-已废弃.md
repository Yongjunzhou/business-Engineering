## 1. 单元导读

**主题**：工程是什么，不是什么；工程与科学/手艺/艺术的区别；系统化、系统工程、工程系统。

**本单元要反转的三个直觉**：

1. 「我们用了敏捷、有CI/CD、有测试，所以我们在做软件工程」——**错**。敏捷只是工程四层里「方法论」一层。
2. 「系统化 = 有算法、机械化执行」——**错**。系统化 = 有方法（含判断），不是算法化。
3. 「系统工程 = 造系统的工程 / 技术系统 = 工程系统」——**错**。系统工程是「元工程」（整合、不造部件）；技术系统只是工程系统的内核。

**本轮 5 题的内在逻辑**：Q1 定界（工程 vs 手艺）→ Q2、Q3 推演（工程 ≠ 方法论、系统化 ≠ 机械化）→ Q4 推演（系统工程 vs 软件工程）→ Q5 落地（技术系统 vs 工程系统，给自己的系统做体检）。

**同类分组说明**：产品组和 IT 组拿到**相同的 5 题**，各自用自己的工作语境作答。老师点评时把两边的答案摆在一起——产品组的例子和 IT 组的例子是**同一个概念的两面**，这正是本套概念「领域中立」的证据。

## 2. 题卡（打印分发）

> **答题要求**：组内讨论 25 分钟，把答案写在便签/白板上。每题答案不超过 5 行。每组选派一人上台讲解（4–5 分钟）。允许观点不同，但必须给出理由。

**Q1.** 「工程师」今天几乎谁都可以自称。请用不超过 30 个字说出「工程」区别于「手艺」的本质判据。然后各自举一个身边的例子（产品侧可举产品设计/需求分析，IT 侧可举系统开发/数据建模）。

**Q2.** 有人说：「我们用了敏捷、有 CI/CD、有自动化测试，所以我们在做软件工程。」这句话对在哪、错在哪？

**Q3.** 「系统化」和「机械化/算法化」是一回事吗？为什么「系统化 ≠ 有算法」？请针对「给现有系统加一个新功能」这件事，各写一个「系统化做法」和一个「非系统化（即兴）做法」，并指出两者的关键差别。

**Q4.** 「系统工程」和「软件工程」都带「工程」二字，它们是什么关系？为什么说系统工程是「元工程」？再回答：单个部件都合格，整体一定合格吗？请举一个「涌现属性」的例子。

**Q5.** 「技术系统」和「工程系统」的边界画在哪里？请用你最近上线/部署的一个系统回答两个问题：①按「技术系统」看，它成功了吗？②按「工程系统」看，它成功了吗？如果两个答案不一致，缺的是哪一块（人 / 流程 / 组织 / 数据）？

## 3. 点评要点·讲师版

### Q1　工程 vs 手艺（试金石）

| 各组答案的常见形态 | 讲师判读 |
|---|---|
| 弱：工程=写代码/画图纸/造东西，手艺=手工作坊 | 把「载体」当判据，未触及本质 |
| 中：工程有流程有规范，手艺靠个人经验 | 方向对，但没给**可检验**的判据 |
| 好：工程换了团队也能交付质量相当的结果，手艺不行 | 试金石到位 |

**产品侧 vs IT侧**：产品侧容易答「工程=有方法论的流程」，IT侧容易答「工程=可测试可复现」。两者合起来正是完整判据。

**反转话术**：
> 先都认可，再追问：「一个老法师做了一辈子手工皮具，步骤熟练、经验丰富，他是手艺还是工程？一个团队用敏捷跑得很顺、每次都能交付，这是不是工程？」——把问题逼到「判据到底可不可检验」上。
> 落点：**试金石 = 换个团队、换个人，用同样的需求和约束，能不能交付质量相当的结果。能，是工程；不能，那是手艺。** 哪怕它碰巧也用了代码、图纸或电路。

**参考答案要点**（05 §2、§10）：
- 工程的对立面不是单一一个，而是**三个维度**：认识论上是科学（创造 vs 发现）、方法论上是手艺（可复现 vs 依赖个人）、目标上是艺术（满足需求 vs 自我表达）。
- 判据落在方法论维度：**系统化、可复现**。

### Q2　敏捷 ≠ 软件工程（四层结构）

| 各组答案的常见形态 | 讲师判读 |
|---|---|
| 弱：对，敏捷就是工程化 | 全盘接受——正是本单元靶心 |
| 中：不全对，敏捷只是流程 | 看到了「只是流程」，没说出缺什么 |
| 好：敏捷/CI/CD 只覆盖「方法论」和「工具实践」；工程还有「工程科学」和「价值与伦理」 | 四层结构完整 |

**产品侧 vs IT侧**：产品侧容易答「还缺需求管理、评审这些」，IT侧容易答「还缺架构、测试理论」。两边补的其实都是「工程科学」这一层。

**反转话术**：
> 「假设一个团队：敏捷跑得飞快、CI/CD 全绿、测试全覆盖——然后它上线的产品有安全隐患，因为为了赶进度悄悄牺牲了安全需求。它是工程还是不是？」
> 落点：**工程 = 知识 + 方法论 + 工具实践 + 价值伦理，四层同时在场。** 每次重大工程事故（泰坦尼克号、挑战者号、737 MAX）背后几乎都不是方法论出错，而是价值层失守。

**参考答案要点**（05 §3）：
- 方法 < 方法论 < 工程。方法论是心脏（正是它把工程和手艺区分开），但工程绝不止方法论。
- 四层：工程科学（为什么能行）· 方法论（怎么组织）· 工具与实践（用什么做）· 价值与伦理（为了什么）。

### Q3　系统化 ≠ 机械化（有算法是错的）

| 各组答案的常见形态 | 讲师判读 |
|---|---|
| 弱：是一回事，系统化就是把流程固化成算法 | 正中误区 |
| 中：不完全一样，系统化强调步骤清晰 | 没抓住「判断」这个关键 |
| 好：算法是确定性执行（同输入必同输出、无需判断）；工程方法是有章法但每步留判断空间 | 核心命中 |

**产品侧 vs IT侧**：产品侧通常用「流程/模板」举例，IT侧用「自动化/流水线」举例。可点出：连自动化流水线本身，「要不要自动、阈值设多少」仍是人的判断。

**反转话术**：
> 把区别类比成乐队和机器：**每个乐手按总谱演奏（有结构），但指挥根据现场情况调整节奏（有判断）——这是系统性，不是机械性。** 敏捷高度系统化，但每一步都依赖人的判断，一点谈不上「算法化」。

**参考答案要点**（05 §6、§7）：
- 三词辨析：**systematic**（系统化=做事有章法）、**systemic**（系统性=看问题有全局）、**algorithmic**（算法化=确定性执行）。
- IEEE 六方面里「有算法」是错的，应为「有方法（含判断）」，出处是 ABET 原文 **"applied with judgment"**。

### Q4　系统工程 = 元工程（涌现属性）

| 各组答案的常见形态 | 讲师判读 |
|---|---|
| 弱：系统工程是工程的一种，做更大的系统 | 没抓住「整合」 |
| 中：系统工程管整体，软件工程管软件 | 接近 |
| 好：系统工程不造任何部件，负责把部件整合成整体——接口、集成、系统级验证；软件/硬件工程是它的「部件工程」 | 元工程到位 |

**产品侧 vs IT侧**：产品侧可举「多个部门各做一块业务、拼起来不通」；IT侧可举「微服务每个单独健康、调用链/数据一致性没人管」。

**反转话术**：
> 「每个发动机都正常、每块机翼都达标，飞机未必能飞」——这就是涌现属性。微服务每个单独健康，但调用链、数据一致性、超时熔断没人管，上线必出事——这些「灰色地带」就是系统工程的地盘。**系统工程不造部件，它管的是部件之间的缝。**

**参考答案要点**（05 §4）：
- SE = **元工程**（跨学科整合、接口管理、系统级验证）；SW/HW = 部件工程。
- **涌现属性**：整体行为不是部分行为的简单相加。

### Q5　技术系统 vs 工程系统（给自己的系统做体检）

| 各组答案的常见形态 | 讲师判读 |
|---|---|
| 弱：我的系统两个答案都一样 | 没深挖，讲师追问「人会用吗」 |
| 中：按技术看成功了、按工程看有些问题，但说不清缺什么 | 卡在「说不清」，讲师引导对号入座 |
| 好：按技术系统验收「上线了」，按工程系统看「没人用/流程没改/数据没清洗」 | 经典案例，正是把技术系统误当工程系统验收 |

**产品侧 vs IT侧**：这题对 IT 侧冲击最大（ERP 经典翻车：软件部署好了、服务器跑起来了、模块上线了 =「系统成功」；采购流程没改、财务不会用、数据没清洗 =「系统失败」）。产品侧则容易想到「智能硬件交付后没人持续用」。

**反转话术**：
> **软件系统本身是技术系统（代码、数据、服务器）；「软件 + 用户 + 业务流程 + 运维组织」才是工程系统。** 说「我们构建了一个技术系统」，说的是设备的集合；说「我们构建了一个工程系统」，承诺的是整个社会技术系统能运转起来——技术达标、人会用、流程顺、组织撑得住。你上次交付，承诺的是哪一个？

**参考答案要点**（05 §8、§9）：
- 工程系统四特征：人为设计/改造、有明确目的、与环境交互、遵守约束（INCOSE 2019）。
- 技术系统 = 纯人工技术组件，人只是使用者；工程系统可含人、流程、信息（机场例子）。
- 20 世纪 70-80 年代最贵的教训：**把工程系统当技术系统管**。

## 4. 知识卡片

### 一页图

```
工程 = 科学原理 × 判断创造 ——在约束下—— 用系统方法 → 有用且安全的人造物
                        （ECPD 1941 / ABET 1979 / INCOSE 2019）

工程的三维对立面
  认识论 → 科学（创造 vs 发现）
  方法论 → 手艺（可复现 vs 依赖个人）  ← 试金石：换团队能否同等交付
  目标   → 艺术（满足需求 vs 自我表达）

工程的四层结构（只讲方法论 ≠ 在做工程）
  价值与伦理 ← 重大事故的根源层
  工具与实践
  方法论     ← 敏捷在这里
  工程科学

三词辨析
  systematic 系统化   = 做事有章法（有步骤/检查点/判断）
  systemic   系统性   = 看问题有全局（部分关系/涌现/环境）
  algorithmic 算法化  = 确定性执行（同输入同输出）

系统工程 = 元工程（整合部件，不造部件）→ 涌现属性：部件全对 ≠ 整体对
技术系统 ⊂ 工程系统（人/流程/组织/信息也是工程系统的一部分）
```

### 金句

- **试金石**：换个团队、换个人，用同样的需求文档和约束，能交付质量相当的成果——能，是工程；不能，那是手艺。
- **约束即定义**：连 1941 年最早的工程定义里，同时出现了「运行经济性」和「生命财产安全」。
- **系统化 ≠ 机械化**：系统化是「有章法的判断」，不是「确定性的执行」；工程靠方法，不靠算法。
- **涌现属性**：每个部件都正常，系统未必正常——系统工程存在，就是因为整体不是部分的相加。
- **社会技术系统**：说「构建了一个技术系统」说的是设备的集合；说「构建了一个工程系统」，承诺的是整个社会技术系统能运转起来。
