## 三之一、★ 术语归一的判据：英文原词／本册术语条目，不是中文词形

这是本主题反复用到、也反复踩坑的一条方法论，值得单列：

1. **判据是英文原词，不是中文出现频次。** 中文「安全」既可能是 `safety` 也可能是 `security`，按词形替换必然出错。故写了 `fix_safety_security.py`：回到该条的英文判定。
2. **本册自己的术语条目压过外部惯例。** 15288 的译文里 `safety` 一度有「安全／安全性」、`security` 有「安全／信息安全／信息安全性／安保」四种写法。查其术语条目——**3.40 safety→安全性、3.41 security→安全**——遂按本册定名归一，而不是套用 ISO 9000 的「供方／相关方」或 GB 通行的「security→信息安全」。同一条原则此前已用于 15288 的 **3.9 concept of operations→运行构想 / 3.23 operational concept→运行概念**（两条原本撞名成一个词，且互引方向相反，一并掰正）。
3. **改名的锚点是专名同源。** 15288 里 `供方` 本身站得住（ISO 9000 就用它），但 `Supply process` 已定译「供应过程」，角色叫「供应方」才同源；混用会让读者以为是两个角色。
4. **标准题名不动。** `fix_safety_security.py` 一度把 IEC 61508「功能**安全**」改成「功能安全性」、把 ISO/IEC 15408-3 题名里的「信息安全」改掉——**标准题名由该标准自己的正式中文名管**，故加 `BIB` 规则跳过 `[NN]` 起首的参考文献条目，并**只替换确实偏离的词形、不动裸「安全」**。
5. **位置映射要验次数。** 「兼含 safety 与 security」的并列枚举可按中英出现次序一一对应，但两侧次数不等时须报出人工处置，不能硬配。

## 三之二、装配器的七处加工（源件特性所致，非译者问题）

1. **并回被页/栏切断的句子**：源件由 PDF 抽出，「…governing architecture」＋「viewpoint.」这类续段极多。判据＝上段不以句读收尾（`.:;!?)]}"'…` 之外）且下段以小写字母起头；ISO 正文段落几乎总以标点收尾，故不会误并。中英两侧同并（中文不加空格）。
2. **注／示例／来源转引用块**，标签统一生成（`> **注 3**：…`）。**只在该单元确被判为注／示例／来源时才剥译文自带的标签**——否则会误伤正文里语义完整的句子（如「示例 1 中名为…」）。译员写法不统一，`注 1：`／`注 1 `／`示例 1 `／`[来源：…]` 都要认。
3. **`NOTE N`／`EXAMPLE N` 的编号要并入标签**（`> **NOTE 1** …`／`> **注 1**：…`），否则编号会掉进正文。
4. **源件头部与印刷目录不送译**（前者是本项目自己的中文转换说明，后者由生成目录取代）。
5. **跨批术语归一**（`NORMALIZE` 表）：译员各自成批，同一术语会出现几种写法——本轮统一了 `architecture considerations` 的三种写法为「架构考量因素」。
6. **表格单元格中英同形则不并置两遍**（如 `GERA`、`TOGAF/ADM`）。
7. **一词多义按语境分译并在【对照体例说明】里声明**：`program`＝软件程序→「程序」／与 project 并列的管理单元→「项目群」／企业举措→「计划」。

## 四、★ 已修的两处源件缺陷

### 4.1 42010 英文 MD 漏了 49 个标题（已修）

`5.1`~`8.3`、`A.4.1`~`A.4.6`、`B.2.1`~`B.2.13`、`C.7.1`~`C.7.6`、`F.3.1`~`F.3.5` 全部没被认成标题，落成了粗体段落，**目录里也整段缺失**。

**根因**：标题级别按**字号**判定，而本 PDF 同一层级的字号并不统一——`5.1` 是 **12pt**、`5.2.1` 是 **11pt**、第 3 章术语 `3.1` 也是 11pt。原 `size_level` 只收了 18/16/13，12pt 落空；条款分支又限了 `size ≤ 11.6`，于是 12pt 条款标题掉进了普通段落分支。

**改法**：新增 `clause_level_of(number)`，**按条款号的级数定级**——数字条款 `1`→3、`5.1`→4、`5.2.1`→5；附录首段为字母，比同级数字条款浅一级——`A.1`→3、`A.4.1`→4。字号只作无号标题的兜底。

**结果**：42010 标题 **91 → 141**（2 级 13／3 级 33／4 级 69／5 级 25），覆盖面校验仍 **4281 窗 0 未命中**；42020 同步按号定级重生成，7453 窗 0 未命中；42030 源为 docx 不受影响。

**教训**：标准 PDF 的标题级别不能靠字号推——同一层级在不同章里字号可以不同，条款号才是可靠信号。此条对后续任何标准转换都适用。

### 4.2 软扫术语会造一堆假阳性（已核，未动）

硬扫关键词查「术语漂移」会误报，本轮逐条看上下文后确认以下**都对**，一律未改：`架构框架`（是 UAF「统一架构框架」／NAF「NATO 架构框架」专名，及正文引述 2011 版旧术语）、`架构模型`（RAMI 4.0「参考架构模型」专名及 2011 版旧术语）、`函数`（数学义，按用户既定口径**术语位译「功能」、数学习语不入术语位**）、`相关方`（实为「相关**方**面体」被正则切错）。
