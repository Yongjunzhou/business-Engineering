## 一、★ 三处缺陷（都是「文本层校验查不出、只有真渲染才暴露」的那一类）

### 1.1 MD 的图片链接含空格 → 图根本没被当图（33 幅，8 个文件）

图片路径含空格（`ISO_IEC_IEEE 42010 2023.assets/fig-01.png`），而 MD 写作 `![Figure 1 — …](ISO_IEC_IEEE 42010 2023.assets/fig-01.png)`。**CommonMark 的链接目标不许有未转义空格**，于是 marked／cmark-gfm 都不把它当图片，整行退化成**字面文本**——PDF 里图位处是一行路径字符串，GitHub 上同样不显示。

- 改法：目标补成 `](<路径>)`（CommonMark 的尖括号目标形式）。**判据锚在路径上**：`\]\(((?:[^()<>\n]*\.assets/[^()<>\n]*))\)`。
- **踩过的坑**：第一版正则以 `![alt](target)` 整体形态匹配，alt 里出现转义方括号（`Figure H.1 … 2011\[36\]`）时被 `[^\]]*` 提前截断，42020 的 fig-11／fig-12 两处漏改（改 15 处而非 17 处）——**改完必须数一遍残留**，不能只看"改了 N 处"。
- 波及四份标准的两侧（英文 MD 与对照版），共 8 个文件、33 幅图。

### 1.2 术语条的领域标注被渲染器当标签吞掉（12 处，4 个文件）

`<system> context determining the setting and circumstances…`、`<架构> 用于构造、解释和使用…` 这类**专业领域标注**以 ASCII 尖括号起头。HTML 解析器视作未知标签，**标签本身在 MD 预览与 PDF 里都不显示**。项目已有先例（ISO 9000-2026 对照版同样踩过，44 行标注在 PDF 里全隐形）。

- 改法：写成 HTML 实体 `&lt;system&gt;`、`&lt;架构&gt;`（渲染回 `<system>`、`<架构>`）。顺带把 42020 表格里源件自带的 `<?>` 乱码占位一并转义。
- 只动两类：**行首**的 `<领域>` 标注、表格内的 `<?>`。

### 1.3 `.tools/md2pdf/md2pdf.js` 两处（主项目区，已改）

| 症状 | 根因 | 改法 |
|---|---|---|
| 图不内联，PDF 里图裂 | marked 把带空格的路径**百分号编码**（`src="…%20…"`），工具按编码后的字面路径 `resolve()` 必然落空 | 解析前 `decodeURIComponent(src)`（非法转义则按原样） |
| 图按固有像素摆放：一张 2000px 宽的图＝529mm，A4 内容区只有 174mm → **右侧被裁**，且高度上千 pt、每幅图白吃一整页 | CSS 缺通用图片规则（只有 `.mermaid svg{max-width:100%}`） | 补 `img { max-width: 100%; height: auto; }` |

**旁证：为什么必须目视**。图裂那版（1.3 未修时）42010 排出 **88 页**，修好反成 **156→159 页**；页数自己不会说话，只有把页面渲成 PNG 看，才知道那 88 页是内容被挤坏的结果（曾见表格单元格**一字一行竖排**、正文被大图顶开）。**文本层校验（字符数、链接数）全部通过，却掩着这一页排版的塌陷**——这类缺陷只能用眼睛抓。

## 二、校验口径（`checkpdf.py`＋`covpdf.py`＋`findlost.py`，均在 `.work-mdconv/`）

| 项 | 判据 | 结果 |
|---|---|---|
| 图是否进去 | 每页 `get_image_rects()` 计数 / 与 `.assets/` 文件按像素尺寸逐一配对 | 11/17/0/5 **全中** |
| 图是否被裁 | 图放置宽度是否超出内容区（A4 减 18mm 边距＝542pt） | 溢出 **0** |
| 图位是否残留字面路径 | PDF 文本里搜 `.assets/fig-NN.png` | 泄漏 **0** |
| 正文是否完整 | ① MD 纯文本字数 vs PDF 提取字数之比；② 末页内容与 MD 末行比对 | **100.4%／99.9%／98.7%／100.0%**，末页一致 |
| 内部链接 | `page.get_links()` 计 GOTO/NAMED 注解 | 135／274／142／157 |
| 排版 | 抽页渲 PNG 目视（图页、表页、体例说明页） | 图完整、双语对照体例正确 |

**两个走过弯路的判据，记下来免得再用**：
1. **逐行取前 40 字回查**——对目录行（`[标题](#锚点)`）、域标注、脚注上标、转义括号必然误报。
2. **按段落算 30 字滑窗覆盖率**——对表格行必然误报（MD 行内并置 vs PDF 按单元格抽取，顺序不同），42020 一次报出 120 段"0% 覆盖"，逐条看全是表格行。
3. **拿 PowerShell `git show … > file` 做对照件**——写出的是 **UTF-16** 文件，工具按 utf-8 读即乱码，据此得出的页数结论（49 页）是假的。要对照就用 Python 写 UTF-8/LF。
