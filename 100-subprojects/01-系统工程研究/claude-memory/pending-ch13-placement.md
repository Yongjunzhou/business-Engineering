# 挂账 · 第13章《配置管理》的位置与两处逻辑缺环

**缘起**：用户 2026-10-10 问「**配置管理这一章应该是工程师之前的内容，还是架构师的内容**」→ 追问「**如果不考虑工作量呢，你建议哪个方案，从逻辑视角**」。**结论＝位置不动（甲）＋补两处逻辑缺环。**

## 一、结论：位置保持在第12章之后、第14章之前

**五条理由（逐条带证据）**：

1. **明线刻度这一条最硬**——`00-三条线索.md` §一 第13站刻度＝「**外化形态（个人脑内的图 → 组织共用的图）**」，是一步**社会化**：必须先有"个人那一章"（ch9 工程师）与"要外化的东西"（ch10~12 架构与决定）。前移＝把"组织共用"放到"个人脑内"之前，**梯度倒挂**。
2. **依赖链两头都断不得**——变更控制的难点不在"会做版本控制、会打变更单"，在"**谁有权批准基线、谁裁高不可逆变更**"；故须**前有决定**（ch12 架构决策：不可逆性·准入）、**后有授权**（ch14 治理章首逐字：「**配置管理是治理的一只手**——基线由谁批准、变更由谁裁决、高不可逆的准入权在谁手里，是治理问题；本章给那只手装上头脑」）。前移＝同时断两头。
3. **它不属于"能力清单"那一类**——ch9 的清单是**个人能力项**（可自问／可练／"缺了会怎样"，**封闭六项**）；配置管理是**机制**（冻结·批准·追溯·变更控制），塞进 ch9 段会破坏清单的封闭性，而封闭性正是"六项一项不能少"的承重点。
4. **"发生在工程师手上"≠"属于工程师章"**——版本、变更单、测试记录确是工程师的日常动作（暗线站落在**季昭**：补测试记录"基线"栏），开场也是水恒/季昭/董勋的现场；但本书归位用的是「**决定的锁定与授权**」这条轴，**不是"谁做"这条轴**。
5. **丙（拆分）在逻辑上被明令禁止**——把"版本／基线"放前面、"准入／授权"放后面，等于**同一概念点两处各讲一遍**，正撞手册那扇硬门（"同一概念点不得两处各讲一遍"为人工判读项）。

## 二、缺环一：书里没写"个人可复现意识 → 组织基线"这条递进

ch9 的元项「**可复现意识**」（让判断被接住）是**个人版**；ch13 的「**基线＋变更控制**」是它的**制度化形态**。这一步书里从未说出，读者读到第13章自然要问"这不该在工程师那章吗"。

**补法（两句，不动结构）**：
- **① ch13 章首/骨架**补一句接驳：「这件事工程师天天在做；让它成为制度，是架构与治理的事。」
- **② ch9 收口处**留一句前向指针：「这一项要成为制度，是后面配置管理的事。」

**落点**：① 随 ch13 开工进它**阶段一框架**（该章状态＝待逐章修订）；② ch9 已收口（阶段七已走、提交 `6b06cf0e`），重开要另记一笔——**若用户点头，宜随下一次 ch9 的收尾批次落**。

## 三、缺环二：ch13／ch14 的刻度行口径错位（★与 `00-三条线索.md` 同族）

`00-三条线索.md` §一 那一列的**表头**明写「**四层清点块（原 §1.4.4 刻度行，必留）**」＝应填**能力四级**（①表征／②图式／③心智模型／④解释框架）。**现状**：

| 章 | 现记 | 问题 |
|---|---|---|
| ch7 | 「② 图式（**并落**「外化地图」定位）」 | **对**：级别＋补充定位 |
| **ch13** | 「**外化形态**（个人脑内的图 → 组织共用的图）」 | **补充定位顶掉了级别位** → 深度档位悬空 |
| **ch14** | 「**外化地图**（守的是"谁有权改这张图"）」 | 同上 |
| **ch16** | 「③ 心智模型」＋自挂「★**所列为六项，待校准**」 | 自带一条待校准 |

**后果**：第13章这一段的"深度档位"悬空——这正是"它到底算哪一段"的根源之一（位置之争有一半是刻度口径造成的）。

**补法**：按四层补正 ch13／ch14 的**级别**，把"外化形态／外化地图"降回**补充定位**；**顺带把 ch15~ch18 一并核**（ch16 那行同批处置）。

**落点**：随 `00-三条线索.md` 的维护批次施工（与 [`pending-three-lines-integrity.md`](pending-three-lines-integrity.md) 同批），**不必等 ch13 开工**。
