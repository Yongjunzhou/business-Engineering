# 已出件 ≠ 已入库

**来历**：2026-10-15 用户问「为什么 39 号研究报告没有被推送到远程仓库」→ 查实报告本体**从未 `git add`**（一直以 untracked 状态留在本机工作区），同轮只提交了它的连带件；另一台设备因查不到该件，于 2026-10-14 判定「原件已丢」并给 ch14 做了替代方案。用户令「同意你的建议」→ 补交 **`2c8923f1`** 并双推，警报更正。

## 规则

1. **报告本体与其连带件（取料单／章入口"★ NN 号随章影响"行／记忆索引行）是两件事**，同轮产出时提交信息**必须分别点名**——写「NN 号取料单入库」就只能被读成"取料单入库"。
2. **记忆索引里凡记某号报告"已出件"，必须二选一**：带提交号，或显式标"未提交"。两样都没有＝下一轮会话（或另一台设备）必然误判。
3. **同一轮"已落"的正文改动与报告本体同批提交**，不留成"报告入库了、随章改动还在工作区"（39 号的 ch8 D1／ch9 D2 即如此，与本体的漏检同因）。
4. **判"已丢"之前先分清"没提交"**：另一台设备的**未跟踪工作区不在任何 ref 里**，`git ls-files`／`git log --all`／`git ls-tree` 全零命中**不能证明文件不存在于世界上**。跨设备查件的正确措辞是"**在版本库里零命中**"；要判丢失，须先向人对证"那台机器的工作区是否查过"。
