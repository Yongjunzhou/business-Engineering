# 以读者明白为准（2026-10-14 用户定）

**原话**：「我的建议是，把这个事情说清楚，书的读者能够明白就OK了。」

**背景**：报告 38 号 v1.4/v1.5 把"决策与描述"的三问整理成学理形态（三句可带走的定名、档位声明、使用注、条款索引）；随即议"据此修订教材 ch12／ch13"。用户以此句给出**修订的判据**。

## 四条取法（据此执行）

1. **判据是复述，不是齐备**：一段补写算不算成，看**读者能不能用自己的话说出那件事**（对象是什么／记在哪／结果去哪），不看条款号是否列全、机制是否声明完整。
2. **报告的黑话不进正文**：`④档`／`档位声明`／`可带走的定名`／`使用注`／`本报告定性` 一类元语言，属研究报告体，**教材正文不用**；正文只写"是什么"。
3. **条款号只作括注**：出处放句末括注（如 §5.2.12），**不为迁就出处而加句、不堆条款**；但**落笔前仍回正本核一遍**——那是防错，不是仪式。批内新增引文的探针登记照旧做，属后台动作，不占正文。
4. **验收用冷读**：改完做一次冷读（只给正文、只问"这三件事你能用自己的话说一遍吗"），**替代**加码的程序件；发现读者卡住的地方就改那句话，不加注解。

## 五 章级加重：第17章（2026-10-16 用户令）

**原话**：「**这一章一定要有容易理解的表达**」（开工第17章同轮；本章＝《一路贯通：从需求到上线运行》，全书收束章）。

**为什么单列**：本章要在一章里把十三个概念章合起来讲，最容易滑向"术语串讲＋画面撑场"（旧稿即如此：十一把刀／大象／抽屉／房间／传送带／里程桩／收费站）。故该令在此**高于本章其余取舍**——与"篇幅按章重算、不砍本义"配对：**宁可贴 2.1 万上限，也不把话讲绕**。

**落成五条可查口径**（同时是阶段四写正文与阶段七优化的判据，落 `pending-ch17-revision-35.md` §五）：

1. 每个书名概念（切片／顺次／横切／接缝／缝合／缝合清单）**先用一句人话讲清，再用它**；不许先抛词后解释。
2. **不靠比喻撑论证**——画面不进主线、不作判据，主线句里一个喻体不留。
3. 每站只讲三件具体事（接手什么／交出什么、前后那道缝、账落在哪份产品数据上），用"哪一份文件、谁的名字、哪一天"说话。
4. 句子一口气读完；不写套括号的括注；行话不进正文（框架 §五 第14条）。
5. **验收用冷读**（本件 §四条 4），读者卡住就改那句话、不加注解。

**推广口径**：本条是"以读者明白为准"在一个**收束章、术语密集章**上的加重版；其余各章如遇同类情形（一章内并讲多章概念、或旧稿靠画面立论），**照此五条办，不另立新规**。

## 与既有纪律的关系

- 不取消既有红线与复算（量尺、三条线索、引文回正本核）——它们管"写得对不对、像不像本书"，与本条管的"读者懂不懂"并行。
- 不取消七阶段门禁：**已收口章的连带改动仍走"解冻一改"**，只是不再为该类小改加开程序批次。
