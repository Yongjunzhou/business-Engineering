# feedback-逐件推进不一次成稿

> 触发：2026-11-19 用户令「你可以先给出产品数据的大概思路，再从问题与机会开始，逐一产品数据推进。如果一次全部搞定，恐怕产品数据的细节和前后转换关系的准确性会难以确保」。

## 一、令的内容（照抄）

**先给"产品数据的大概思路"→ 再从**问题与机会**起，**逐一产品数据推进**；**不一次全部搞定**。

## 二、为什么（用户给的理由，也是可查的判据）

一次成稿，**细节的准确性**与**前后转换关系的准确性**都难以确保。落成四条可查的风险：

| 风险 | 现场 |
|---|---|
| **细节变糊** | 栏填不满、来路写不出 |
| **转换断链** | 上游编号到下游对不上 |
| **门形同虚设** | 过没过看不出来 |
| **打回无处可留** | 一次成稿没有"改过"的位置 |

逐件推进正好一件挡住一个风险。

## 三、落法（已落到文档，不是只记在记忆里）

- `90-治理登记/20-47号设计与取料单.md` **§二 2.2 之一 逐环节转换一览**＝"大概思路"的正式载体（十五行，每行四格：**进什么｜怎么转（判据）｜出什么｜过哪道门／停在哪档**）。
- 同件 **§8.5 推进纪律**＝六条：一件一交／每件带转换三句（节首"进什么"、节末"出什么·交给下一件什么"）／件内三遍法（立表头→逐格填→回核转换）／不许边写边改上游（落打回台账）／每件交完给三行体检（栏齐・门过・编号对得上）／进度台账单立。
- `90-治理登记/24-47号正文逐件推进稿.md`＝正文推进处（§〇 进度台账＋§一 件1）。

## 四、延伸适用

凡**大件正文**（多件／多章成一套的产品数据、成书章节整批重写）都按此办：**先出思路表，再逐件推进**。**不许再出现"一次交全篇"的交付**——尤其不许把"设计单过了"当成"正文可以一口气写完"。

## 五、与另外两条已知指示的关系

- **不冲突**：`feedback-八阶段不得跳关` 管"每章按八阶段走"；本条管"一件一交的颗粒度"。两条可同时成立。
- **相邻但不同**：`pending-47号完整范例改造` 管"47 改造成什么"；本条管"47 怎么写出来"。
