# 48 号 v5.0 · 六段重分段（已落）

## 一、来路：两轮问答逼出来的三段结论

1. **第一问**（段③切位要先用段④的视角，③④先后如何）：回正本得三事——① **轴先于切**是切法第零条规则（§7.6 的 R0），§7.5 把"视角与模型种类"列为切位输入的**第一件**；② 42010 §5.2.8 的动词是"标识"、不是"决定"，**视角点名、种类定规矩**（48 号 §6.4 末"标识≠定义"）；③ 真正的时序是"关切→聚类→标种类"（§6.8 四步）先行、"视角规格成册"留后。⇒ **提前的是判断，不是文档。**
2. **第二问**（架构决策 vs 架构评估各是什么、对象、关系）：
   - **架构决策**＝42010 §5.2.12 *a collection of choices*（一组选择，涉 AD 元素／实体要求／环境影响）；**§3 无术语条**，义务只有"记录"（§6.10.1，且只记 *essential*）；它在 §5.2.5 被列为**描述元素**。
   - **架构评估**＝42030 §3.4 *judgment about one or more architectures with respect to the specified evaluation objectives*；有术语条、有过程（42020 §9）、有四件工作产品（§9.5）、有三层（42030 §4.3）；**不含处置**（§3.4 注 1）；**可不依赖描述**（§3.2 注 1）。
   - **关系五条**：不同层；评估为决策供证据（42020 §5.7）；决策需要倒过来定评估判断的形（42020 §9.4 a)）；过程接口双向（42020 表 C.2 决策管理**用**"架构评估建议"／表 C.3 架构过程**用**"架构相关决策·决策准则"）；记录与仓储分两册（决策入 AD、评估入库）。
3. ⇒ 由此得**"决策不是一站、是一条带"**，并据此重分段。

## 二·补、v5.1：六段名由四字改六字（2026-11-18 同日）

**六名（2+2+2，口诀 24 字）**：**讲清现实问题／立住成功判据／认下架构内容／定住读写约定／切成基本角色／交出架构描述**。配方是"**旧名前两字不动、中间各插两字**"，所以旧名一字未丢、迁移成本低。

**段⑤ 议了四稿，记明以免后人重议**：责任 → 角色 → 岗位 → 终裁"**角色**"。
- **否"责任／岗位"的理由**：两者都在回答"**谁**"，而位回答的是"**哪一处**"；"岗位"更属**组织**，撞 §7.6 的 **R4 第三禁**（不按组织部门切）。
- **八类替换测试（判据，可复用）**：责任通一两类／岗位通一类（角色位本身）／**角色八类全通**（功能角色、信息角色、接口角色、结构角色、部署角色、行为角色、角色位、能力角色）。
- **"角色"的广义称名（§1.1，三条界线）**：广义＝"被架构实体身上某一处**名义承担者**"；① **「角色位」连写＝狭类**（八类第 7 类：人／岗位／外部组织），单说"角色"才是广义——**词形即判据**；② **不含相关方**（段①的外部人）；③ **与 42020 §10.4.4 b) 注 1 的 `role` 不同层**（那是可建模元素）。
- **两处连带**（本次最有价值的一处）：§零「读前先认这几样」与 §7.2 的"最小责任块"各补一句——**派活与归责是位的用处（§7.11），不是定义**。用户原话点破：位的主要意义是"**能说清基本概念、属性和管控原则所能识别的系统是什么样子**"，责任/派活是下游价值。

## 二·补二、v5.2：位的"义"与"用"分家（2026-11-18，同一会话第三批）
