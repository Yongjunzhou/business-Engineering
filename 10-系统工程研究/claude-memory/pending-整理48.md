# 十、待裁三件（§七 原三项不变，按实测细化）

**一、整理边界。** 实测后五类的分量变了：A 已无可改，B 的"最大一块"（中英并列）实际只剩标号格式，C、D、E 都是小批量。建议**五类全做**，按 §9.6 四批走；理由是全做合计 2.5~3 日，而"只做 A＋C＋E"省下的 1 日正是 D 的收敛——D 里含**一处必改的编号冲突**（§7.6 与 §7.7 同三条两套号），跳过它，附录 B 的"复核三条"在正文就有两种数法。若只做低风险三项，也建议把 D-2a 一条单独拎出来先改。

**二、是否允许删句。** D 类的改法不是"删"，是**客场换指针**：删掉重复的英文原文，留下条款号与一句结论。按这个改法，"内容不得减少"并不被触动——每条标准引文的**依据位仍在**（条款号＋附录 A 的行），被删的只是同一句原文的第二次排印。建议这样定：**允许删重复引文的原文与同义重述句；不允许删任何"只有这一处才说"的句子**。判据可操作：删后该处仍答得出它自己那一问，且 `check48.py` 全过（裸 § 有户口、表格不错列）。

**三、版本口径。** 建议**整理期不升版本，收口一次升 v3.3**，附录 D 加一节「v3.2 → v3.3（整理轮）」记五类各做了哪些、哪些核过未改（A 类即属此列）。理由：每批升版会让附录 D 记五次中间态，而各批只动体例与归位、不动判据，中间态对外没有引用价值；回溯由 git 提交承担（每批一提交，与 §4 的备份纪律并行）。
