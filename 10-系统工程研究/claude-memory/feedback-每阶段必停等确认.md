# 每个阶段都要停，等用户确认

## 发生了什么（2026-10-23·第10章重排轮）

那一轮我停了三次：**阶段三**（框架）一次、**阶段四＋阶段六**合一次、**阶段七＋阶段八**合一次。用户收工时明确纠正：

> 「**每个阶段都要停，等我确认**」

合并的动机是"这两关之间没有需要人裁的东西"——但那是**我**的判断，不是关口该由谁开的判断。合停把"两关两次确认"压成"两关一次确认"，等于替用户省掉了其中一次的裁决权。

## 规则

1. **八阶段一关一停**：一、目的·目标·主线·内容概要 → 二、原料清单 → 三、框架 → 四、写正文 → 五、概念一致性 → 六、标题名实 → 七、表达（主笔＋两只代理）→ 八、换位通读。**每一关结束＝展示 ＋ 停 ＋ 等确认**，不并关、不预支下一关。
2. **一次确认只放行一关**。用户说"好的"针对的是**刚展示的那一关**；不能据此再走两关。
3. **展示件两处同贴**（手册 §0.7）：对话贴全文 ＋ 写回本章入口 `pending-ch<N>-*.md`；每件末尾固定三行——**关内清单（逐项打勾）＋ 证据块三格 ＋「请确认阶段 N，确认后我出阶段 N+1」**。
4. **确认由用户给，agent 不得自代**（手册 §0.5 纪律 6）：沉默、没反对、"我做完了"都不算确认。
5. **未确认时只做本阶段内的收尾**（复核、自查、记忆写回），**不碰下一阶段的产出**；该停就停，不制造"看起来在推进"的动作。
6. **提交＋双推只在阶段八确认之后**。

## 与「八阶段不得跳关」的分工

那一件管**做没做**（阶段五必走、两只代理必开、换位通读必走）；本件管**停没停**——两件一起才闭环：做了但不展示、展示了但不停，同样视为该关没走完。

## 判据（一句话）

**凡一次展示里出现两个阶段的产出，或"请确认"那一行写的是两个阶段号，即违规。**
