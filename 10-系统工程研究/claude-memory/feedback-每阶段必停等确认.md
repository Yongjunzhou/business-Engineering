# 每个阶段都要停，等用户确认

**规则正文在 [`00-逐章修订手册.md`](../03-架构师是个怎样的物种/00-逐章修订手册.md)**——**§0.5 纪律 6 末段「★ 一关一停，不得并关」**（四条：一次展示＝一关／一次确认只放行一关／并关须单开一段请裁／判据＝"请确认"那行写了两个阶段号即违规）；导语那一句在 **§0.2** 开头；改版留痕在 **§0.4之三 五、2026-10-23 新增条目**。

**用户原话**（2026-10-23，第10章重排轮收工时）：「**每个阶段都要停，等我确认**」。

**起因**：那一轮我停了三次，其中两次是**两关并作一次停**——阶段四（写正文）＋阶段六（标题名实）合一次、阶段七（表达）＋阶段八（换位通读）合一次。动机是"这两关之间没有要人裁的东西"，但**有没有要裁的东西不该由 agent 判**；合停等于替用户省掉了一次裁决权。

**这一件与 [`feedback-八阶段不得跳关`](feedback-八阶段不得跳关.md) 的分工**：那一件管**做没做**（阶段五必走、两只代理必开、换位通读必走），本件管**停没停**——两件一起才闭环。

**本件不放规则细节**：按手册 §0.4之三 的口径，凡"手册自身的事"记在手册那一节，记忆侧只留指向它的指针；要改规则改手册，不要改这里。
