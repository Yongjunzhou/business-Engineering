2026-10-26 拉取远仓（30 个提交）后，`claude-memory/MEMORY.md` 顶部冲突。用户两裁：「**以远仓为准**」「**按最小损失处理**」。

**两类冲突分开判**：

- **同对象的新旧两记**——取远仓那条，删本地过期行。判据：远仓记的是后继状态（本例第4章「进行中、下一台机器 pull 后发『确认阶段四』」vs 远仓「收工、已提交 `0261f1b`」），本地那条的接续指引已失效，留着会误导下次开工。
- **不同对象的并列追加**——两边都留（本例 37／44／45 号那一路）。互不相交的新增条目不是冲突。

**边界**：

- **本地独有的未跟踪产出**（远仓无对应物，如 44／45 号新报告）不在「以远仓为准」射程内，不得随冲突丢弃；纳入跟踪即可，不必删。
- 冲突之外的格式漂移（本例 42 号 03 列带加粗被 `核对-报告用途.py` 报出）按最小改动回正，不顺带改别的。

**Why**：44／45 号是未跟踪文件，删了没有 git 副本可恢复；「以远仓为准」是冲突消解口径，不是清空工作区的授权。

**How to apply**：拉取前 `git stash push -u`（未跟踪件一并带走）；pop 后先分「同对象冲突」与「并列追加」两类再动手；收尾把本地独有产出 `git add` 并提交，做到零丢失。
