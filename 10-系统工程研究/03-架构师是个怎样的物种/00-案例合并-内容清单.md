## 二、两个平台：不变量／配置点／变体凭证

| 项 | 实物平台（M3 产品平台） | 信息平台（冷链运输管理平台） |
|---|---|---|
| **不变量** | ±0.5℃ 最大允许误差；数据不可改·不得反向导入·不开放修正；监测与调控不得联动；测点数据至少每 1 分钟更新；每年至少校准一次；超范围声光报警＋至少 3 名指定人员；独立不间断运行与不间断电源 | 采集与判定算法；数据不可改约束；证据包封包规则；留痕机制（申请—审核—留痕）；出具口径（同一份证据三视图） |
| **配置点** | 容积与箱体层数；续航（72 小时／96 小时）；测点数量与布点方案（在允许范围内）；通讯（4G／北斗／有线）；蓄冷剂配置（按验证确定的条件）；上报协议版本。**温区（-20℃~8℃）与三条告警指标不配** | 流程（审批链与节点）；单据与字段；规则（阈值·升级路径·判定表）；呈现（报表与对外出具视图） |
| **变体凭证** | 一份**验证过的构型**（验证档案按变体登记） | 一份**配置基线**（配置包＋确认记录） |
| **变体定死时点** | 制造前：型号＋选配 → 物料 → 生产 → 该构型重新验证 | 上线时或运营中：客户管理员改一格 → 配置回归与确认 |
| **谁有权动** | 工程变更与生产流程 | 客户配置与运维审批 |
| **变一变要付什么** | 重做温度分布与断电保温验证（周级、成本高、不可回滚） | 配置回归与确认（日级、可回滚） |

**IT 面的硬判据（2026-11-19 用户定）**：**新业务与业务变更不得由代码开发实现，必须由配置实现**——流程、单据与字段、规则、呈现四类改动都在配置项上改，不改代码、不发新版本。判据是每一张变更单都能指出它落在哪个配置点。

**配不出来怎么办（同日用户追定）**：**不回客户改代码，而是回平台补配置功能**——新增配置点或配置能力，补完之后这项业务对所有客户都可配。**只有两步**：第一步 **配置**（既有配置点上改，凭证＝配置基线）→ 第二步 **补配置功能**（平台长出能力，补完对全体客户可配）。**没有第三步**："给单个客户改一版代码"这一步一开，可配置就不成立。

撞平台级不变量（温区、三条告警指标、判定算法、封包规则）的，**不属于可配置性范围**：那不叫"配不出来"，叫"不许配"，走平台变更与决策记录，不拿它当配置的第三步。

## 三、四类要合起来的版本（第21章的「合件」）

| 件 | 由谁定 | 定下来的标志 |
|---|---|---|
| 箱构型（型号＋选配） | 实物平台＋生产 | 构型编码与验证档案对应 |
| 固件版本 | 实物平台 | 烧录记录与批次 |
| 平台基线 | 信息平台 | 平台版本批准、冻结、进基线 |
| 客户配置包（配置基线） | 配置层 | 配置基线批准、与平台基线对应 |

**合件判据**：四样对得齐，才判得出一票货有没有断链；对不齐就判不了——这正是第21章「三块各依各的版本与周期」的升级版。

## 四、三个场面（素材可直接取用）

1. **实物侧的选配**：客户要「96 小时续航＋12 个测点＋北斗双通道」。销售当场答应；工程回来说这个组合没验过——布点在允许范围内，但温度分布没做过。要么排验证（周级），要么改选配。
2. **信息侧的配置**：客户要「审批加一级质量放行＋一张和 ERP 对齐的报表」。配置两天出来，回归跑完上线。
3. **碰不变量的一条**：客户要「断链判定改成 15 分钟」。这一条在平台级不变量里，配不了——要动只能走平台变更，而且改的是所有客户。

> 场面 1 与 2 是「同一副骨架、不同血肉」的新证明：同一条客户要求，一面触发再验证、一面触发配置。

## 五、术语待立户（五条，附录 A 位次待定）

| 词 | 英文 | 说明 |
|---|---|---|
| 产品平台 | product platform | 一组可被配置出多个变体的共享能力与约束 |
| 变体 | variant | 平台配置出的一个具体构成，各自要凭证（验证过的构型／配置基线） |
| 配置点 | configuration point | 平台留出的、允许在变体上取不同值的地方 |
| 配置包 | configuration package | 一个变体的配置集合，随包给出基线 |
| 配置基线 | configuration baseline | 被批准、被冻结、能当参照的那一份配置 |

「**平台级不变量**」若入正文，标**本书立名**。
