# 版本记录（交付包版本台账）

> **用途只有一条：凭版本号找回当时的文件。**
> 版本号是**交付包**的号，不是书内版次——版权页不印版本号，EPUB 元数据也不写版本；包版本只在三处留痕：本台账、提交信息、项目记忆，外加 git 标签一处，便于检出。

## 一、怎么按号找文件

| 想干什么 | 命令／路径 |
|---|---|
| 看本版是哪一次提交 | `git log --grep "文件包 2.0" --oneline` |
| 把那一包的六个文件取到本地 | `git checkout pkg-v2.0 -- 10-系统工程研究/03-架构师是个怎样的物种/成书/` |
| 只导出整包（不动工作树） | `git archive pkg-v2.0 10-系统工程研究/03-架构师是个怎样的物种/成书 | tar -x -C <目标目录>` |
| 只看提交摘要与改动量 | `git show --stat pkg-v2.0` |
| 不用 git 的人 | 查本台账第二节，按"提交号"找提交即可 |

标签命名：`pkg-v<版本号>`（包版本，与书内无关）。

## 三、维护规矩

1. **出一包、记一行**：每次形成交付包（六件齐）就在第二节加一行，并打 `pkg-v<版本号>` 标签指向该提交。
2. **提交信息带包号**：格式 `[AI] 成书（文件包 X.Y）：…`，`git log --grep "文件包 X.Y"` 即可定位。
3. **版本号不自增**：包号由用户给定；未给定就不编。
4. **版权页与元数据不写版本**：两处均不承载包版本，避免"书里一个号、包上一个号"两套号并存。
