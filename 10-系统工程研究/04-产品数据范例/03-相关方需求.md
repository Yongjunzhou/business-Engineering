# 03 · 相关方需求

## 1 概述

上一份《相关方与关切》记录的是相关方与各自的关切。这一份把那些关切写成一条条能判定真假的要求。料从三处来。文档1 给问题与机会编号，文档2 给关切与角色，需求调研记录给原话。一代需求规格另供四个登记值。下游九处要用它的编号。这一版 v0.43，按《相关方需求规范》v0.35 与编制规程 v7.5 复核。它从在役那一版改进出来。整份十张数据表、一百五十条记录，八阶走到第七阶。过没过见同编号件第 1 至 9 条。

## 2 术语

表2-1 的词，定义的正本在《相关方需求规范》第 1 章与第 2 章、规程 5.4。这里只写出读到那一个数据项时按哪种读法用。

**表2-1：术语的读法与用法**

| 专用术语 | 读法与用法 |
|---|---|
| 需求 | 对产品该做什么、该做到什么程度的一句话要求。写齐名称、描述、指标三样才算一条：描述一句可判定真假、不暗示实现，指标三到四个量、至少一个度量型。读到表3-1 一行时，先查看这三样齐不齐，缺一样就不是需求。 |
| 相关方需求 | 相关方就对产品的要求提出的那一条需求，说的是相关方要什么：用的人要它做成什么，买的人要它算得过账，监管要它出得了证据。它不答系统怎么做到，也不等于调研记录里的一句原话；读这一份的每一行都按这个尺度。 |
| 功能性需求 | 对产品动作与行为的要求：要它做成哪些事、在什么时刻做、交出什么结果。客户与使用者问的是做不做得到，故由他们提；指标落在时限、成功率、覆盖情形数这类动作上的量。表3-1 里这一类行的那两栏写出主角色与触发事件。 |
| 通用质量特性需求 | 对产品在使用环境下的程度的要求：不指定做哪个动作，只规定用不用得下、活不活得下去，可用、可靠、易用、安全、时点一致、容量都在内。客户提要求、环境施加条件，两端共担；它与质量特性本身不是一回事，后者是被度对象的一项固有特性。 |
| 易实现性需求 | 对承制方实现产品的要求：实现不只制造，横跨物料采购、制造、测试、交付、部署、运行、运维、退役各段，问的是比现有多容易，即各段上更少专用件与专用工装、更少工时、更少产线改造、更低成本，更多复用既有报告、既有备件与既有工艺窗。承制方自己提，客户与环境不提；指标里至少一项拿既有基线比；与能不能实现不是一回事，后者是门槛。 |
| 承接键 | 认出一个枝梢节点所凭的那一对值，只对非功能行成立。非功能行取用被度对象与质量特性，定文档5 的枝梢节点。功能性行不凭键，凭承接它的那些需求：一条需求只落一条业务，一条业务可收多条。 |
| 端到端业务 | 文档4 那棵树的枝梢节点，起于一份正式的需求或要求，止于该需求被正式确认得到满足。 |
| 质量特性 | 被度对象的一项固有特性，名取用通用特性表里的一名。通用特性表由文档5 立，未立时写〈待回填〉。 |
| 启动要求 | 相关方接到的那一份需求或要求，接到它一条端到端业务才开始。读到表3-4 那一栏时按这个读：它不是相关方需求，后者是相关方对产品提的要求；也不是事件，事件只说那一刻发生了什么。 |
