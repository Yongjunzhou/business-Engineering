# 01 · 问题与机会清单规范

## 1 概述

这份数据是产品开发过程中产品数据清单里的第一份，上游没有别的产品数据。下文写「文档2」「文档3」，都指那份清单里的第几份。它装四张表：把现状记成可查编号的条目（问题、机会），把不能协商的边界登记成约束，把各方想要什么收作参照。料由组织自己的记录汇总而来，不由别的产品数据变来。下游四处按号取：文档2 列相关方与关切，文档3 在需求的「来源」列挂号，文档6 截这里的现状原话作坐标，文档13 取目的陈述作册头「预期目的」。它不写要什么与到什么程度（文档3 管），不写方向句与指标（文档6 管），不写怎么做（方案之属），不管谁关心什么（文档2 管）。

| 近邻件名 | 分界一句 |
|---|---|
| 产品数据本身 | 那份文件装取值，一格一个事实或一个号；本册只写字段名与写法判法，一个真条目、一个真取值都不装 |
| 编制规程 | 规程管工序与通则：七个阶段怎么走、取用与留下的资产、体例与文风、取料与标档；本册管这一份的表与字段、合格判定 |
| 48 号第1卡 | 卡上给转换规则与不成立判定的正本，含输入四件、六步与三条判否；本册写它们落在哪一字段、看哪一格、数什么。卡改了依卡号回查本册，本册写错也依卡号回到卡上 |
| 判例库 | 库中一条一行记已犯过的错法与自查查法；本册只列错法名并挂条号，不展开案例 |
| 同号过程记录件 | 与本体同号的过程与交付记录件装门、留痕与未完项；本体装取值，本册管字段与判定；该件的题名与九节题同按元规范 8.1 核 |
| 24 号 | 逐件推进的登记处，记进度与打回；本册只在打回台账与该件的「门」列登记，不向它取条目 |

依据：读 48 号第1卡（问题空间定义报告）——输入四件、六步、输出一表、三条不成立判定。引两条标准：15288 的 §6.4.1 给这件人工制品的出处，42020 的 §8.4.3 与 §8.5 给现状材料的来源。上游没有产品数据，读的是资产与原料两份，逐处见 4.1。

一条分界：正本里那件人工制品叫问题或机会陈述（problem or opportunity statement），本册这份数据叫问题与机会清单；两处不同名、不同层，改文档名不改正本对陈述的要求。

## 3 表的张数与字段写法

### 3.1 表的张数与级次

形态：四张平面表，没有树，也没有坐标对。四张表并排，不分级次，表与表之间靠号挂靠。

| 表格名称 | 行的含义 |
|---|---|
| 问题表 | 一条问题 |
| 机会表 | 一条机会 |
| 约束登记表 | 一条约束，一个 C 号 |
| 目的参照表 | 一方的一件目的 |

表与记录的对应：一条记录先按第 2 章的判据定它是什么，再落表——过"算不算问题"这条判据的落问题表，写得出抓住它的条件的落机会表。同一批记录可以两张表各出一行，两行不互相替代，也不并成一行；文档1 的 3.1 与 3.2 里各有一行出自同一批记录，即此例。

表间挂靠只有一个方向：问题行与机会行的「走满足的约束」写约束号，指到约束登记表；目的参照表的「挂号的件与号」写问题号或机会号，指到前两张表。约束登记表不回填这条约束管着哪条问题，目的参照表也不列它被几行引用。

号段与唯一性：三个号段各自成序——问题号、机会号、约束号。问题与机会不共用号段，共用即违。目的参照表不编号，一行按「目的的主体」与「目的陈述」两格定位，一方有两件事的分两行写。约束号只作 C 加阿拉伯数字一种写法，与问题号、机会号不同形，转述时不另加前缀。

验收准则与判定结论不是数据表：它记的是判定结论一句，归同号过程记录件第 1 条，不属本册的字段表。

### 3.2 逐表的字段写法

#### 3.2.1 问题表

| 字段名 | 写法 | 不成立 |
|---|---|---|
| 问题编号 | 问题加阿拉伯数字，按条目在取料中出现的次序给 | 改号、跳号、把已删条目的号转给别条 |
| 问题名称 | 名词短语，读到名称即知所指的那件事 | 写成一句话；带方案 |
| 现状描述 | 可观察事实；读数、型号与版本的对照、时点、批次，至少带一样。同一形态的多条记录合成一条，事实一个不缺 | 形容词与判断句；"存在问题"这类空话；把方案或目标写进来 |
| 现状出处 | 组织自己的记录名与部位，读到即知是哪一本、哪一行 | 写研究报告、教材、案例设定；写"相关记录""同上" |
| 直接原因 | 一环：可指认的机制，答得出缺的是哪一环 | 复述现状；写到读数这一层 |
| 直接原因的成因 | 二环：为什么会有这个机制，退到可归责处 | 与直接原因同一句；两环合成一句；这一格空着 |
| 驱动与场景 | 何时、哪个环节、由谁触发，三项齐 | 只写"日常""一直""在途中" |
| 走满足的约束 | 写约束号，指到约束登记表；一行可引一个号，也可引几个。确实一条约束也不管这一行时写「无」 | 自造约束；把约束正文抄进来；有约束却写「无」 |
| 所缺的东西 | 与目标态的差距一句，只写缺的能力或证据 | 把目标或指标写进差距；写谁做、审批、加强管理 |

#### 3.2.2 机会表

| 字段名 | 写法 | 不成立 |
|---|---|---|
| 抓住它的条件 | 已具备的事实：在库、在岗、量已够摊薄。写得出一条才算机会 | 条件写不出仍入表；写成行动项 |
| 所缺的东西 | 要把它做成还缺的那一样，写能力或凭证 | 写成行动项；写成方案 |

其余六个字段与 3.2.1 同写法、同不成立；其中编号与名称随表分名（问题编号与问题名称、机会编号与机会名称），两个号段各自成序。

机会表不设根因两环，直接原因与直接原因的成因两格只存在问题表。卡1 的两条判否因此各压一张表：根因那条压问题表，抓住条件那条压机会表。

跨表共用的字段：现状描述、现状出处、驱动与场景、走满足的约束四个在两表同名同写法；问题编号与机会编号、问题名称与机会名称各按表按同一写法、名随表分。写法只写在 3.2.1，此处不重列。

同名不同义：「所缺的东西」两处不同义。问题表那一格写与目标态的差距，答的是差在哪儿；机会表那一格写要把它做成还缺的那一样，答的是所缺的东西才具备条件。两处都不得写成行动项或方案。

#### 3.2.3 约束登记表

| 字段名 | 写法 | 不成立 |
|---|---|---|
| 约束编号 | C 加阿拉伯数字，一条一数 | 与问题号、机会号共用号段；跳号、重用 |
| 约束原文 | 两型之一。要求型写"须：…；判定＝…"，判定要能照它查一遍：到配置、台账或记录里取值，或按它抽一次样。事实型写"是：…；现象＝…"，现象写在这一格，观测主体写进「来源出处」那一格 | 只写"须"不写判定；只写"是"不写现象；两型混写；把取舍写进事实型 |
| 来源出处 | 法定要求、协议条款、观测记录，到户名与部位。事实型的观测主体也写在这一格，待定的写"待定"加谁定 | 写"行业惯例""普遍做法"；不到部位；观测主体无处落 |
| 不能协商的缘由 | 一句实话。要求型写改一次的代价：全体一起改、要重做验证、不参与加权；事实型写它不是取舍项 | 写"很重要""必须遵守"；复述约束本身 |

#### 3.2.4 目的参照表

| 字段名 | 写法 | 不成立 |
|---|---|---|
| 目的的主体 | 到相关方与岗位，不写人名。一行可列几个岗，列几个就写它们共同的那一件目的；一方有两件事的分两行写 | 写人名；写到"用户"这一层不拆；一行写两件互不相干的事 |
| 目的陈述 | 那个角色对这件事的一句原话式期待 | 提炼成指标或门槛；写成方案 |
| 读法一句 | 固定一句：只作参照，不作判据、不进视图、不作准则。第一行写全，以下各行写「同上」 | 改这一句；整列省掉 |
| 挂号的件与号 | 问题号或机会号，一行可挂一个号，也可挂几个；号在本册查得到 | 挂约束号；挂查不到的号 |

表后两句收束，各一句：综合目的写各行取交集的那一句，无主语；研制方使命写承制方口吻的那一句。目的只此一处：文档6 的「为谁」与文档13 册头的「预期目的」都从这里引用，不另立版本。

编号三件：号按条目在取料中出现的次序编，问题与机会分两个号段，约束单独一个号段，目的参照不编号。号一经冻结即不动——不重排、不跳号、不把已删条目的号转给别条；四张表都要列全，不许占号不占行，能占号不占行的只有相关方与关切那几类（规程 4.5）。下游按号引用：文档2 列相关方与关切、文档3 挂需求的「来源」、文档6 填「坐标」，号一改三处同时断。

## 4 字段的来源与转换

### 4.1 上游提供的字段

链首没有上游文档，读的是资产与原料。

| 上游来料 | 读的处与字段 | 取来的用法 |
|---|---|---|
| 同类本子（资产） | 旧一册的条目号与各格取值 | 借格式与号段，条目按本代原料重写，不沿用旧条目；取不到即按新增走原料并登记缺口 |
| 沉淀清单（资产） | 按场景编的条目行 | 按号引用，不并入本册条目 |

| 平台级不变量与既有系统边界 | 不能改的那几条与边界声明 | 转成要求型约束，判定写进配置的取值唯一 |
| 事故记录与投诉记录 | 事故记录的事项格与处置格；投诉记录的诉求格与争执点格 | 摘出现状与现状出处 |
| 内审项与交付台账 | 内审项的发现格；交付台账的客户格、版本格、周期格 | 内审项并入现状；台账三格并成一条重复比例 |
| 物料清单与装配图 | 同一物料的型号格与版本格 | 对照两处是不是同一处权威 |
| 法规正本与协议条款 | 条文里的义务句与判定口径 | 转成要求型约束，并写出判定 |
| 观察记录（线路、现场、装机台账） | 现象格与观测主体格 | 转成事实型约束，观测主体落来源那一格 |
| 各岗访谈记录 | 各岗原话 | 摘成目的陈述，不提炼指标 |

### 4.3 不转换的字段

六个出现处不从上游变来：编号三处（问题号、机会号、约束号）各按条目在取料中出现的次序编、各占一个号段；名称两处由同一行的现状提炼，不经某份输入；目的参照表的「读法一句」一处固定一句，各行同一句。

## 5 验收准则与判定结论

### 5.1 准则的正反两面

| 不合格条件 | 合格条件 | 处置 |
|---|---|---|
| 四张表的表头与本册 3.2 的字段名不是逐字相同；或四类指向别处的一格——问题与机会的「现状出处」、约束的「来源出处」、目的行的「挂号的件与号」——记录名、户名或部位有一处是空的 | 表头与 3.2 逐字相同、不多不少；四类指向格各到户名与部位：问题与机会到组织自己的记录名与部位，约束到户名与条（事实型的观测主体也写在这一格），目的行挂的号在本册查得到 | 表头不一样：退回改齐，确要改字段由元流水线开发者裁定后同批改本册与数据。指向格空着：退回补；补不出的写「未取到」或「待定」加谁定，解锁人与时机落 00 号打回台账，解锁前下游不得引用 |
| 一条问题的直接原因只是症状，或与成因并成一句，或那一格空着 | 直接原因与直接原因的成因分两格，环环有证据 | 退回重写两环；只写症状的按没找根因算 |
| 一条机会写不出抓住它的条件却仍入表 | 每条机会写得出一条已具备的条件 | 退回；条件写不出的改作愿景，不入表 |
| 一条约束要求型无判定、事实型无现象，或两型混写 | 每条约束落在两型之一；要求型写得出判定，事实型写出现象并把观测主体落在来源出处那一格 | 退回补；观测主体待定的写「待定」加谁定 |
| 目的参照表的一行改动了读法一句那一格，或挂的号在本册查不到，或一行写两件互不相干的事 | 各行读法同一句，挂的号都在本册，一行一件事 | 退回改；写两件的拆成两行 |

第一条册级通用，判的是表头与四类指向格，四张表都落；其余四条按表判，四张表各有自己那一条。

### 5.2 判定结论与不过的处置

按 5.1 五条逐条判到每条记录；判过就是过，交付件不记成立、缺口待补、违例这类状态，也不给计数。第一条判表头与四类指向格：表头不合的，该表全部记录判不过，改齐后重判。逐条的判断依据留在工作件的评审记录里，数据不摆。00 号进度台账该文档那一行的「门」列只记一句「按本册 5.1 逐条判过」与读数几处；那一列是台账的列名，取规程的件名，数据里对应的节题作验收准则与判定结论，两处不是两套判据。这一段落在同号过程记录件第 1 条。

### 5.3 判不过的两条路

只剩两条路。一条改到过：本份执笔当场改，改完由评审复核；判该条不适用而改作不入表的也归这条，由评审提、元流水线开发者定，改动落 00 号打回台账。另一条挂进未完项：只收当场改不动的四类——须实测才得的量、须上游答复的条款号或部位、须立册才有的户名与号、须另开一只代理的复核；写谁办、几时办、落 00 号哪一行，交稿前在同号过程记录件的未完项一节逐行写清。事实型观测主体缺的那一位，按 3.2.3 写在来源那一格。不留第三种状态：判不过又不在这两条里，就是漏改。

本册不设题面与表达专节：所管数据的题面与表达按《产品数据规范编制规范》8.1 的三问与 8.2 的七条自核。
