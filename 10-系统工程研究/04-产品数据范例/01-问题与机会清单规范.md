# 01 · 问题与机会清单规范

## 1 概述

本规范规定如何编制合规的《问题与机会清单》：它装哪几张数据表、每张数据表有哪些字段、每个字段从哪里来、什么算合格。它是产品数据清单里的第一份，排在它前面没有别的产品数据。下文写到「文档2」「文档3」，说的都是那份清单里的第几份。

它装四张数据表。问题和机会各占一张，记录的是现状，每条都给一个编号，以后查得到。约束占一张，记录的是不能协商的边界。目的占一张，收的是各方想要什么。料从组织自己的记录里汇总，不是从别的产品数据变来的。

下游靠问题编号与机会编号认它。文档2 列出相关方与关切时，把问题编号或机会编号写进那一行；文档3 每条需求的来源栏里，写出的是这两个编号。编号一改，这两处跟着断，所以编号定了不动。

文档6 和文档13 不按编号取。文档6 摘这里的现状原话当坐标，文档13 把目的陈述抄进册头。要什么、到什么程度，本规范不写，那是文档3 的事；方向句与指标留给文档6；怎么做属于方案，谁关心什么属于文档2。

**表1-1：本规范与相邻文档的分工**

| 相邻的文档 | 分工的界线 |
|---|---|
| 产品数据本身 | 那份文件里装的是取值，一个数据项放一个事实、或者一个编号。本规范只写出字段名、写法和判法，一个真条目、一个真取值都不装。 |
| 编制规程 | 规程管两头。一头是工序，八个阶段怎么走；一头是通则八条：形态、结构、资产、条目、排表、文风、取用原料、留痕。本规范管这一份的数据表跟字段，还有合格不合格怎么判。 |
| 48 号第1卡 | 转换规则跟不成立判定，正本在卡上：卡上给四件输入、六步、三条判否。本规范只写出它们落到哪个字段、查看哪一个数据项、数什么。卡改了，依卡编号回查本规范；本规范写错，也依卡编号回到卡上。 |
| 判例库 | 库里一条一行，记录的是已经犯过的错法，和自己怎么查。本规范只列出错法名、挂上条编号，不展开案例。 |
| 同编号过程记录文档 | 与本体同编号的那件过程与交付记录文档，装的是验收判定、留痕、未完项。本体装取值，本规范管字段跟判定。那份文档的题名和九节题，也照元规范 6.3 核对。 |
| 24 号 | 那是逐件推进的登记处，记录进度、记录打回。本规范只在打回台账和那份记录的「验收判定」字段上登记，不从它那儿取用条目。 |

它的依据有三份。一是 48 号第1卡，问题空间定义报告那一张。卡上给的输入、六步做法、一张输出表，还有三条判不成立的口子。二是两条标准：15288 的 §6.4.1 说这件人工制品从哪来，42020 的 §8.4.3 与 §8.5 说现状材料从哪来。三是组织自己的资产与原料两份，每一处怎么读见 4.1。

有一处名字要分清。标准正本里那件人工制品叫问题或机会陈述（problem or opportunity statement），本规范这份数据叫问题与机会清单。两个名字不同，层次也不同；改动文档名，改动不掉正本对陈述的要求。

## 2 术语

通用词照《产品数据规范编制规范》第 3 章表3-1 那一套读，二十一条分三组，本规范用到哪几条就在那一处读，不在这里重列。数据表与同号过程记录里的名照它抄，不换字。读者在第 5 章看到的那一节，题作验收准则与判定结论，与数据同号件第 1 条的节题同名。

本册用到的特有词共七条，定义、出处与读法都写在《01-问题与机会清单》第 2 章那一张表上。这里只指过来，不重列，也不另写一套；两处都写，改一处漏一处。

## 3 数据表的张数与字段写法

### 3.1 数据表的张数与级次

四张数据表都是平面表，没有树，也没有坐标对。它们不分级次，也不互相嵌套，只靠编号连起来。

**表3-1：数据表各装一条记录**

| 表格名称 | 行的含义 |
|---|---|
| 问题表 | 一条问题 |
| 机会表 | 一条机会 |
| 约束登记表 | 一条约束，占一个 C 编号。 |
| 目的参照表 | 一方的一件目的 |

一条记录该进哪张数据表，先按第 2 章的判据定它是什么，再记进去。过得了「算不算问题」这条判据的，记进问题表。写得出既有条件的，记进机会表。同一批记录可以两张数据表各出一行，两行不互相顶替，也不并成一行。文档1 的 3.1 与 3.2 里各有一行，就出自同一批记录。

数据表与数据表之间的挂靠只有一个方向。问题行和机会行的「须满足的约束」写出约束编号，指到表3-4。目的参照表的「挂编号的件与编号」写出问题编号或机会编号，指到表3-2 与表3-3。反过来不填：约束登记表不写出这条约束管着哪条问题，目的参照表也不列出自己被几行引用。

三个号段分开用，问题、机会、约束各占一个。谁也不用谁的编号，混用就是错。目的参照表不编号，一行按「目的的主体」和「目的陈述」两数据项认。一个主体有两件事，就写出两行。约束编号写成 C 加数字，只这一种写法，跟问题编号、机会编号都不同形；别人转述时不用再加前缀。

验收准则与判定结论不是一张数据表。它记录的是判定结论那一句。这一句归到同编号过程记录文档的第 1 条，不算本规范的字段表。

### 3.2 逐表的字段写法

本节的字段表比 48 号卡1 的最小形多。卡1 的输出是一张数据表七列：编号、类型、现状含出处、根因链、驱动与场景、须满足的约束、与目标态的差距。本规范按记录类别分成四张，另立目的参照表一张。卡上最小形之外的字段，依元规范 4.4，由本规范看着数据实际长成什么样来定。判法缺了才回卡上补。这件事备过案，记在打回台账第 121 行。

#### 3.2.1 问题表

**表3-2：问题表的字段与写法**

| 字段名 | 写法 | 不成立 |
|---|---|---|
| 问题编号 | 写出「问题」两个字加阿拉伯数字，按条目在取用原料里出现的先后给。 | 改动编号；跳编号；把删掉条目的编号转给别条。 |
| 问题名称 | 写出名词短语，读到名称就知道说的是哪件事。 | 写成了一句话；名字里带方案。 |
| 现状描述 | 写出看得见的事实。读数、型号与版本的对照、时点、批次，至少带上一样。同一形态的好几条记录，合成一条写，事实一件不缺。 | 只写出形容词、只下判断句；写出「存在问题」这种空话；把方案或目标也写进来。 |
| 现状出处 | 写出组织自己的记录名和部位，读到就知道是哪一本、哪一行。 | 写成研究报告、教材、案例设定；写出「相关记录」「同上」。 |
| 直接原因 | 写出第一环，要能指认的机制，答得出缺的是哪一环。 | 把现状复述一遍；写到读数这一层就算过头。 |
| 直接原因的成因 | 写出第二环，答为什么会有这个机制。要退到能归责的地方，点得出一个角色、一处规则或者制度名，还得跟上一环对得上。 | 跟直接原因写成同一句；两环合成一句；这一个数据项空着；退不到角色或规则名。 |
| 驱动与场景 | 写出什么时候、哪个环节、由谁触发，三项都要有。 | 只写「日常」「一直」「在途中」。 |
| 须满足的约束 | 写出约束编号，指到约束登记表。一行引一个编号行，引几个也行。真的一条约束都管不着这一行，就写「无」。 | 自己造一条约束；把约束正文抄进来；明明有约束，却写「无」。 |
| 与目标态的差距 | 用一句写清差在哪儿，只写出缺的能力或者证据。 | 把目标或指标写进差距；写出谁来做、写出审批、写出加强管理。 |

#### 3.2.2 机会表

**表3-3：机会表的字段与写法**

| 字段名 | 写法 | 不成立 |
|---|---|---|
| 机会编号 | 照表3-2 里问题编号的写法写，号段单独另起 | 跟表3-2 同名字段犯一样的错；再就是跟问题编号共用号段 |
| 机会名称 | 照表3-2 里问题名称的写法写 | 跟表3-2 同名字段犯一样的错 |
| 现状描述 | 照表3-2 里现状描述的写法写 | 跟表3-2 同名字段犯一样的错 |
| 现状出处 | 照表3-2 里现状出处的写法写 | 跟表3-2 同名字段犯一样的错 |
| 驱动与场景 | 照表3-2 里驱动与场景的写法写 | 跟表3-2 同名字段犯一样的错 |
| 须满足的约束 | 照表3-2 里须满足的约束的写法写 | 跟表3-2 同名字段犯一样的错 |
| 既有条件 | 指一样已经具备的东西：在库的本子、在岗的角色、已经取到的读数。它是手上已经有的，不是打算去做的事。一句话，既有条件是抓这个机会时已经握在手里的那一样。 | 卡1 步骤⑤；本规范 3.2.2 |
| 与目标态的差距 | 写出要把它做成、还缺的那一样，写出能力或者凭证。 | 写成了行动项；写成了方案。 |

两个号段都照取用原料的先后编。问题编号按它在表3-2 里出现的先后，机会编号按它在表3-3 里出现的先后。问题与机会的编号、名称跟着各自的数据表走，写法是同一套，只写在表3-2 那一处。

机会表没有直接原因与直接原因的成因这两数据项，只存在问题表里。卡1 那两条判不成立的口子，因此一条落在问题表上、一条落在机会表上。根因那条管问题表，既有条件那条管机会表。

有四个字段两张数据表共用，名字和写法都一样：现状描述、现状出处、驱动与场景、须满足的约束。只有一个名字同叫不同义，是「与目标态的差距」。问题表那一个数据项写出差在哪儿，答的是缺哪一样能力或证据。机会表那一个数据项写出要把它做成还缺的那一样，答的是缺哪一样才具备条件。两处都不许写成行动项或方案。

#### 3.2.3 约束登记表

**表3-4：约束登记表的字段与写法**

| 字段名 | 写法 | 不成立 |
|---|---|---|
| 约束编号 | 写出 C 加阿拉伯数字，一条一个数。 | 跟问题编号、机会编号共用号段；跳编号；重用。 |
| 约束原文 | 两种里挑一种。要求型写「须：…；判定＝…」，判定要能照它查看一遍：到配置、台账或者记录里取值，或者按它抽一次样。事实型写「是：…；现象＝…」，现象写在这一个数据项，观测主体写进「来源出处」那一个数据项。 | 只写出「须」不写出判定；只写出「是」不写出现象；两种混着写；把取舍写进事实型。 |
| 来源出处 | 法定要求、协议条款、观测记录，三类来源都要到户名和部位。事实型的观测主体也写在这一个数据项；待定的，写出「待定」再加谁定。 | 写出「行业惯例」「普遍做法」；不到部位；观测主体缺着，也没标待定。 |
| 不能协商的缘由 | 写出一句实话。要求型写出改动一次的代价：全体一起改、要重做验证、不参与加权；事实型写出它不是取舍项。 | 写出「很重要」「必须遵守」；把约束本身复述一遍。 |

#### 3.2.4 目的参照表

**表3-5：目的参照表的字段与写法**

| 字段名 | 写法 | 不成立 |
|---|---|---|
| 目的的主体 | 写到相关方和角色，不写出人名。一行可以列出几个角色，列出几个，就写出它们共同的那一件目的。一方有两件事，分两行写。 | 写出人名；写到「用户」这一层就不拆了；一行写出两件互不相干的事。 |
| 目的陈述 | 写出那个角色对这件事的期待，照原话的样子写出一句。 | 提炼成了指标或者门槛；写成了方案。 |
| 读法一句 | 这是固定的一句：只作参照，不作判据、不进视图、不作准则。每一行都要写全这一句。 | 把这一句改了；写出「同上」，或者写出别的字。 |
| 挂上的编号 | 写出问题编号或者机会编号。一行挂上一个编号行，挂上几个也行；编号在本规范里查得到。 | 挂了约束编号；挂了查不到的编号。 |

目的参照表后面还跟两句。一句是综合目的，把各行目的放在一起看的那一个结果，不带主语，不设指标，也不设通过线。一句是使命，用研制方的口吻，写它为什么做这门生意、要做到什么份上。目的只有这一处：文档6 的「为谁」和文档13 册头的「预期目的」都从这里引，不另立版本。

编号怎么办，见 3.1。这里只补一条：目的参照表不编号。编号一旦定了就不动，不重排、不跳编号，也不把删掉条目的编号转给别条。

四张数据表都得把行列全，不许先占一个编号、行空着。规程 5.2 说可以先占编号、行空着的有五类：相关方、关切、目的、位、叶。本规范四张数据表里只有目的参照能这么办。问题、机会、约束这三张，占了编号就得把那一行写出来。下游有三处按编号引：文档2 列出相关方与关切，文档3 挂上需求的「来源」，文档6 填进「坐标」。编号一改，三处同时断。

### 4.1 上游提供的字段

### 4.2 转换表与字段覆盖

表里一行是一条规则，六件事都要说清：规则编号、输入的处与部分、落到数据表与字段、怎样判定它做对了、做成什么样算错、卡上哪一步是它的正本。

**表4-2：转换规则的输入与落点**

| 规则编号 | 输入的处与部分 | 落到数据表与字段 | 判法 | 反例 | 出处 |
|---|---|---|---|---|---|
| R1 | 事故、投诉、内审项、交付台账、物料清单与图纸里的一次记录，或一处文件对照 | 问题表・现状描述；机会表・现状描述 | 数据项里的每个数都要指得回那一处。拿一条参照对一对，判得出是符合还是不符合。取不到的值，按规程 5.7 造出来，标上（示例值），再指回它是怎么造出来的。 | 运输途中温度多次超标（暂无判例） | 卡1 步骤① |
| R2 | 同一记录的名和部位，是哪一本、哪一行。 | 问题表・现状出处；机会表・现状出处 | 读到这一个数据项即知是哪一本、哪一行 | 写出「书侧治理一章」「相关记录」，查起来无从下手（判例库第 1 条、第 7 条）。 | 元规范 4.4 三型来源；卡1 步骤① 只到「写出处」 |
| R3 | 同一形态的好几条记录。 | 问题表・现状描述，合成一条 | 合成一句以后，事实一件不缺；合并前后各几条，数得出来。 | 把「箱内温度超过上限」和「内审又发现记录不全」挤进一句（暂无判例）。 | 本规范；卡1 未列出合并一条 |
| R4 | 一条现状，或者一条记录连着的好几行。 | 问题表・直接原因 | 往下退一层，退到「哪一环缺了」。删掉这一个数据项，现状照样成立，「为什么」却答不出来，就对了。 | 直接原因写成「箱内温度超过了上限」，等于把现状复述一遍（暂无判例）。 | 卡1 步骤② |

### 4.3 不转换的字段

六个出现处不从上游变来。六个里有三个是编号：问题编号、机会编号、约束编号。三个都按条目在取用原料里出现的先后编，各占一个号段。另外两个是名称，从本行的现状里提炼，不经哪一份输入。目的参照表的「读法一句」一处固定一句，各行同一句。

## 5 验收准则与判定结论

### 5.1 准则的正反两面

**表5-1：准则、不合格条件与处置**

| 不合格条件 | 合格条件 | 处置 |
|---|---|---|
| 四张数据表的表头与本规范 3.2 的字段名不是逐字相同；或四类指向别处的一个数据项——问题与机会的「现状出处」、约束的「来源出处」、目的行的「挂上的编号」——记录名、户名或部位有一处是空的 | 表头跟 3.2 逐字相同，不多不少。四类指向数据项都要到户名和部位：问题与机会到组织自己的记录名与部位；约束到户名和条，事实型的观测主体也写在这一个数据项；目的行挂上的编号，在本规范里查得到。 | 表头不一样的，退回改动齐；确实要改动字段，由元流水线开发者裁定，再同批改本规范和数据。指向数据项空着的，退回补；补不出来的写「未取到」或者「待定」加谁定，解锁的人和时间记进 00 编号打回台账。没解锁之前，下游不得引用。 |
| 一条问题的直接原因只是症状，或与成因并成一句，或那一个数据项空着；或无证据而不标〈待核〉 | 直接原因和直接原因的成因，分两数据项写。只写出有证据的那一环；没证据，标注〈待核〉，再进未完项。 | 退回重写两环。只写出症状的，按没找根因算；该标注〈待核〉没标注的，退回补标。 |
| 一条机会写不出既有条件却仍入数据表，或只点得出趋势与愿望 | 每条机会都要点得出一条已经具备的东西，还得指得回本规范的一处：一条已经入册的登记、一个在岗的角色、一笔已经取到的读数和它的出处。 | 退回。条件点不出的，改作愿望，不入数据表。 |
| 一条约束要求型无判定、事实型无现象，或两型混写 | 每条约束落在两种里的一种。要求型写得出判定；事实型写得出象，观测主体落在来源出处那一个数据项。 | 退回补。观测主体待定的，写出「待定」再加谁定。 |
| 目的参照表的一行改动了读法一句那一个数据项，或挂的编号在本规范查不到，或一行写出两件事 | 各行读法用的是同一句。挂上的编号都在本规范。一行一件事；一行里出现两件各有主体的目的，就算两件。 | 退回改。写成两件的，拆成两行。 |

第一条册级通用，判定的是表头与四类指向数据项，四张数据表都落。其余四条按数据表判，四张数据表各有自己那一条。表5-1 那五条，与表3-2 至表3-5 的第三列，是一套判据。某一个数据项第三列判不过、而表5-1 没单独列出它的，同样算不合格：五条不是全部。

### 5.2 判定结论与不过的处置

判定的时候一条一条来：5.1 那五条，每条都要过到每条记录。判过就是过，交付件不记录成立、缺口待补、违例这类状态，也不给计数。第一条判定表头与四类指向数据项。表头不合的，该数据表全部记录判不过，改动齐后重判定。逐条的判断依据留在工作件的评审记录里，数据不摆。

00 编号进度台账上，这份文档那一行的「验收判定」字段只写出「按本规范 5.1 逐条判过」这一句。后面再跟几处读数。那一个字段是台账的列名，取用规程的件名。数据里对应的节题作验收准则与判定结论，两处不是两套判据。这层关系记在同编号过程记录文档第 1 条。

### 5.3 判不过的两种处置

只剩两种处置。一种改到过：本规范执笔当场改，改完由评审复核。判定该条不适用而改作不入数据表的也归这条。由评审提、元流水线开发者定，改动记进 00 编号打回台账。

另一种是把事情挂进未完项。这条只收当场改不动的四种：要实测才拿得到的量、要上游答复的条款编号或部位、要立了册才有的户名与编号、要另开一只代理的复核。

写出谁办、几时办、落 00 编号哪一行，交稿前在同编号过程记录文档的未完项一节逐行写清。事实型观测主体缺的那一位，按 3.2.3 写在来源那一个数据项。不留第三种状态：判不过又不在这两种处置里，就是漏改。

所管数据的题面与表达，按《产品数据规范编制规范》6.1 的三问与 7.3 的八条自核。本规范不为它另立专节。
