# AI 引擎（平台 AI 能力）

**文档版本**：v0.1（方案稿，待评审）
**状态**：待裁决

---

## 一、问题与设计立场

**需求**：在 B/S 模式的 EOS 平台上增加 AI 能力——右侧辅助栏增加一个"AI 对话"标签页，切到该标签时辅助栏成为与 AI 的对话窗口；人类在对话中要求 AI 获取或操作**当前页面上的内容**，例如"请将左窗的数据进行统计"、"请分析左窗中第三行的文件中的内容"。

难点不在对话窗口本身，而在**指代消解**与**操作落地**：

| 难点 | 表现 | 本方案的对策 |
|------|------|-------------|
| 指代消解 | "左窗""第三行""这个文件"是屏幕语言，不是数据语言 | 结构化上下文快照 + 稳定标识锚点（§五、§六） |
| 操作落地 | 统计、取附件、改字段，要落到引擎的正规入口 | 能力层工具集，工具即引擎 API（§四） |
| 配置驱动 | 平台由配置生成业务积木，表单种类无穷 | AI 消费**引擎元数据**而非 DOM，不为每个表单定制（§五） |
| 越权与误操作 | AI 可能绕过用户权限或流程节点权限写入 | 三重权限交集 + 写入一律"提议—确认—执行"（§七） |

**核心立场**：AI 不是外挂在页面上的一个聊天机器人，而是**平台的一个横切引擎**——它把人类的自然语言翻译成平台已有的结构化操作，复用既有引擎的能力与权限，自己不新造业务通路。

## 二、AI 引擎在体系中的位置

EOS 现有体系为"引擎三级 + 横切"（[10-eos-architecture §二](../00-eos-product-spec/10-eos-architecture.md)）。AI 引擎的定位与菜单引擎同类：

| 引擎层级 | 引擎 | 生成 | 平台体现 |
|---------|------|------|---------|
| 组件级 | 场景引擎 | L4 场景业务 | 编排场景部件为多窗口场景 |
| 部件级 | 表单引擎、流程引擎、看板引擎、工单引擎 | L5 场景部件 | 一个窗口（含主表单 + 子业务 TAB 群） |
| 元件级 | 实体引擎 | L6 功能元件 | 原子构件（实体对象、事件、定时任务等） |
| 横切 | 菜单引擎 | L1~L4 菜单树 | 菜单节点 CRUD + 权限 + 末级映射 |
| **横切（新增）** | **AI 引擎** | **不生成业务积木** | **辅助栏对话标签页 + 上下文快照器 + 能力层工具网关** |

**不生成业务积木的理由**：AI 不新增 L4~L6 的任何层级，它只提供"人类意图 → 既有引擎操作"的翻译与执行通道。其配置产出是两个非业务资产：

- **AI 能力清单**（AI Capability Definition）——某场景业务允许 AI 调用哪些工具、白名单范围；
- **对话技能包**（Prompt/Skill Pack）——某业务域的系统提示词、术语表、领域知识引用。

**与既有引擎的关系**：AI 引擎是**调用方**，不是替代方。它经能力层调用实体引擎（取数）、表单引擎（改字段）、流程引擎（流转）、指标引擎（统计口径）、看板引擎（呈现）、CAX 引擎（专业格式文件）等；所有调用都走各引擎既有 API 与校验。

## 三、辅助栏交互设计

### 3.1 标签页形态

辅助栏的内容区改为**多标签并存**，而非单一详情区：

```
┌──────────────────────────────┬──────────────────────────────┐
│ 左窗（列表/树表）             │ 辅助栏                        │
│                              │ [详情] [AI 对话]      [关闭]  │
│  ┌────┬────┬────┬────┐       │ ────────────────────────────  │
│  │行1 │    │    │    │       │ 你：请将左窗的数据进行统计      │
│  │行2*│ ← 选中            │ │ AI：将按【采购订单】的 3 个指标 │
│  │行3 │    │    │    │       │     统计当前筛选后的 128 行…   │
│  └────┴────┴────┴────┘       │     [确认] [改为临时聚合]      │
│                              │ ────────────────────────────  │
│                              │ 输入框…                  [发送]│
└──────────────────────────────┴──────────────────────────────┘
```

- **[详情]** 标签：即 91 规范 §1.1.1 已定义的辅助栏标签页（两列「字段名 | 字段值」），行为不变。
- **[AI 对话]** 标签：切到该标签，辅助栏内容区变为对话窗口。
- 两个标签**并存不互斥**——否则 AI 无法引用"当前选中行"，且人类无法一边看字段详情一边与 AI 对话。
- 辅助栏宽度可拖拽伸缩（伸缩时主内容区实时联动），见 [91 规范 §1.2.1](../../20-pl4eos/10-pl4eos-subpl-sysdev/10-wfsysdev-4-eos/91-eos-biz-eng-spec.md) 辅助栏规则。

### 3.2 "当前页面"的定义

AI 语境中的"当前页面"= **当前场景标签页**（浏览器标签页 → 场景标签页 → 窗口标签页 → 表单标签页 这条链上的一个工作区）。其可寻址单元如下，是人类口语指代的锚点集合：

| 人类口语 | 平台语义锚点 |
|---------|-------------|
| "左窗""右窗" | 场景标签页内的活动窗口（单窗态只有一个，双窗态为左/右） |
| "当前标签页""这个表" | 该窗口的激活窗口标签页 |
| "第三行" | 该标签页数据集的**第三可视行** → 经稳定标识（主键/单号）锚定，**不按显示序号落库** |
| "这个文件""附件" | 选中记录的附件类字段（CAX 引擎产出的文档、上传件） |
| "这一页""刚才那份" | 对话会话内已引用过的锚点（会话上下文栈） |

**关键风险与控制**：行号会因排序、筛选、分页、折叠（树表）而变化。上下文快照必须同时给出显示序号与稳定标识，AI 的落库操作一律以稳定标识为准，并在回复中回显人类可读的名称（如"第 3 行 PO-2026-0003"）请人类确认。

## 四、页面—AI 交互协议（能力层）

AI 不生成 SQL、不直接写库、不驱动 DOM，只调用**能力层工具**。工具签名全部取自平台自身的元数据与引擎 API：

| 工具 | 类型 | 引擎/组件 | 说明 |
|------|------|----------|------|
| `page.get_context()` | 读 | 页面运行时 | 取当前场景标签页的结构化上下文快照 |
| `page.get_selection()` | 读 | 页面运行时 | 取各窗口的选中行（含稳定标识） |
| `page.get_visible_dataset()` | 读 | 列表/树表页面 | 取当前筛选、排序、可见列的**标识集合**（不返回全量数据） |
| `entity.describe()` | 读 | 实体引擎 | 取实体、字段、类型、单位、精度、主键、枚举、实体关系 |
| `form.describe()` | 读 | 表单引擎 | 取当前窗口标签页的字段布局、只读性、行为定义 |
| `entity.query(entity, filter, fields, limit)` | 读 | 实体引擎 | 结构化查询（补取上下文之外的数据），**受用户数据权限过滤** |
| `entity.stat(query, agg, group_by)` | 读 | 实体引擎 + 指标引擎 | 统计；先匹配指标引擎已定义的指标口径 |
| `indicator.match(entity)` | 读 | 指标引擎 | 查该实体功能表单上已定义的指标，供统计对齐口径 |
| `attachment.list(record)` | 读 | 实体引擎 | 取记录的附件字段清单 |
| `attachment.fetch(id)` | 读 | 附件解析器 / CAX 引擎 | 取原件与解析后文本（专业格式如 CAD 走 CAX 转换） |
| `attachment.extract_table(id)` | 读 | 附件解析器 | 从文档中抽取结构化表格 |
| `record.propose_update(record, fields, values, reason)` | 写（提议） | 表单引擎 | 生成**字段级差异预览**，不落库 |
| `record.propose_create(entity, values, reason)` | 写（提议） | 表单引擎 | 生成新建记录草案，不落库 |
| `flow.propose_action(record, action, reason)` | 写（提议） | 流程/工单引擎 | 生成流转动作提议，不推进流程 |
| `page.propose_navigate(target)` | 写（提议） | 场景/菜单引擎 | 跳转、开新窗口、下钻的提议 |

**写入路径唯一**：AI **没有**直接写入工具。任何写操作产出**提案对象**（人类可读的差异 + 机器可执行的指令），经人类确认后由**页面自身**调用原引擎 API 执行——即"AI 提议、人类确认、页面执行"。由此天然继承表单校验、流程节点权限、字段只读性等既有约束。

**工具粒度的取舍**：工具按**引擎能力**切，不按业务功能切（不出现"采购订单统计工具"这种表单专用工具）。这是配置驱动平台下 AI 能"零定制适配所有表单"的前提。

## 五、上下文快照（Context Snapshot）

AI 每次收到人类输入时，由页面运行时按需采集并随消息上送一份**结构化快照**。它是 AI 理解"当前页面"的唯一依据。

```
PageContext
├── 导航路径       场景业务 > 主子表单A > 子业务X     ← 面包屑
├── 场景标签页      id、标题、显示模式（单窗/双窗）
├── 窗口[]
│   ├── 位置        left | right | single
│   ├── 活动窗口标签页 { id、标题、显示模式（列表/单据/指标/看板）}
│   ├── 激活表单标签页 { id、名称、所在任务节点 }
│   ├── 实体元数据   { 实体名、字段清单(名/类型/单位/可筛选/可编辑)、实体关系图 }
│   ├── 指标定义     [ { 指标名、口径、度量、维度 } ]
│   ├── 视图状态     { 筛选条件、排序、分页、分组/折叠状态 }
│   ├── 可见数据集   行数 + 首屏行的稳定标识与显示序号（超出部分按需 query 拉取）
│   └── 选中行       { 稳定标识、显示序号、人类可读名称、字段值摘要、附件清单 }
└── 会话上下文栈    本次会话中已引用过的锚点（"刚才那份""这一页"）
```

**设计要点**：

1. **送元数据，不送 DOM**。快照给的是"这是一张采购订单列表，有 12 个字段，其中金额是数值型带二位小数"，不是页面 HTML。同一个 AI 引擎因此能适配全部配置出的表单。
2. **大数据集只送句柄**。可见数据集送"128 行的标识集合 + 筛选条件"，不送 128 行全字段；AI 需要细节时再调 `entity.query` 按需取。
3. **快照有生命周期**。随对话消息生成，不常驻内存；人类切换窗口/标签页/选中行时，后续消息携带新快照。
4. **脱敏在快照生成侧完成**。字段级权限在采集时就已过滤，AI 看不到无权字段——不是靠提示词约束它"不要看"。

## 六、典型链路

### 6.1 "请将左窗的数据进行统计"

```
人类输入
  → 快照：左窗 = 采购订单列表，筛选=状态:审批中，可见 128 行，指标定义= [金额合计, 平均交期, 逾期率]
  → indicator.match(采购订单) → 命中 3 个已定义指标
  → AI 回复："将按【采购订单】已定义的 3 个指标，统计当前筛选后的 128 行" —— 请确认
      · 口径取指标引擎定义（金额合计 = Σ金额）
      · 范围取当前筛选（非全表）
      · 呈现：对话内结论 + 图表；[查看明细] 可下钻到构成行
  → 人类确认 → entity.stat 执行 → 指标引擎计算结果 → 对话区渲染
```

**口径纪律**：优先对齐指标引擎已定义指标；库中无对应指标时，才做**一次性临时聚合**，并在回复中显式标注"临时口径"，给出聚合表达式。人类可将满意的临时口径**一键存为指标定义**（回到指标引擎正规入口），使一次性分析逐步沉淀为平台资产。

### 6.2 "请分析左窗中第三行的文件中的内容"

```
人类输入
  → 快照：左窗活动标签页数据集的显示第 3 行 = PO-2026-0003（附稳定标识）
  → AI 二次确认："第 3 行 PO-2026-0003（供应商：××）的附件《技术协议 v2.pdf》，是否分析这份？"
      └ 该行有多个附件时，列出清单请人类指定
  → attachment.fetch → 解析（PDF/Office → 文本；专业格式走 CAX 转换）
  → AI 回复：内容摘要 + 要点 + 引用定位（页码/章节），并可衔接后续操作（提取表格→写回某字段的提议）
```

**大文件与长任务**：解析超时阈值以上的文件转异步作业，对话区显示进度；不阻塞会话。

### 6.3 写操作样例（"把第三行的交期改成 7 月 20 日"）

```
快照 → 定位 PO-2026-0003 → record.propose_update(交期, 2026-07-20, reason="人类口头指示")
  → 提案对象：字段级差异（原 2026-07-15 → 新 2026-07-20）
  → 人类点击 [确认] → 页面调用表单引擎原 API 写入 → 校验通过 → 落库 + 审计
  → 若该字段只读、或当前流程节点不允许修改 → 提案生成阶段即被拒绝并说明原因
```

## 七、权限、安全与审计

**三重交集**（任一不满足即拒绝）：

| 维度 | 内容 | 承载 |
|------|------|------|
| 人类权限 | 当前登录者对实体、字段、数据行范围的权限 | 功能引擎（数据/字段权限）+ 菜单引擎（菜单可见性） |
| AI 工具白名单 | 该场景业务允许 AI 调用的工具集合 | AI 引擎（AI 能力清单配置） |
| 上下文合法性 | 提议的目标必须落在当前页面上下文可达范围内 | 页面运行时（快照 + 会话栈） |

**硬约束**：

- AI 不得绕过流程节点权限推进流转（流程/工单引擎的校验照常生效）。
- AI 的一切读写都带 `发起者=AI、指示者=人类账号` 双标识，写入审计（含提案全文、确认人、时间、前后值），审计记录不可删改。
- 是否允许 AI **新建业务对象**（场景级动作）为**待裁决**项，见 §九。

## 八、技术实现要点

| 层 | 要点 |
|----|------|
| 前端 | 辅助栏内容区标签容器（详情标签 + AI 对话标签）；对话区支持流式增量渲染、Markdown/表格/图表、提案卡片（确认/驳回）；宽度拖拽与主内容区联动复用 91 规范已定的辅助栏伸缩机制 |
| 通信 | 对话流用 SSE/WebSocket；长任务（附件解析、大批量统计）走异步作业 + 进度推送 |
| AI 引擎服务 | 会话管理、快照组装、工具注册与路由、白名单校验、提案生成、审计落库 |
| 工具网关 | 每个工具 = 一个引擎 API 的受控封装；统一的入参校验、权限校验、超时、幂等键、调用日志 |
| 附件解析 | 可插拔解析器（PDF/Office/图片 OCR/邮件）；专业格式委托 CAX 引擎转换；解析结果可按内容哈希缓存 |
| 模型接入 | 模型可替换（内网/公有云），支持流式；系统提示词与领域知识按"对话技能包"配置化，不写死在代码里 |

**一个工程约束**：工具调用的**可见性与可用性由配置决定**，不由模型自觉。人类看不到的字段、没权限的按钮，对应的工具在网关侧就应被过滤出工具清单——既省 token，也避免模型"幻觉出一个不该有的操作"。

## 十、待裁决事项

1. **AI 引擎的定位**——按本方案作为**横切引擎**（与菜单引擎并列，不生成业务积木），还是作为**组件级引擎**（生成 L4 场景业务，即 AI 可编排业务）？本方案倾向前者。
2. **工具白名单是否配置化**——由业务配置者按场景业务勾选 AI 可用的工具集（更安全、更贴合配置驱动理念），还是平台全局统一开放（更简单）？本方案倾向配置化。
3. **权限引擎是否需要扩维**——现有权限承载在功能引擎（数据/字段）与菜单引擎（菜单可见性）；AI 工具级权限是否新增一个维度，还是复用功能引擎的数据权限表达？
4. **AI 的自治边界**——AI 能否发起新建业务对象、提交审批、跨场景取数？默认建议：**限定在当前场景标签页上下文内**，跨场景与提交类动作一律提议 + 人工确认。
5. **统计结果的信息层级**——AI 统计结论是否允许脱离指标引擎口径自由计算（便利性 vs 口径一致性）？本方案的处理是"优先对齐已定义指标，临时口径显式标注且可沉淀"。
