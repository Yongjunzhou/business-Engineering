# 越界件处置流程（本子项目 · 可复用）

> **适用**：发现的问题落在**本子项目工作目录之外**（或跨区），而依 AOS 根 `CLAUDE.md` §九「主题上可互引、操作上互不干扰」＋子项目 `CLAUDE.md` 边界约定，**本目录无权改**它。
> **首次成型**：2026-10-12，用于 `10-eos-engineering/00-generalspec/01-generalspec-sysdev.md` §1.1「架构」定义仍是 2011 口径＋「架构末级节点」一族把文档树当架构（用户同意"分层做"）。
> **产出一律落本子项目内**：登记目录 `00-系统工程相关研究报告/90-治理登记/`；工作脚本落 `.work-align35/`。**不动越界件一字**。

## 一、六步法

| 步 | 做什么 | 判据／要点 | 本次对应产物 |
|---|---|---|---|
| **1 亲核取证** | **回原文逐字摘录**，并回**库内正本**取证 | 代理报的发现**必须自己再核一遍**（本次代理明标"未亲自核证"，我核出：定义句 2011 版＋自撰释义把文档树当架构，两处独立缺陷） | `03-越界件移交单-…md` §一 |
| **2 定权威层级** | 判定该件在仓库中的权重与归属 | 越界件若是**仓库级权威**（本次是 AOS 三产品的方法论底座），权重高于本子项目全部报告 → 只能移交，不得"顺手改" | `03-…` §四 边界声明 |
| **3 出移交单** | 发现＋逐字证据＋正本依据＋复现命令＋**明确"我没做什么"** | 移交单必须能被**没有上下文的人**照做：给命令、给行号、给正本行号 | `03-…md` |
| **4 分层建议** | 把病灶**按波及面分层**，而不是一锅端 | **事实错**（引废止版／取值错）＝必修且常**零波及**；**命名撞车**（自建术语与标准术语同名不同物）＝**先加口径注声明＋立挂账**，改名是独立决策 | `04-…施工包.md` §一（T1/T2/T3 三层） |
| **5 施工包＋差异补丁** | 给**粘贴级**文本：`--- old / +++ new` 逐块对照＋版本行与历史 bullet 记法 | 改法要写到"复制替换即可"；**"改前提"与"改措辞"分开标**；历史记录按体例**不改写** | `04-…md` §二；`05-…差异补丁.md` |
| **6 干跑与自检** | ①**自检脚本**（施工前后对照读数）②**改名干跑**（分类：可自动替换／须人工处置／历史行）③**逐文件计划差异** | **先跑基线再交**；判据方向**逐条显式声明**；**元陈述行必须单列** | `recheck-rootarch.mjs`／`plan-rename-rootarch.mjs`／`make-rename-diff.mjs`；`06-…逐文件计划差异.md` |

## 二、四条方法纪律（都是踩过才写下的）

1. **代理会假，一律回原文核**——本次回归审计四路共**至少 4 处误报**（`confirmation＝证实`说"无出处"其实对照版有译注；页码/节数说"多一节"其实正本有；版本链说"不一致"其实一致；条款号给错如 A.2.5 实为 A.2.2）。**新纪律：报"缺失／不一致"时先核该处是否存在，再核它是否真不一致。**
2. **基线先跑再交**——"施工前读数"本身就是交付物的一半，否则"改完了"无法证。
3. **自己的工具会污染自己的读数**——清单脚本首版把 `.work-align35/` 与登记目录里自己的产物也计进去了；凡统计脚本**必须显式排除自己的工作目录**。
4. **元陈述行不得盲替换**——含"废止／勘误／原用／改称"等词的行是**在引述旧名**；盲目全量替换会把废止声明改成**自查自指的空转**（24 研那次事故同型）。逐文件差异与干跑都要**先把这类行挑出来单列**。

## 三、用户裁定口径（2026-10-12 定，可复用）

- **分层做**：事实错（引废止版、取值/条款号错）**该修就修**；**命名撞车不改名**，改为**一处口径注声明＋一条 `pending-` 挂账**。
- **理由**：改名代价与收益不对称（本次实测 ≈559 处／约 70 文件，含 skills 两份并行副本、产品数据件、记忆件）；而"被读成一物"的风险，**一句声明即可压住**。
- **挂账格式**：事实（已改什么）／待决（是否改名）／规模（实测处数＋Top 落点）／建议／取证指针——**片段交用户粘入主项目记忆**（本子项目**不写** `.claude/memory/`）。

## 四、触发条件与自查清单

**触发**：核证时发现问题的**权威件不在本目录**；或改动会波及目录外文件/目录（skills、产品数据件、仓库级规范）。

**收尾前自查四问**：
1. 我**逐字**核过原文了吗？正本条号是自己 grep 出来的还是转述的？
2. 移交单里**"我没做什么"**写清了吗（避免被读成已施工）？
3. 分层了吗——哪部分是**事实错**（必须修），哪部分是**命名/体例决策**（挂账）？
4. 我交的是**读得懂用得上的东西**吗（粘贴级文本、基线读数、复现命令、干跑清单）？
