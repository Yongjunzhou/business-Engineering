# 逐章重写，按本轮共识（2026-10-15 用户定）

> **用户原话**：「**后续的工作是，我们从第十四章开始，每次重写一章，就基于本轮对第十四章～十八章的讨论共识**」。

## 一、这条令定的是什么

1. **次序**：**从第14章开始，一章一章往下**（14 → 15 → 16 → 17 → 18），**一章落库再开下一章**；不并章、不跳章。
2. **依据**：**每章重写都基于 2026-10-15 本轮对第14~18章的讨论共识**——共识不再散在各处，已固化。
3. **门**：**一阶段一确认**；用户同日另令「**不要出阶段二**」——**各章阶段一确认前，不出下一阶段**。

## 三、每章开工的七步（照《逐章修订手册》七阶段）

1. 读 `MEMORY.md` → 读 **框架 §五 第 22／23 条** → 读该章入口文件（抬头＋本章裁定）→ 读本件。
2. **阶段一**（目的·目标·主线·内容概要／摘要）：**双落点展示**（对话全文＋入口文件分节）＋关内清单＋证据块三格（守据／尺度／拦下）＋"请确认"。
3. 确认后才走**阶段二**（全库点检表＋原料清单）→ 三（框架）→ 四（正文十三步）→ 五（概念一致性）→ 六（标题名实）→ 七（表达）。
4. **连带件与该章同批**（框架 §三 行／目录／案例设定／`19-附录.md`／主线支撑／三条线索／训侧对应单元／派生件与 `成书/build`）；**报告库的连带随章就地改**（不另开批）。
5. **"工作量大"不作理由**；技术性同批须写明批次与落点。
6. 收工：复算（量尺＋三条线索脚本）＋**记忆写回**（本轮人为决断／新挂账／可交付修订）＋提交双推。
7. **一章落库后再开下一章**。
