### 0.2 架构树模板

```text
EOS 企业运营体系 — 系统需求
└── 信息系统 ────────────── ① 承接业务流程的信息系统（可有多个；功能部分与非功能部分共用此根）
    ├── 【功能部分 srb-biz】分类视角 · 单归属（一个系统用例功能只归一 类）
    │   └── 系统用例功能簇 ─── ② 对 ③ 的再聚类（职责族）
    │       └── 系统用例功能类 ─ ③ 按系统职责对 ④ 的聚类
    │           └── 系统用例功能 ─ ④ 实现同一功能的不同实现方式
    │               └── 用例场景功能 ─ ⑤ 将用例场景转换为系统视角的功能 ← 枝梢（05 到此为止）
    └── 【非功能部分 SysReq-NFR】
        └── 一级类目 ──────── ② 质量特性 / 环境适应性 / 可实现性
            └── 分类维度 ──── ③
                └── 具体系统非功能需求 ─ ④ 量化指标 + 统计口径 + 验证方法 ← 末级
```

> **功能表单不属于本树**（2026-09-10 定）：功能表单是「**用户操作页面视角**」对系统用例功能的聚合——一个系统用例功能可按需出现在多张功能表单上；而本树是「**功能分类视角**」——一个系统用例功能只归一 类。两个视角正交，功能表单不入本树的任何层。

### 0.3 层级口径

| 层级 | 层级名称 | 含义 | 是否进入 pa-eng设计 |
|------|----------|------|------------------|
| ① | 信息系统 | 承接业务流程的信息系统（可有多个）；功能与非功能共用此根 | 否 |
| ② | 系统用例功能簇 / NFR 一级类目 | 对 ③ 的再聚类（职责族） | 否 |
| ③ | 系统用例功能类 / NFR 分类维度 | 按**系统职责**对 ④ 的聚类（单归属） | 否 |
| ④ | 系统用例功能 | 实现同一功能的不同实现方式 | 否 |
| ⑤ | **用例场景功能** | **枝梢**——本文件（框架）到此为止 | 是 |
| NFR ④ | 具体系统非功能需求 | 非功能部分的末级（量化指标+统计口径+验证方法） | 是 |

> 叶（**⑥ IPO功能**：系统接收某组字段的值→处理→给出响应）只在完整态产出，见 `06-eos-system-requirement-detailed.md`；本文件为框架，不含叶。树形/级语义单源见 [94-eos-sys-dev-dbs.md](../10-pl4eos-subpd-sysdev/10-wfsysdev-4-eos/94-eos-sys-dev-dbs.md) §2.3.1/§2.3.2。

## 3. 规则区 / 口径区

### 3.1 功能部分生成规则

1. `wft03` 只将 `首次出现` 的 bpd-biz末级节点生成为 srb-biz节点（枝梢＝⑤ 用例场景功能）。
2. `非首次出现` 的 bpd-biz节点不重复生成 srb-biz，只在映射和复用说明中登记。
3. srb-biz 按**系统职责**聚类组织（树的层与级语义见 [94-eos-sys-dev-dbs.md](../10-pl4eos-subpd-sysdev/10-wfsysdev-4-eos/94-eos-sys-dev-dbs.md) §2.3.1）。`业务定义类型`（流程定义/表单定义/指标定义等）属**产物类型口径**，用于 配置方案 层组织，不用作本树的第一层。
4. 仅当同一职责类下节点过多、语义差异过大或 pa-eng承接边界不清时，才增加可选中间聚合层。
5. 每个 srb-biz枝梢节点应能追溯到来源 bpd-biz IPO 和对应 业务框架末级节点。

### 3.2 非功能部分生成规则

1. 非功能需求不经过 bpd-biz，直接从 bpl-nfr 详细定义末级节点映射。
2. SysReq-NFR 应保留可验证量化指标，并明确对 pa-eng的约束。
3. NFR 分类应优先引用 `22-eos-nfr-taxonomy.md` 中已确认分类。

### 3.3 状态口径

| 节点类型 | 状态口径 | 推荐状态 |
|----------|----------|----------|
| 干枝节点（②③④） | 分类方案是否稳定 | 待确认分类 / 分类已确认 / 分类迭代中 |
| 枝梢节点（⑤ 用例场景功能） | 是否可进入产品架构设计 | 待产品架构 / 已产品架构 / 迭代中 |
