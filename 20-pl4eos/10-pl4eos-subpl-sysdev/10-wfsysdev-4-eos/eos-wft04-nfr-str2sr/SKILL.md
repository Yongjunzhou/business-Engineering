## 一、职责定位

### 负责与不负责

| 负责 | 不负责（路由指向） |
|------|-------------------|
| 接收≥1个 bpl-nfr 节点（`可以NFR设计`/`待补充NFR设计`），校验状态/分类边界 | 修改 wft01-nfr 已确认的角色语境/NFR 分类边界/规范化的相关方需求 分组 → 退回 `wft01-nfr` |
| 量化——承接相关方经澄清确认的目标值，展开系统级量化指标（名称/单位/统计口径/测量方法/验收条件） | 设计业务场景/输出文档/功能表单 → biz 路径 |

| 退回——bpl-nfr 分类边界/角色语境/适用范围不足时退回 `需wft01修订` | — |

### Step 3 · 非功能需求架构设计

#### Phase A — bpl-nfr 消费感知与宿主匹配

逐 bpl-nfr 检查消费版本——首次消费→全量设计，版本递增→按变更声明分流；分类边界或语境不足→退回 wft01-nfr。按 22 分类维度 + 约束对象 + 指标口径匹配已有宿主：

| 条件 | 路由 |
|------|------|
| 已有 SysReq-NFR 分类维度+约束对象+指标口径兼容 | 归入该宿主 → Phase B |
| 不满足 | 进入待聚合池 → Phase C |
| 多个宿主均可承载或语义不内聚 | 标记 `[需裁决]` |

待聚合池按**同一 22 分类维度 + 同一约束对象类型**分组。

#### Phase B — 修订已有 SysReq-NFR

1. **要素提取**——从 bpl-nfr 提取待量化线索、适用对象线索和 22 分类路径
2. **宿主匹配检查**——Q1→追加指标和追溯；Q2→修订宿主+变更声明；宿主冲突→`[需裁决]`（详见 human spec §3.2.3）
3. **重判定与关系检测**——基于全部 bpl-nfr 重新量化指标，比对已有基线判定六种关系（详见 human spec §3.3.3）：

| 关系 | 判定 | 处理 |
|------|------|------|
| 确认 | 指标匹配+22分类一致+来源升级 | 追加 bpl-nfr 引用 |
| 无新增 | 指标匹配+全部已确认 | 增量合并口径/测量细节 |
| 指标口径变更 | 指标匹配+目标值/统计口径/测量方法变化 | 更新指标定义+变更原因 |
| 22判定变更 | 指标匹配+22判定不同 | 更新22判定+变更原因 |
| 补充 | 指标不匹配 | 新增量化指标 |
| 过时 | 基线指标未被本轮覆盖 | `[过时]`+保留不删 |

4. **变更影响声明**——判定变更类型，写入 SysReq-NFR 节点末尾

#### Phase C — 新建 SysReq-NFR

1. **确定 22 分类路径** → 一级类目 → 分类维度 → 具体需求归属判定
2. **生成量化指标** → 逐需求项提取待量化线索 → 目标值/单位/统计口径/测量方法/验收条件。**信息不足时标注 `待确认`，不伪造确定值**。多对象可切分指标按分解规则生成子指标（四类运算：加法=响应时间/乘法=可用性/弱链=吞吐量/职责分布=安全审计权限；候选子预算 `[需裁决]`，人类确认后入约束包；父→子引用记录；单对象指标不分解；子指标到组件类型级标 `待wft05映射`，规则见 human spec §3.2.1）
3. **判定分层约束** → 六类约束范围判定（附录 A.3）
4. **生成页面 NFR** → 影响用户可感知页面行为时绑定页面类型/srb-biz/业务域
5. **装配分层约束包** → 按全局/业务域/srb-biz/页面级/CU/pa-eng组件/共享七组独立组织
6. **组装 SysReq-NFR** → 写入 `05-*.md`

### Step 4 · 页面与分层约束设计

**1. 分层约束表生成**

基于 Step 3 量化指标，逐条判定约束范围。每条记录：约束行 ID、约束范围、约束对象、量化指标引用、影响级别（阻断型/非阻断型/待判定）、消费目标（统一为 `wft05-eng`）。

| 约束范围 | 判定线索 |
|----------|---------|
| 全局 | 影响 EOS 整体运行质量 |
| 业务域 | 只影响某业务域或产品类型 |
| srb-biz | 指向具体功能性系统需求 |
| CU | 指向配置单元、配置规则或配置可达性 |
| pa-eng组件 | 指向前后端组件类型、接口或运行机制 |
| 页面级 | 指向七种页面类型之一、具体页面 ID、交互行为或页面体验 |

**2. 页面 NFR 生成**

当指标影响用户可感知页面行为时生成。页面类型从 91 规范七种中选择：菜单标签页、场景标签页、窗口标签页、全屏单据页、辅助栏标签页、弹窗页面、配置页面。逐条写入九项：指标 ID / 页面类型 / 具体页面 ID（暂缺标记待目标绑定）/ 约束内容 / 量化目标 / 测量方法 / 影响点 / 消费目标 / 确认状态。全量 `[推断]`。

**3. wft05-eng NFR 约束包装配**

生成唯一约束包，只引用分层约束表行 ID 和页面 NFR 条目，不复制正文。**分解子指标作为独立约束行装配，标注「分解运算 + 父指标引用」**（分解规则见 human spec §3.2.1）。包头记录：约束包 ID / 包版本 / 生成时间 / 来源 SysReq-NFR / 上一版本 / 变更类型 / 新增/修订/删除行 / 消费状态 / wft05-eng 已消费版本。正文按七组分别列示（全局/业务域/srb-biz/页面级/CU/pa-eng组件/共享）。

**首版发布门禁**：全局/共享约束可无具体对象 ID；业务域约束必须绑定业务域；srb-biz/CU/页面级约束必须绑定已存在的目标 ID；pa-eng 组件级约束在 pa-eng 未生成时只记录组件类型+映射条件，标记 `待wft05映射`，不得虚构 pa-eng ID。阻断型约束未满足条件 → SysReq-NFR 保持 `待目标绑定`，不发布首版。

### Step 5 · 闭环检查

逐 SysReq-NFR，七项检查：

| # | 检查项 | 不通过处理 |
|---|--------|-----------|
| 1 | 量化完整——全部需求项已生成量化指标或标注待确认 | 标记 `[覆盖缺口]` |
| 2 | 宿主唯一——每条需求项有唯一 SysReq-NFR 宿主 | 标记宿主冲突 |
| 3 | 分层正确——约束范围未错层 | 修正分层 |
| 4 | 页面可消费——影响页面体验的 NFR 已生成页面级约束 | 补充页面 NFR |
| 5 | eng 一致——共享指标保持同一 ID/目标值/测量方法 | 对齐指标 |
| 6 | 22 可落账——写回项指标集完整、分类路径明确 | 标记 `[覆盖缺口]` |
| 7 | 06 可验证——详细定义含来源/指标/测量/验收/追溯 | 补充 06 条目 |

| 类型 | 动作 |
|------|------|

| 关系 | 判定 | 处理 |
|------|------|------|
| 确认 | 指标匹配+22分类一致+来源升级 | 追加 bpl-nfr 引用 |
| 无新增 | 指标匹配+全部已确认 | 增量合并口径/测量细节 |

### A.9 量化指标分解规则

| 分解运算 | 适用指标 | 预算方向 | 处理 |
|---------|---------|---------|------|
| **加法** | 响应时间等可切分指标 | Σ 子目标 ≤ 系统目标 | 按组件类型切预算：父指标 + N 条子指标（各约束对象类型），父→子引用标注；候选子预算基于 22 模板/同类场景推断，标 `[需裁决]` |
| **乘法** | 可用性等可切分指标 | Π 子目标 ≥ 系统目标 | 按组件类型切可用性目标，父→子引用标注；候选子目标标 `[需裁决]` |
| **弱链** | 吞吐量/并发等 | 每子目标 ≥ 系统目标 | 不切预算，逐对象类型指派（各承接全量） |
| **职责分布** | 安全/审计/权限/易用性等 | 无守恒 | 不切预算，逐对象类型指派职责 |

**多对象识别**：约束对象类型按 91 §8.5 三类组件（前端/后端/平台服务）+ srb-biz/CU/页面级判定；一条指标同时影响多个对象类型时为多对象。加法/乘法多对象→生成子指标（组件类型级）；弱链/职责分布多对象→逐对象类型生成约束行、不切预算。**单对象指标不分解**，一条到底（保持原约束范围）。子指标目标到组件类型级，不预判具体组件（`待wft05映射`）。**记录**：父指标记「分解运算 + 子指标引用」，子指标记「父指标引用 + 分解运算 + 目标对象类型」。
