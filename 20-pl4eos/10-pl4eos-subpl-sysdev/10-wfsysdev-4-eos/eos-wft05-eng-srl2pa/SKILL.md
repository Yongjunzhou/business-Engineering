### Step 3 · 约束映射与平台架构决策

先加载 NFR 约束包：首次消费全量加载；版本递增时按变更声明仅处理增量和修订行。逐约束行判定范围（CU级→前后端组件参数 / 组件级→并发/缓存/持久化 / 全局级→平台架构决策）。

随后加载 FR-BIZ 指标约束包并逐行承接映射：Q1 已覆盖行判定承接组件归属（指标展示 → 前端组件、指标计算/聚合 → 后端组件、共享指标基础 → 平台服务组件），记录承接组件及包版本/消费版本到 pa-eng 节点；Q2/Q3/Q4 缺口行标记为待FR-ENG 规范化的相关方需求节点（或待裁决结论），不承接。

输出四类平台架构决策（部署/通信/数据/安全），每项引用来源约束行 ID。对携带「分解运算」的 NFR 约束行按类型处理：可用性子目标（乘法）绑定到对应组件类型并作为验收目标；响应时间类（加法）不硬切分，由组件设计预算（记 pa-eng/SRD 作为设计决策）共同保证 E2E 目标。约束映射完成后，将本 Skill 消费的 NFR 约束包版本与消费状态（已消费）回写约束包头。

#### Phase A — 候选组件生成与宿主匹配

逐系统需求概要 srl-eng 提取组件候选（组件业务[布局组件→前端容器、构件类型→公共构件、承载操作活动→前后端组件]、pa-eng收敛项→决策候选），然后按归属+职责+承接对象匹配已知 pa-eng：

| 条件 | 路由 |
|------|------|
| 归属+职责+承接对象落入已有 pa-eng 组件 | 归入 → Phase B |
| 不满足 | 待聚合池 → Phase C |
| 组件可能公共化/拆分/合并或跨引擎归属不明 | `[需裁决]` |

#### Phase B — 修订已有 pa-eng

1. **要素提取**——从本轮 srl-eng 提取组件候选，已有仅追加不重建
2. **组件匹配检查**——Q1复用→追加来源；Q2扩展→全量重写+变更声明；需裁决→`[需裁决]`
3. **重判定与关系检测**——基于全部 srl-eng 和当前 NFR 重判归属，比对基线判定六种关系（确认/无新增/组件职责扩展/归属变更/补充/过时）
4. **变更影响声明**——判定类型（无变更/增量/修订/结构/返工），写入 pa-eng 末尾

#### Phase C — 新建 pa-eng

1. **判定平台架构归属**——五类（引擎专属/布局组件扩展/公共构件/公共平台服务/运行支撑模块），优先复用已有公共能力
2. **推断前端组件**——组件业务（布局/构件类型→容器→交互构件→状态反馈）
3. **推断后端组件**——校验/持久化/发布/审计/运行支撑→同步异步/回滚点
4. **制定平台架构决策**——部署/通信/数据/安全
5. **推断平台服务组件**——职责/约束行ID/实现策略/依赖/消费方
6. **装配三类组件架构**——循环依赖和无人承接检查
7. **展开 SR 详细定义并组装 pa-eng**——写入 `06/07`

## 附录A：判据速查

### A.1 平台架构归属五类

| 归属 | 典型组件 |
|------|----------|
| 引擎专属组件 | 流程发布服务、看板指标聚合服务 |
| 布局组件扩展 | 树表配置容器、配置详情辅助栏 |
| 公共构件 | 发布按钮、回滚按钮、引用钻取 |
| 公共平台服务 | 审计服务、版本服务、任务调度服务 |
| 运行支撑模块 | 运行日志模块、错误恢复模块 |

### A.2 三类 pa-eng 组件

| 组件类型 | 来源 | 核心定义 |
|----------|------|---------|
| 前端组件 | 组件业务（布局/构件类型）+承载操作活动 | UI层实现单元，承载显示、交互和页面状态 |
| 后端组件 | 组件业务承载的操作活动+系统处理 | 服务层实现单元，承载校验/保存/发布/运行处理 |
| 平台服务组件 | 全局/共享/业务域级 NFR | 基础设施层部署单元，承载全局约束 |

### A.3 四类平台架构决策

| 架构 | 决策内容 |
|------|----------|
| 部署架构 | 节点、集群、扩缩容、容灾与故障域 |
| 通信架构 | 协议、同步/异步、消息、超时、重试与幂等 |
| 数据架构 | 持久化、缓存、一致性、备份恢复、生命周期 |
| 安全架构 | 身份、权限、加密、审计、密钥与边界防护 |

### A.4 NFR 影响点→承接位置

| NFR 影响点 | 承接位置 |
|------------|----------|
| 性能/并发 | 后端发布/装载/运行支撑组件；前端状态反馈 |
| 安全/权限 | 前端可见/可操作规则；后端鉴权与权限校验 |
| 审计/追溯 | 后端审计组件；前端引用关系/日志查询入口 |
| 可用性/可靠性 | 后端重试/补偿/回滚/降级 |
| 可观测性 | 运行日志/指标/告警/追踪 |
| 兼容性/易用性 | 前端容器/构件交互/提示/校验体验 |

### A.5 SR 详细定义六要素

| 要素 | 说明 |
|------|------|
| 系统职责 | 系统必须提供什么能力 |
| 输入/触发 | 页面动作、事件、状态或配置 |
| 系统处理 | 校验/保存/发布/查询/回滚等摘要 |
| 输出/结果 | 页面反馈、状态变化、记录、事件 |
| 约束与 NFR | 性能/安全/审计/可靠性等 |
| 验收口径 | 如何验证该需求被承接 |

### A.6 十项闭环检查 + 正式冻结条件

闭环检查：组件业务覆盖/活动覆盖/组件覆盖/pa-eng收敛/NFR承接/FR-BIZ承接/平台架构/平台服务/依赖闭合/SRD完整。

正式冻结（八条全满足方可推进）：srl-eng已确认/组件业务构件活动均有组件承接/pa-eng收敛项已闭合/阻断型NFR已改变设计/FR-BIZ指标约束包Q1行均有组件承接结论（Q2/Q3/Q4缺口行已关联FR-ENG候选线索或规范化的相关方需求节点或待裁决）/三类组件依赖闭合/SRD完整可验证/人类已确认全部pa-eng条目。

### A.7 pa-eng 双生命周期状态流转

**srl-eng 侧**：`已详细定义` ──wft05锁定──→ `在pa-eng设计` ──wft05完成──→ `已pa-eng架构`

**pa-eng 侧**：`待确认方案` ──人类确认──→ `已确认方案` ──冻结──→ `待追溯验证` ──验证──→ `已验证冻结`

### A.8 pa-eng 层收敛项承接锚（输入锚）

**pa-eng 是 wft05-eng 的设计产出**（前端承接配置展示/交互，后端承接配置处理与业务逻辑）；**pa-eng 层收敛项是 wft04-eng 在组件业务条目中标注的待本 Skill 判断的问题线索**——本 Skill 只承接设计组件，不重新标注收敛项（发现缺失退回 `需wft04修订`）。

| 收敛项 | 标注 | 本 Skill 承接 |
|--------|------|--------------|
| 组件边界 | `pa-eng层收敛-组件边界` | 判定组件归属与边界 |
| 接口问题 | `pa-eng层收敛-接口` | 定义组件间接口契约 |
| 数据问题 | `pa-eng层收敛-数据` | 决定持久化归属与数据架构 |
| 运行问题 | `pa-eng层收敛-运行` | 决定同步/异步、回滚、缓存等运行机制 |
| NFR 问题 | `pa-eng层收敛-NFR` | 消费约束包后承接约束 |

> **载件是 pa-eng 收敛项的主要来源**——wft02-eng 详设的配置信息组"系统处理·生效后响应"生成的载件（数据/配置/界面/构件/实例/支撑载件），经 wft04-eng 标注为收敛项后由本 Skill 判断如何由前后端组件承接。
