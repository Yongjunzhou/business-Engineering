## 一、职责定位

### 1.1 负责与不负责

| 负责 | 不负责（路由指向） |

| 方向 | 对象 | 交接内容 |

## 二、操作流程

### Step 布局总览

|------|------|------|---------|---------|------|--------|

### Step Start · 为任务选择并校验材料

1. 检查 `../../../80-pl4eos-2-eosdata/00-origin-requirement-materials/` 存在；不存在则创建
2. 检查 `10-raw-files/` 存在；不存在则创建
3. 检查 `01-eos-sysdev-status.md` 存在；不存在则按该文档自身已定的表结构创建（表 A／表 B 及其表头、字段说明）
4. 状态文档已存在的，校验三张表的表头与字段说明；不一致时按 §四 的字段表对齐
5. 确认处于 git 仓库且 AI 基线可用：`.scripts/ai-commit.sh` 存在；基线 = 状态文档的基线记录字段，或最近一次 AI 提交
6. 用 `ls 10-raw-files/` 与状态文档表 A 生成**候选清单**：每份待处理材料占一行，列出源文件名、生命周期、AI建议，人类选定本批处理的一份或多份
7. **按状态路由**（见 SKILL 指南 §5.1）——`人类决策=已终止` 而生命周期停在 `已登记`/`已文本化` 的进本批；生命周期为空且源文件仍在的进本批（走重进入）；`已废弃（重复）` 且源文件已不存在的进本批（交 Step 3/4 收尾）；`人类决策=同意切分`/`暂不切分` 的不进本批，列入行动清单
8. **受理门槛**——逐文件判：`.textualized.md` 结尾或含 `.chunk-` 的不是原始需求，跳过；表 A 上生命周期已是 `已文本化` 或更后的跳过（重做须先清空该行生命周期值）；`已废弃（重复）`／`已废弃` 的跳过
9. 无待处理材料且无入口检出的存量 → 输出「无待处理对象」→ 退出；否则进入 Step 1

**加载经济原则**：用 `ls`/glob 扫描 `10-raw-files/` 与状态文档表 A，不 Read 整个状态文档或整个目录；查重比对只读既有工作副本的**正文区**。

### Step 1 · 基于材料生成文本化方案

存量节点先于新输入处理。对每一份材料依次走 SKILL 指南第四章的三步：

1. **换载体**——逐份读取源文件内容，转成 Markdown；无法识别或不确定的按 §三 转录标注速查写占位符；保留原文结构（章节/段落/列表/表格），不修改、不摘要、不解释。转换失败（损坏/加密/格式不受支持/报错）的不产出文档，在表 A 登记失败：`内容摘要=转换失败：<原因>`、`生命周期=已登记`、`AI建议=待人工处置`；部分成功的能转部分正常转录，未转部分正文区标 `[转换失败：<原因>]`，仍按 `已文本化` 处理
2. **查重**——新文本化正文区与既有工作副本正文区逐字精确比对（忽略行尾空白与连续空行差异；比对范围：表 A 上生命周期不是 `已废弃（重复）` 的既有工作副本）：

| 结果 | 方案 |
|------|------|
| 无重复 | 输出完整工作副本；登记草稿按 `已文本化` + `可以切分` |
| 重复 | 输出定向引用文档（正文区仅指向原文档）；登记草稿按 `已废弃（重复）`、`内容摘要=与<源文件名>内容完全重复` |

3. **登记**——填写表 A 对应行的各列草稿（见 §四 表 A 列与取值）

三步走完，本批每份材料都给出一份方案：正文区草稿 + 独立正文或定向引用的判定 + 一行登记草稿。**方案不作状态写入**，随方案一并交 Step 2。本步无人类参与点。

**失败处置**：源文件读不到或转录中途报错的，该份材料登记失败、`处置标记=待人工处置` 交 Step 2，其余材料照常。

### Step 2 · 基于对话确认文本化方案

1. 列出**未确认清单**——本轮新生成的方案 + 表 A 上状态为 `文本化方案待确认` 的遗留方案，逐份给出处置建议，交人类讨论
2. 按讨论结果修改方案；人类确认后该份材料转为已确认。确认的单位是材料，可逐份给也可一次全部确认
3. **写回前的要素机械检查**——逐份检查：管理区四项非空或属合理空置、正文区有内容或已按 §三 标注、标注齐备。检查不过的就地补齐；无法补齐的回 Step 1 重做
4. **写回**：

| 对象 | 讨论结果 | 写回动作 |
|------|---------|---------|
| 本轮生成或修订的方案 | 已确认 | 写工作副本与表 A，生命周期写 `已文本化` |
| 本轮生成或修订的方案 | 未确认 | 写工作副本与表 A，状态写 `文本化方案待确认`，留作下一轮处理对象 |
| 遗留的待确认方案 | 已确认 | 推状态到 `已文本化`，正文按讨论结果改或不改 |
| 遗留的待确认方案 | 仍未确认 | 不动 |

5. 已被下游消费过的材料本次被修订的，维持原状态、版本递增，或标为待下游重审
6. **写回顺序（同步契约）**：先更新状态文档表 A（权威源），再从表 A 推导写入工作副本管理区；两者不一致时以表 A 为准重建管理区
7. 写回前执行 §五 冲突检查

### Step 3 · 检查材料并检出待处置项

检查取三面：

- **载体这一面**——每份材料都换成了工作副本，源文件未被改动；正文区只有纯原文与转录占位标注，无切分标记、方案块或分析建议块
- **查重这一面**——判为重复的确实与既有正文逐字一致；判为不重复的确实无逐字一致的既有正文
- **要素这一面**——管理区四项齐备、正文区有内容或已标注

检出问题的在 `处置标记` 列记 `待处置`，按三类锚点归位：

| 类 | 锚在哪 | 例 |
|----|--------|----|
| 材料缺陷类 | 源文件 | 损坏、加密、格式不受支持、转换器报错；部分转换成功而未转部分 |
| 重复判定类 | 表 A 的对应行 | 判重存疑、重复误判、源文件已删而重复关系已记录 |
| 要素缺项类 | 工作副本 | 管理区四项不齐、正文区为空、标注不完整 |

产出检查结论与待处置项清单交 Step 4。本步无人类参与点。所依据的既有工作副本不可读时，该份材料的 `处置标记` 记 `待处置` 交 Step 4 讨论，不静默通过。

### Step 4 · 基于对话裁决待处置项

1. 列出**待处置项清单**——每条写明锚在哪份材料或哪个工作副本上、属于哪一类、缺的是哪一样，交人类讨论
2. 逐条裁决：材料缺陷类的，人类修好或换掉源文件后重跑；重复判定类的，判「确认」即删源文件、判「误判」即清空表 A 生命周期值重跑；要素缺项类的，就地补齐或回 Step 1 重做
3. **复跑检查**——每执行一处修改即复跑 Step 3 的检查，范围限被改动的材料；改动触及重复关系的按 91 §A.5.3 的级联处理 `处置标记=待处置` 回 Step 1 重走。同一处反复退改超过一次的，停止处理，`处置标记=待处置` 留待下一轮
4. **写回**——判「确认重复」的源文件删除、定向引用文档保留，表 A 落 `已废弃（重复）`；判「重跑」的按 §六 重进入；判「误判」的删掉定向引用文档、重新判定。裁决完成的行清掉 `处置标记`。改动使管理区变更的，一并写回

### Step End · 给出本轮任务成果总结

输出三区摘要（本次运行报告 + 下一步交接），结束：

```text
当前状态：<已文本化 / 文本化方案待确认 / 待处置 / 待人工处置 / 已废弃（重复）/ 无待处理对象>
  本轮已文本化：<N 份，逐份列源文件名>
  本轮判为重复：<N 份，逐份列「源文件名 → 与<原文档>内容完全重复」>
  本轮待人工处置：<N 份，逐份列「源文件名 → 缺陷与原因」>
  检查结论：<通过 / 检出待处置项 N 处，已裁决 M 处>

一、未确认的方案
  <本轮未确认 N 份：源文件名 + 状态；无则写「无」，下一轮运行接着讨论>

二、下一步
  本任务 → 选定新一批待处理材料重新运行
  下游    → 切分任务（取本轮交出的文本化文档）
```

收尾：更新状态文档的基线记录，提交本轮变更（`.scripts/ai-commit.sh`，author=EOS-AI + `[AI]` 前缀）。工作区无改动时跳过提交。

## 三、AI 标记约定

**转录占位标注**——含义是「此处需人工确认」的提示牌，不是 AI 加工结论。宁可用标注如实说明，也不凭空补全。标注写入正文区：

| 场景 | 标注 |
|------|------|
| 图片/扫描件 | `[AI 识别，待人工确认]` |
| 录音听不清 | `[听写不清]` |
| 手写可辨识 | `[AI 推测]` |
| 手写不可辨识 | `[原文模糊]` |
| 完全无法识别的图片 | `[图片：无法识别文字内容]` |
| 文档明显不完整 | 文档开头 `[文档疑似不完整：缺页/截断]` |
| 多语言混写 | 保留原语种，必要时标注 `[中文/英文/…]` |
| 转换失败（损坏/加密/格式不支持/报错） | 不产出文档，表 A 登记 `转换失败：<原因>`（`生命周期=已登记`、`AI建议=待人工处置`） |
| 部分转换成功 | 能转部分正常转录，未转部分正文区标 `[转换失败：<原因>]`，按 `已文本化` 处理 |

**增量与状态标记**：`[新增]`／`[变更]`／`[确认]`／`[需裁决]` 按 91 §A.3.1 执行。本任务另用三枚：`[待复核]` 标候选清单中归上存疑的行；`[待处置]` 标检查检出的问题；`[推断]` 标转录中由 AI 推定而未获确认的内容。增量清单在 Step End 输出，不写入资产文档。

## 四、判据速查

### 4.1 受理门槛（Step Start 过滤）

| 跳过原因 | 判定条件 |
|---------|---------|
| 不是原始需求 | 文件名以 `.textualized.md` 结尾（本步产物）；或含 `.chunk-`（下游需求文档） |
| 已在处理流程中 | 表 A 已有记录，生命周期为 `已文本化` 或更后（重做须先清空该行生命周期值） |
| 重复关系已记录 | 表 A 生命周期 = `已废弃（重复）`（已通过定向引用文档记录） |
| 已废弃 | 表 A 生命周期 = `已废弃`（如需重新启用，先清除该行生命周期值） |

> `已登记` 材料每轮重新进入转换：转换失败自动重试、中断材料继续处理。

### 4.2 查重判定

| 结果 | 判定 | 处理 |
|------|------|------|
| 无重复 | 无任何既有工作副本正文与新材料逐字完全一致 | 输出完整文档；表 A → `已文本化` + `可以切分` |
| 重复 | 有既有工作副本正文与新材料逐字完全一致（忽略行尾空白/连续空行） | 定向引用文档；表 A → `已废弃（重复）` |

### 4.3 表 A 列与取值（本任务写入的列）

| 列 | 取值 / 写法 |
|----|------------|
| 记录ID | `ORT-YYYYMMDD-序号`（序号为本日流水号，从 001 起） |
| 内容摘要 | 一句话摘要；重复写 `与<源文件名>内容完全重复`；失败写 `转换失败：<原因>` |
| 源文件 | 原始文件名（含扩展名） |
| 文本化文档 | `{原始文件名}.textualized.md` |
| 生命周期 | `已文本化` / `文本化方案待确认` / `已废弃（重复）` / `已登记`（转换失败） |
| AI建议 | `可以切分` / `已废弃（重复）` |
| 处置标记 | 转换失败写 `待人工处置`；其余留空 |
| 操作指引 | 人类下一步应执行的操作 |

> `人类决策` 列是人类输入面，本任务只读不写：空（未处理）/ `同意切分` / `暂不切分` / `已终止`。表 A 的完整列定义与其余各表以状态文档自身为准。

### 4.4 状态路由（Step Start 分流）

| 表 A 状态 | 走哪条路 |
|-----------|---------|
| `人类决策=已终止` 且 生命周期 ∈ {`已登记`,`已文本化`} | 进本批，Step 1 给出「置 `已废弃`」方案，Step 2 写回 |
| `人类决策=已终止` 且 生命周期 ∈ {`切分方案待确认`,`已切分`} | 不进本批，行动清单提示走 `eos-or01-chunk`（含表 B 需求文档联动） |
| `生命周期` 为空 且 源文件仍在 | 进本批，按 §六 重进入分流 |
| `生命周期=已废弃（重复）` 且 源文件已不存在 | 进本批，Step 3 检出、Step 4 裁决收尾 |
| `人类决策=同意切分` / `暂不切分` | 不进本批，列入行动清单 |

## 五、写回与版本感知

### 5.1 写回前冲突检查

状态文档表 A 是人类与 AI 共同维护的表。AI 写回前执行冲突检查，防止覆盖人类手工修改：

1. **快照**——Step Start 记录待处理行的生命周期与人类决策当前值
2. **写回前复核**——写回前重读该行；与快照不符（人类在本次运行期间手工修改）的标 `[需复核]`、不覆盖，在 Step End 向人类提示
3. **人类决策保护**——`人类决策` 是唯一由人类写入的字段，AI 绝不覆盖非空的人类决策

### 5.2 写回顺序（同步契约）

1. **先更新状态文档表 A**（权威源）——登记 / 转迁生命周期 / 更新 AI建议与操作指引
2. **再从表 A 推导**写入工作副本管理区状态表（阶段/AI建议/待处理/操作指引）
3. 两者不一致时，以表 A 为准重建管理区
