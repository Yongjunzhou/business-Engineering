## AI读取文档说明

本文件是业务方案（bpd-biz）架构类树形资产文档。AI 读取本文件时应按需读取，不应默认读取全部正文。

默认读取顺序：

1. 读取文档元信息和本说明，确认文档用途、状态和读取规则。
2. 读取 `0. 职责视角业务流程树画像`，建立业务域、角色与节点规模的感知。
3. 读取 `1. 业务方案状态与处理队列`，确定本轮 bpd-biz 节点、活动锁、待资产写回队列和当前待办 ID。
4. 读取 `2. 业务方案节点索引 / 分片索引`，定位目标 bpd-biz 正文块、候选宿主块和必要追溯关系。
5. 仅读取目标 bpd-biz 正文块、来源 `02` 的同名节点块、相关资产候选块和本轮反馈区。

扩大读取范围仅在以下情况允许：

- bpd-biz 节点索引缺失或块 ID 无法定位。
- 与 `02` 的来源关系或 `23/24/25/27/28` 资产引用关系断裂。
- 业务域存在边界冲突、业务定义冲突或资产归属争议。
- 需要执行全局一致性检查或批量迁移。
- 人类明确要求通读全文。

禁止事项：

- 不得在常规 `biz01cr` 运行中默认全量读取正文节点块。
- 不得将旧版正文、废弃节点或未确认资产建议作为当前 bpd-biz 正式资产参与判断。
- 不得只凭对话上下文推进状态；人类反馈必须先写入节点反馈区、状态队列或转交记录。

## 3. 规则区 / 口径区

### 3.1 bpd-biz 节点口径

bpd-biz = **业务流程定义节点**（业务流程的定义，= `02` 概要 + 各级详细定义）。一个 bpd-biz 对应一个岗位级E2E业务，与 `02` 的同名节点 1:1，节点编号沿用 `02` 的。本文件只装**职责视角**——详细定义的落点是界面，界面只属 R 侧；P 侧内容（产品类型 / 构件类型 / WBS 包 / 认亲）在 `03-eos-business-product-process.md`。

### 3.2 schema 单源与判据落点

- **schema 单源**：本文件结构与节点类型 = [91 规范 §11](../10-pl4eos-subpl-sysdev/10-wfsysdev-4-eos/91-eos-biz-eng-spec.md#11-产品文档结构读写及反馈) + 本文件 + `02`（来源）自身；SKILL 指南只引用（93 §4.1）。
- **结构/领域判据**（正式/轻量、封面映射、引擎权威校验）引 91 §二；**覆盖检查** = "`02` 承接语义 ⊆ 本文件叶定义之并"（20 号 §4.5 本对实例，biz01cr §5.5）。
- 引擎权威值**落在本文件**（`biz01abr` 候选 `[推断]` → 本任务确认/修正/推翻），下游消费以此为准。
