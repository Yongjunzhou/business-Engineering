## AI读取文档说明

本文件是 业务概要 架构类树形资产文档。AI 读取本文件时应按需读取，不应默认读取全部正文。

默认读取顺序：

1. 读取文档元信息和本说明，确认文档用途、状态和读取规则。
2. 读取 `0. 业务概要树画像`，建立 bpl-biz、bpl-nfr、角色分片和节点规模的整体感知。
3. 读取 `1. 业务概要状态与处理队列`，确定本轮目标 业务概要 节点、活动锁、当前待办 ID 和下游选择记录。
4. 读取 `2. 业务概要节点索引 / 分片索引`，定位目标 业务概要 正文块、候选同角色节点块和必要追溯关系。
5. 仅读取目标 业务概要 正文块、追溯关系指向的 规范化的相关方需求 块，以及本轮需要写回的反馈区或建议区。

扩大读取范围仅在以下情况允许：

- 业务概要 节点索引缺失或块 ID 无法定位。
- 追溯关系断裂，无法判断 规范化的相关方需求 到 业务概要 的承接关系。
- 候选 业务概要 节点存在边界冲突、角色归属冲突或十链信息载体归属冲突。
- 需要执行全局一致性检查或批量迁移。
- 人类明确要求通读全文。

禁止事项：

- 不得在常规 `wft01a/wft01b/wft02a` 运行中默认全量读取正文节点块。
- 不得将旧版正文、废弃节点或历史归档作为当前 业务概要 资产参与判断。
- 不得只凭对话上下文推进状态；人类反馈必须先写入节点反馈区、状态队列或转交记录。

## 3. 规则区 / 口径区

### 3.1 bpl-biz 节点口径（新模型 2026-09-04）

bpl-biz 架构末级节点指代**场景业务**（业务流程概要节点）。每个 bpl-biz 节点对应一个主责角色的一个业务对象闭环（业务对象与主责角色一一对应，定义见 91 规范 §1.4；配合角色是闭环内的流程环节，不单独成 bpl-biz），在 `wft02` 阶段与其完整态 bpd-biz 形成 1:1 映射。

**概要形态（按 93 §三.3「概要—完整态边界」定案）**：业务流程概要 = 不含叶的树——场景业务 = 各级枝干（聚合层），**输出文档 = 枝梢节点（PL5，架构末级）**；PL6 活动/正文条目 = 完整态叶（04 由 wft02-biz 定义成叶），02 **不含叶**——PL6 名称只以枝梢**分解源判据展开项（预告）**出现（各带内联稳定标签作 02→04 追溯键），不占 02 树位。节点正文按 §4.1 模板组织：场景职责边界 + 业务链（文档序列枝梢）+ P 组装结论。

### 3.2 十链信息载体口径【退役 2026-09-04】

十类信息链是已废弃 `wft01a` 的分析框架（wft01a 已由 wft01-biz 取代）。原「场景部件分组 / 信息载体清单 / 场景指标清单」字段退役——场景指标落为业务链中的指标/看板文档枝梢（指标/看板文档 = 独立 PL5，与其他文档平权，见 wft01 §2.2 与 91 §二）。本文件 4.x 正文节点已按新模板迁移（2026-09-04）：bpl-biz-GOV-001 = 演示态（业务链较完整示范），GOV-002..009 = 真实态结构迁移（业务链待 wft01-biz 承接设计，不展开）。
