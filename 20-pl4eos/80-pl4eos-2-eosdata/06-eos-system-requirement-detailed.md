## AI读取文档说明

本文件是 系统需求概要类树形资产文档。AI 读取本文件时应按需读取，不应默认读取全部正文。

默认读取顺序：

1. 读取文档元信息和本说明，确认文档用途、状态和读取规则。
2. 读取 `0. 系统需求概要全貌`，建立详细定义规模、分片和状态概览。
3. 读取 `1. 系统需求框架详细定义状态与处理队列`，确定本轮待写回、待审阅或待修订的详细定义 ID。
4. 读取 `2. 系统需求框架详细定义索引 / 分片索引`，定位目标详细定义正文块。
5. 仅读取目标详细定义块、对应 `05` 系统需求框架架构块、对应 `07` pa-eng组件块和本轮反馈区。

扩大读取范围仅在以下情况允许：

- 详细定义索引缺失或块 ID 无法定位。
- 与 `05` 系统需求框架架构节点或 `07` pa-eng组件的追溯关系断裂。
- 同一 srl-eng 组件业务出现多个 pa-eng 承接候选或边界冲突。
- 需要执行全局一致性检查或批量迁移。
- 人类明确要求通读全文。

禁止事项：

- 不得在常规 Skill 运行中默认全量读取正文节点块。
- 不得将旧版正文或废弃详细条目作为当前详细定义参与判断。
- 不得只凭对话上下文推进状态；人类反馈必须先写入节点反馈区、状态队列或转交记录。

## 3. 规则区 / 口径区

### 3.1 详细定义写回口径

本文件为 **L4 详细档**（系统需求框架的详细定义），由消费 系统需求框架的下游 Skill 按路径分节写回：

- **§4.1 srb-biz 详细定义**——biz 链 `wft03-biz` 将 srb-biz 末级（功能表单）展开为字段级详细条目（功能表单/窗口标签页要素，见 wft03-biz §2.4/§5.5/§5.6）
- **§4.2 srl-eng 详细定义**——eng 链 `wft04-eng` 将 srb-eng 末级（功能表单）展开为区域内布局组件/构件 + 组件业务 + pa-eng 层收敛项标注

### 3.2 分配约束

- **srl-eng（§4.2）**：pa-eng 层收敛项（组件边界/接口/数据/运行/NFR）标注在组件业务条目中（wft04-eng 写回）；pa-eng 三类组件分配由 wft05-eng 依据 srl-eng 组件业务推断，不在此做「场景活动→pa-eng」分配
- **SysReq-NFR**：不在本文件进行详细分解，其指标定义在 `05-eos-system-requirement-summary-architecture.md` 的 SysReq-NFR 节点中维护
