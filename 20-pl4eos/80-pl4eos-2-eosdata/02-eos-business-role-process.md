**EOS Role-Perspective Business Process — Framework**

**文档版本**：v1.7
**创建日期**：2026-09-16
**用途**：承载业务流程的 **R 树**——职责视角（业务域 → 相关方角色 → 职责级业务 → 岗位级业务 → 文档级任务 → 任务节点 → 用例场景）。数据分解结构见 [94 号文档](../10-pl4eos-subpl-sysdev/10-wfsysdev-4-eos/94-eos-sys-dev-dbs.md) §2.2；节点 schema 见 [91 规范](../10-pl4eos-subpl-sysdev/10-wfsysdev-4-eos/91-eos-biz-eng-spec.md) §11。

## AI读取文档说明

本文件是树形资产文档。AI 读取时应按需读取，不默认读取全部正文。

默认读取顺序：

1. 读取文档元信息与本说明，确认文档用途、状态和读取规则。
2. 读取 `0. 职责视角业务流程树画像`，建立业务域、相关方角色、分片与节点规模的整体感知。
3. 读取 `1. 业务流程状态与处理队列`，确定本轮目标节点、活动锁、当前待办 ID 与下游选择记录。
4. 读取 `2. 业务流程节点索引 / 分片索引`，定位目标节点正文块、候选同角色节点块与必要追溯关系。
5. 仅读取目标节点正文块、追溯关系指向的相关方需求条目块，以及本轮需要写回的反馈区或建议区。

扩大读取范围仅在以下情况允许：

- 节点索引缺失或块 ID 无法定位。
- 追溯关系断裂，无法判断相关方需求条目到业务流程的承接关系。
- 候选节点存在边界冲突、角色归属冲突或属性的唯一性冲突。
- 需要执行全局一致性检查或批量迁移。
- 人类明确要求通读全文。

禁止事项：

- 不得在常规运行中默认全量读取正文节点块。
- 不得将旧版正文、废弃节点或历史归档作为当前资产参与判断。
- 不得只凭对话上下文推进状态；人类反馈必须先写入节点反馈区、状态队列或转交记录。

## 3. 规则区 / 口径区

### 3.1 bpd-biz 节点口径

- 一个节点 = **一个 E2E职责**，即一个端到端的职责业务，由一组有流转依赖的业务文档序列构成。
- 类型二分类：**执行类**——从接收需求到需求被确认得到满足；**管理类**——计划 → 监控 → 分析 → 纠正。
- 节点内的业务文档 = 本节点的 ⑤ 级；其下的任务节点（⑥、枝梢）与用例场景（⑦、叶）由相关方需求直接给出。
- **任务类型的启动规则**：E2E职责中第一个带任务类型的文档，其任务类型必然是**计划**——该 E2E职责的业务由这份计划启动（策划 → 发布）；文档本体仍是开发/记录类文档，不是计划清单。

### 3.2 schema 单源与判据落点

- 节点正文 schema 单源 = [91 规范](../10-pl4eos-subpl-sysdev/10-wfsysdev-4-eos/91-eos-biz-eng-spec.md) §11 + 本文件 §4.1 模板。
- 树形与级语义单源 = [94 号文档](../10-pl4eos-subpl-sysdev/10-wfsysdev-4-eos/94-eos-sys-dev-dbs.md) §2.2。
- 正式 / 轻量的封面判定见 91 规范 §2.1。
- 产品数据即资产；R 树与 P 树即资产，不另立资产文件。
