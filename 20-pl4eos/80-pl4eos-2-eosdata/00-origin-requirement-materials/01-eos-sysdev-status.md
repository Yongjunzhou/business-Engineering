# EOS 规范化的相关方需求预处理状态文档

**用途**：规范化的相关方需求预处理链（`or00-textualize` / `or01-chunk` / `or02-clarify` / `or03-norm`）的状态追踪共享接口。AI 通过此表感知原始材料、文本化文档、需求文档的处理状态；人类通过此表做预处理阶段的批量决策。

**HEAD @上次AI运行**：`{commit-hash}`（AI 每轮 `.scripts/ai-commit.sh` 提交基线后更新；各步 Step 1 以 `git diff <该 hash>` 检出人类变更，`git log --author="EOS-AI" -1` 校验兜底）

**权威源契约**：

1. 本表只管理 规范化的相关方需求预处理阶段的状态：表 A（原始材料）、表 B（需求文档）。
2. `wft01/02/03/04/05` 不以本表管理 业务框架 / 业务方案 / 系统需求框架 / 产品框架 状态；这些状态以对应产品文档管理区为权威源。
3. `wft01/02/03/04/05` 若生成补充原始需求材料，只登记到表 A，生命周期为 `已登记`，后续仍由 `or00~or03` 进入预处理链。

**同步契约**：

1. 规范化的相关方需求预处理链写入顺序：先更新本表 A/B，再更新对应原料、文本化、切分或规范化文件。
2. 设计链写入顺序：直接更新对应产品文档管理区；本表不派生、不同步 业务框架 / 业务方案 / 系统需求框架 / 产品框架 状态。
3. 本表不承载设计正文，只承载 规范化的相关方需求预处理状态、选材和批量决策信息。
4. AI 每次运行结束更新表头 `**HEAD @上次AI运行**` 为本次 ai-commit 基线 hash（供 Step 1 以 `git diff` 检出人类变更）；人类无需维护该字段。
5. 生命周期转迁时，AI 更新 `AI建议` 为针对新阶段的前视建议，同时清空 `人类决策`，等待人类针对新建议重新决策——表 A、表 B 同此。

### 表B — 需求文档处理进度

| 源文件 | 子文件 | 内容摘要 | 生命周期 | AI建议 | 人类决策 | 处置标记 | unresolved_count | 操作指引 | 最后更新 |
|--------|--------|---------|---------|-------|---------|---------|----------|----------------|-----------------|---------|---------|

**粒度**：一行/需求文档（`.chunk-{seq}.md`），追踪从切分创建到规范化完成的预处理全生命周期。

**生命周期取值**：

```
已切分 → 澄清中 → 已澄清 → 规范化方案待确认 → 已规范化 → 已废弃
```

| 阶段 | 说明 | 管理步骤 |
|------|------|---------|
| 已切分 | 切分执行完成 | or01 完成 |
| 澄清中 | 问题清单不空，等相关方答复 | or02 迭代中 |
| 已澄清 | 复核后清单空，澄清完成 | or02 完成 |
| 规范化方案待确认 | AI 已给出规范化方案，等待人类确认 | or03 等待反馈 |
| 已规范化 | 规范化完成，规范化的相关方需求条目已写入基线 | or03 完成 |
| 已废弃 | 子文件不再处理 | 任何步骤 |

**AI建议取值**：可以澄清 / 需继续澄清 / 可以规范化 / 建议执行 / 已完成 / 建议终止

**控制流**：
- 人类设 `人类决策=同意澄清` → or02 选材入澄清
- 人类设 `人类决策=同意规范化` → or03 选材入规范化
- 人类设 `人类决策=已终止` → 废弃处理

**字段说明**：

| 字段 | 写入者 | 说明 |
|------|--------|------|
| 源文件 | or01 | 所属原始材料文件名 |
| 子文件 | or01 | 需求文档路径（`.chunk-{seq}.md`） |
| 内容摘要 | 各步更新 | 该子文件核心内容一句话摘要 |
| 生命周期 | 各步转迁 | 见上方生命周期取值 |
| AI建议 | 各步更新 | 对当前阶段的前视建议（如"可以澄清""可以规范化"）；纯提示，不作入口硬门槛 |
| 人类决策 | 人类 | 空（未处理）/ 同意澄清 / 同意规范化 / 需退回澄清（下游退回重题）/ 已终止 |
| 处置标记 | 各步更新 | 叠加标记，不占生命周期；空 / `待处置`（检出、待裁决的问题）/ `待人工处置`（文档缺陷、处置权不在本步）/ `待退回重切`（下游检出需求侧缺陷、要求重切——由下游写在**该缺陷所锚的切分片**这一行） |
| unresolved_count | or02 | 当前澄清问题清单的条数 |
| 操作指引 | 各步更新 | 人类下一步应执行的操作 |
| 最后更新 | 各步更新 | 格式 YYYY-MM-DD |
