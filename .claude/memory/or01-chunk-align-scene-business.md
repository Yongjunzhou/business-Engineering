> **⚠ 口径已被 [[or01-chunk-rewrite]] 取代（2026-10-08）**：切分口径从「业务对象闭环 ∪ 系统级非功能约束」改为「功能性需求按业务输出文档、非功能需求按适用对象 × 主题」。本件只作沿革。


or01 语义切分（人类方案 v0.33 起）以「单个主责角色的单个业务对象闭环」为主要判断标准，对齐 91 §1.4 业务对象概念：**一个场景业务 = 一个业务对象闭环 = 一个主责角色的端到端职责闭环**（需求提出 → 满足 → 确认）。

**业务对象** = 场景业务全部操作与输出文档所围绕的核心实体（91 §1.4 权威定义），与主责角色一一对应；配合角色（审批/审核/协作）是闭环内流程环节，不产生独立场景业务。**确定三步法**：候选对象提取（输出文档为识别抓手）→ 独立生命周期三问 → 主轴锚定。业务对象有层级（产品 → 构件 → 构件数据文档），大端到端含小端到端——取级随材料自然描述（完整闭环成片 / 仅含部分环节的归入大闭环 / 子对象独立管理升格成片），完整闭合为成片底线、可独立设计（wft01 STR-F 承接）为切分上限。

**v0.55 候选单元扩展（NFR 纳入切分）**：候选单元 = 业务对象闭环 ∪ **系统级非功能约束**（适用对象为业务域/平台能力/全局对象的性能/安全/合规等约束）；附着于某业务对象闭环（STR-F 场景）的 NFR 随场景成片、不单独成候选。识别第 4 步判**适用对象线索**（取值对齐 [91 §九 STR-NFR 归组四元组]：STR-F 场景 / 业务域 / 平台能力 / 全局对象；FR-ENG/STR-E 留同构扩展），仅结构识别（定文本归属）、不判分类维度（@nfr-xxx 由 or03 判定）。命名：系统级非功能约束片按主题锚点。

**Why:** 语义切分是业务识别的第一步。切分片按"业务对象闭环"界定后，天然对齐 wft01-biz 的 STR-F 场景业务与平台运行时 M4 菜单（业务对象工作台）——预处理链与设计链在「业务对象」概念上打通。此前"相关方 × 场景"会把配合角色误计入候选，v0.33 改为主责角色标识后消除该失真。NFR 无业务对象闭环，v0.55 纳入系统级 NFR 片，否则系统级 NFR 会被误并入无关场景。

**How to apply:** 判定"切不切"时：数"业务对象闭环（由主责角色标识）+ 系统级非功能约束" = 候选单元；识别抓手 = 数输出文档归并到业务对象（主轴）+ 扫质量属性词判适用对象线索。仅识别业务对象/主责角色/适用对象线索作边界，不评价需求内容（详概分离）。业务对象概念权威定义在 91 §1.4，STR-NFR 归组四元组在 91 §九。人类方案 v0.55 / SKILL v2.37 已落地。衔接 [[or03-normalization-connotation]] NFR 链。
