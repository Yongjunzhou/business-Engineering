**人类 2026-09-17 定**：「第二章应该只是输入文档的结构及各级语义」「对输入文档的检验或校验等，以及对输出文档的校验等，都应该放在第五章中」。据此改一份规范、一处树权威、三份试点，已提交并推两仓（`55783d15` `[AOS]`、`12cd06c4` `[AOS-记忆]`）。

## 判据：看主语是谁

- **主语是 X** 的判据（属性齐不齐、归得到同一个业务对象吗、状态对不对、一次收多少）→ **第二章**（只作 X 的描述，不写动作）。
- **主语是本任务的产出** 的判据（要素齐了吗、覆盖住了吗、兄弟互斥吗）→ **第五章**。
- 两者都落在第五章：**入口检验（对 X）** 与 **关口（对 Y）** 两组并列，出三个不同的口——退出／退回／挂起。
- 配套理由：校验由「条件→判定→动作」三段构成，动作只在执行时有意义；且 93 对承接早有同样分工——承接规则立第四章、单承接检查归第五章，规则与检查不混。
- **"退回"两向不重复**：X 有缺陷 → 退回给 X 的上游；Y 被下游挑出 → 本任务修订。两个方向各写去向。

## 第二章收窄后的形态

`## 二、输入文档结构及规则`（章标题即 93 §2.1 骨架名，**不加括注**）＋ 章首一行认定句「输入文档（X） = …，为需求-方案对的需求侧文档。」

- **2.1 X 的树形结构与各级语义**——树块＋级语义表（级｜节点｜意义｜怎么得到｜本任务如何处置）＋出处句（树权威 94 ＋ schema 91 §11 ＋ 数据文件自身）。
- **2.2 X 的树形结构规则**——那些不进节点定义的结构性规矩（属性随节点携带不占级位、同一对象可对应多条上游需求、末三级与下游同批、X 在现行数据文件里的落位与由此而来的读法）。章名里的"及规则"就是这一节。

## 第二章与第三章的不对称是对的

**Y 是本任务造的，所以第三章有要素清单与传出承诺**（得说它该长什么样）；**X 不是我们造的**，只能如实描述它长什么样、加一份验收条件，而验收条件归第五章。故第三章不动。

## 下一开工点（人类 2026-09-17 定）

**到另一台电脑上修订 biz01abr 的第三章（输出文档结构及规则），按本轮同一套方式**：先逐条发现问题（对 93 §3.3 应含 ＋ §2.4 十条写法 ＋ 91／94 权威源逐年核），列清单交人类裁，再落笔——93 与三份试点同步改。

开工前已知的裁点（第三章）：

1. **要素清单与传出承诺的去留**——按"Y 是我们造的"这条理由，两者都该留在第三章；但**传出承诺是接口契约的另一半**（§4.2 的 A 侧），动它牵动整个装置，须人类点头。
2. **第三章的级语义表也有「意义」列**，与树块逐字重复（规则十）——与第二章那条同源，两章宜一并裁。
3. **第二章收窄后的对称性**：§3.1 产出的产品数据／§3.2 Y 树／§3.3 节点类型与结构要点／§3.4 Y 侧规则／§3.5 要素清单／§3.6 传出承诺 六节，哪些是"Y 是什么"、哪些其实是执行动作而该挪走（按第二章那把尺子重量一遍）。
