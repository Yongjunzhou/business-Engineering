**SR/业务树（分类视角）与功能表单（页面视角）是两个正交视图**（人类定 2026-09-10）：

- **分类视角**：树的 ③ 系统用例功能类——一个系统用例功能只归一 类（**单归属**）。
- **页面视角**：**功能表单 = 多个系统用例功能的集合**——同一系统用例功能可按需出现在多张功能表单上（**多归属**）。
- **对应关系（树节点 ↔ 页面单元）**：
  - **功能表单 ↔ 业务树 ⑤ 业务输出文档（枝梢）下的任务步骤**（R 树／P 树，[94 §2.2](20-pl4eos/10-pl4eos-subpd-sysdev/10-wfsysdev-4-eos/94-eos-sys-dev-dbs.md)）——任务步骤是该文档的**分解源判据展开项**，不占树位（一个文档 0 或 1 个任务）。**注（v1.13/v1.14 校正）**：原记作"↔ A2/Bn ⑥ 任务节点"；94 v1.13 把末两级并作一级（⑤ 业务输出文档＝枝梢 / ⑥ 活动节点·正文条目＝叶），v1.14 又把树名改为 R 树／P 树（旧称 A2/Bn/A1 作废）。
  - **A1 的 配置信息组 ↔ 功能表单中的一个"配置信息组区"**（即 CU 配置页面上的一个区）

**SR 树的级**（人类定 2026-09-10）：**枝梢＝⑤ 用例场景功能、叶＝⑥ IPO功能**（叶只在完整态——"系统接收某组字段的值 → 处理 → 给出响应"）。**功能表单不属于 SR 树**。

**Why**：此前 91 / wft03 / 06 把"功能表单"当作 SR 树的末级节点——那是**视角错位**（把页面视角的聚合物写进了分类视角的树），不是层级错误。已退役的 92 曾以"功能表单不是节点"察觉到此，但当时没有"两个视角"这个命名。

**How to apply**：写/审 SR 树（05、06、wft03、91 §7~§9）时，末级一律用 ⑤/⑥ 的需求语义名；功能表单只出现在"业务侧载体"的位置。91 已按此改 **v5.54**（十一处 + 总锚注）。93 框架/完整态派生：wft03（框架）末级＝⑤、wft04（完整态）末级＝⑥。

**未决**：A1（v1.14 起称 P₀）树是否还有"用例场景类操作"一层（决定配置信息组是**枝梢**还是**末级**）——91 现说"无 PL6、末级＝配置信息组"，94 §2.2.3 说"⑥ 配置信息组（枝梢）→ ⑦ 用例场景类操作（叶）"（v1.13 加【待裁】注；v1.14 归族后判据已备，删 ④WBS 与 ⑦叶即对齐 91）。
