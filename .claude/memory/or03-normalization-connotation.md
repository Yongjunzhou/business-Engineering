2026-08-17 新会话重点讨论 or03「规范化」概念层——拆分规则与质量规则已落定（v0.40~v0.44），开放项逐一处理。

**已定案（or03 人类方案 v0.41 基础 + v0.42~v0.44 开放项处理）**：
1. **类型先行、按类型分治**——先判 FR-BIZ/FR-ENG/NFR，再按各类型边界拆分：
   - FR-BIZ：**场景为锚、一场景可多条 OR**——场景需求可能被多个用户分别提出，成条依据 = 提出者 × 单一可确认性；**取消「能力单元」中间层**（因"能力"太抽象放弃，也避免场景内强制细分），场景内不设中间单元
   - FR-ENG：对一个平台引擎的一项能力诉求（25 资产锚定）
   - NFR：**四元组原子**——单一关注角色 × 单一分类维度（22 @nfr-xxx）× 单一适用对象线索，对齐 [91 §九 STR-NFR 归组四元组]
2. **资产判定只到 23 输出产品及其部件**（产品类型/组部件 Q1/Q2/Q3）——不再匹配 26 文档（输出文档在 STR 层由 wft01 确定）；22 从"候选线索"升级为"NFR 分类维度判定"（判 @nfr-xxx，无匹配标候选待写，**不写回 22**）
3. **五项标准按类型解读**（§2.2）：NFR 边界可判定 = 数值+单位+条件（应已在 or02 澄清中由相关方确认，缺则标 `待确认` 退回 or02）、可测试性 = 目标值可验证，统计口径/测量方法/验收条件由 wft04-nfr 展开
4. **NFR 链全链贯通**：or01 v0.55 识别 NFR 适用对象线索（文本归属）；or02 v0.27 澄清 NFR 目标值+属性/适用对象（缺少定量指标第六子类型，废除不量化）；or03 v0.45 判四元组 + 完整性检查（缺则待确认退回）；wft01-nfr v5.3 归组记录相关方确认的目标值；wft04-nfr v5.3 承接目标值做系统侧指标设计
