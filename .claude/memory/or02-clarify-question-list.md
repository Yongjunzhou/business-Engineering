2026-08-17 人类讨论定案（三轮）：or02（澄清步骤）的 AI 建议形态 = 生成「向相关方澄清的问题」，处理框架对齐 or01；v0.23 补 NFR 质量诉求澄清扩展；2026-08-18 v0.27 定案「缺少定量指标」第六子类型 + NFR 定量指标在本步澄清（锚定通用设计规范 §1.2 需求=需求描述+性能指标）。

**核心设计（v0.20 问题清单 + v0.21 框架对齐 + v0.23 NFR 澄清扩展 + v0.27 缺指标子类型）**：
1. 标注格式 `[⨯子类型: 原文→问题：<问句>]`——AI 对每处模糊生成可问相关方的问句；报告含「待向相关方确认的问题清单」
2. 反馈双通道 + 记录机制（v0.21 对齐 or01）：
   - 线下：开发者持问题清单向相关方澄清，写 `[✓已澄清: <相关方确认内容>]` → Step 1 状态扫描检出 → 登记表 B 内容摘要（`反馈：澄清（<文件>）`，查重幂等）→ Step 2 处理追 `[已处理]`
   - 对话：Step 5 收集流程指示/澄清答案（只记录不处理）→ Step 6「汇总」落表 B 内容摘要 + 提交基线；对话澄清答案由 AI 代写 `[✓已澄清]` 到正文区（内容来自对话确认）
3. Step 布局 5→7 步（对齐 or01）：Start / 1 反馈检测与汇总 / 2 反馈处理 / 3 新增处理 / 4 提交基线 / 5 反馈交互（对话）/ 6 变更汇总（口令）/ End
4. 「记录 + [已处理]」显式分界解决多次运行/中断恢复（状态自终止无显式分界，多次运行有重复处理风险）
5. **缺少定量指标第六子类型（v0.27，锚定 [通用设计规范 §1.2] 需求=需求描述+性能指标，不可衡量则不成为需求）**：任何需求（FR/NFR）缺"性能指标"中的定量指标部分都是模糊——FR 缺指标（如批量导入缺单次上限）与 NFR 缺指标（如实时响应缺目标值）同构适用，AI 均向相关方要 数值+单位+条件。**NFR 分支废除 `[⨯质量诉求]` 不量化路由**——改标 `[⨯缺少定量指标]`，额外澄清质量属性准确表述（喂 or03 分类维度）/适用对象（哪个场景/流程/系统整体，喂 or03 适用对象线索）/关注角色（必要时）；目标值由相关方确认，系统侧指标设计（统计口径/测量方法/验收条件）由 wft04-nfr 展开
6. 三项条件「正文清晰完整」= 内容来自相关方确认；AI 生成的问题不构成已澄清；缺少定量指标需相关方确认目标值后才算已澄清（§3.5 尾注：系统侧设计 wft04-nfr 不遗留）
7. 六种子类型：术语模糊 / 主体客体不明 / 边界模糊 / **缺少定量指标** / 信息缺失 / 多重模糊（§2.1/§3.4 定义单源，锚 §1.2）

**Why:** AI 建议的价值在「帮人类知道该问什么」，不在「替人类补答案」——AI 注入业务/指标内容会污染 OR 基线原始性、确认主体错位（开发替业务脑补）、且在 or02 阶段缺信息锚点。指标数值不是 AI 发明的，是相关方经澄清确认的（需求=需求描述+性能指标，通用设计规范 §1.2）。与 wft01a「提问清单 + 业务人员确认收敛」模型同构 [[wft01a-redesign-multi-or-convergence]]。

**How to apply:** or02 人类方案 v0.27 / SKILL v2.12 已落地（v0.22 新增 §二「澄清核心概念与分工」；v0.27 六种子类型 + NFR 目标值本步澄清）。链级已同步：or03 v0.45/v2.13（NFR 定量指标在澄清确认，本步只完整性检查）、91 v5.18、wft01-nfr v5.3、wft04-nfr v5.3（承接已确认目标值做系统侧设计）。后续审视按此口径——AI 只出问题、不进内容；缺少定量指标 FR/NFR 同构澄清目标值；反馈走记录 + [已处理]；处理框架与 or01 同构。
