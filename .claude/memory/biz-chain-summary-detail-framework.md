2026-08-21（本会话）**biz 链分工「框架/详细」重述框架定案**。用户提议 + 四问逐一裁决，全部收敛：

**框架（最终形态）**：
- s01：规范化需求 → **业务框架定义**，末级节点 = **文档**（+ 详细需求 + 框架说明）
- s02：业务框架定义 → **业务详细定义**，详细条目 = **活动**（+ 正文条目 + 表单使用顺序）
- s03：业务详细定义 → **系统框架定义**，末级节点 = **功能表单**（+ 详细需求 + 框架说明）

**树的读法**（一棵树，A2/Bn 不是两条树）：
```
[A2 归纳枝] SL3 角色类型 → SL4 角色职责 ──┐
                                        ├→ 场景业务(SL5) → 文档(PL5) → 活动(PL6-A)/正文条目(PL6-B)/表单使用顺序 → 功能表单
[Bn 归纳枝] PL3 构件类型 → PL4 WBS ──────┘
   s01 枝      s01 末级             s02 内容                s03 末级
```

**四问裁决**：
- **① 文档详细需求粒度**：s01 框架说明 = **结构判定级**（wft01 §3.3 现状：名称/用途/封面模式/候选引擎/开发方式/任务层/条目层三独立），**字段级留 s02**（DocumentCover 映射/正文实体字段集——wft02 §5.5.2）；「文档为框架末梢、场景业务降为枝」作叙述采纳、**资产锚不动**（02 STR-F 节点=场景业务保留，追溯/23/26 不迁）；通用规范「BP 无详细定义」（§1.3 特例/§1.4/§3.4.1）以「BP IPO 承担详细角色→命名业务详细定义」叙述兼容，不破规范。
- **② PL6-B 归属**：**维持三级接力**——s01 存在性判定（三独立预判）+名称级捕获（wft01 §2.2.2/§3.3.6）/ s02 定义要素+生命周期（wft02 §5.5.7）/ s03 按资产权威源转化（wft03 §2.5，指标/看板→28、风险/问题/行动项/计划→26）；s02 条目**泛化为「活动与正文条目」**（PL6-A「怎么做」与 PL6-B「有什么」是文档子节点正交两维）。
- **③ A2/Bn 双视角**：**A2 不是第二条树**——角色层级 SL3/4（与 PL3/4 同性质「归纳层，可选占级」）归 s01 结构；表单使用顺序归 s02 内容（wft02 §2.2.2「BP 只定义场景边界和表单使用顺序」）；页面编排归 s03 系统。**Bn 组装执行上移 s01**（唯一真改 Skill 边界）：WBS 归组（wft02 §5.5.1②）+ 23 一致性（§5.5.1③）+ 缺口推断（§5.5.5）+ 结构性缺口 OR 回路（复用 wft01 现有 Step 4 业务需求增补）入 wft01；wft02 收缩纯详细层（引擎校验/文档方案/活动/正文条目/使用顺序/权限/任务关系）。缺口判断 = **构件的产品数据清单完整性**（名称级资产比对，**不依赖任务类型/引擎**）——比「按 WBS 推断缺口」更干净。
- **④ 横切工作**：**引擎/任务类型权威留 s02**（现状终审，基于活动设计上下文——wft02 §3.2「完整处理模式只有 BP 展开后才看清」；s01 候选引擎容忍 + wft02 §5.5.1③ 复核 + Phase B 对齐兜底，校验结论不回写 STR-F）；权限 s02 数据/s03 表单（不动）；缺口回路结构性→s01 设计性→s02（不动）；资产写回各层自己的（23B/26→s01、24/27→s02、28/FR-ENG→s03）。

**总方向**：概念确认 + 叙述为主；**唯一真边界变更 = Bn 组装执行上移 s01**（③）。涉及 Skill 文档：wft01 增 Bn 组装步骤（WBS/23 一致性/缺口推断/结构性 OR）、wft02 收缩（§5.5.1②③/§5.5.5 迁出）；wft03 §3.1「引擎权威在 BP 校验值」引用**保留**（权威未迁）。**91 规范可能有旧内容，Skill 文档为活依据。**
