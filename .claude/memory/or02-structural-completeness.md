2026-08-18 人类裁定「应考虑是否必要，而非是否复杂」后定案：or02 新增**结构完整性扫描**。必要性 = 不追加则三类结构缺口（分支缺对应面/闭环缺端/引用对象缺失）会带「已澄清→可规范化」认证穿过整条预处理链——or03 单条级完整性门禁看不见跨片/跨条件缺口；且与「缺少定量指标」（v0.27，结构预期）同族，方法论自洽。复杂度不否决必要性。

**设计要点**：
- **定位**：独立于六种模糊子类型的第二类澄清对象（非第七种子类型）——六类 = spot 锚定的表述不清；完整性 = 文本结构整体缺席，证据规则不同，故不混入六类表（功能理由，非复杂度理由）
- **证据规则（§2.5 标注纪律 6）**：只在文本自证缺口时发问，标 `[⨯完整性: 原文/对象→问题：<问句>]`——①分支缺对应面（写了「当X时/正常情况」缺对应面，排除上下文明显推出）；②闭环缺端（明确描述业务对象闭环多环节但缺提出/处理/确认一端，对齐 or01 完整闭环 [91 §1.4]）；③引用对象缺失（文内引用的实体/流程/文档在全切分文件集无定义）
- **不标边界**：模板式业务覆盖猜测（「该需求是否还应包含X功能」）归需求开发职责，AI 不做（同纪律 1 只出题）
- **判定联动**：三项条件条件①吸收「完整性缺项经相关方确认补齐」；条件③「无新增模糊」含完整性；**Step 3 无六类模糊但完整性有缺项 → 仍进澄清中**（行为变化，非文字变化）
- **落地**：or02 人类方案 v0.34 / SKILL v2.19；链级 or03 v0.58 / v2.26（§2.4 五项标准「完整性」口径注——结构完整性已在 or02 检知，本步聚焦 OR 条目表达完整）；README 各步对照表 + pl4eos 规范 §15.7 对照表 or02 列同步

**Why:** 结构完整性缺口在预处理链末段不可见（or03 逐条检查看不全跨片/跨条件缺口），晚爆于 wft03 覆盖业务阶段，成本高；or02 是规范化前相关方仍握着业务事实的最便宜发问点。

**How to apply:** or02 执行结构完整性扫描时严格按三形态证据规则，禁止模板式业务覆盖猜测；新会话修订 or02/or03 时保持「六种模糊子类型 + 结构完整性」两类澄清对象口径，勿把完整性并入六类表。相关：[[or02-clarify-question-list]] [[requirement-definition-authoritative]] [[or03-normalization-connotation]] [[or02-03-readability-revision-plan]]
