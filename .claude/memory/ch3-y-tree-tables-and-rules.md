## 一、级语义表：两章反向收

- **输入侧（第二章）**：产出者对整棵树是同一个（本链两步都是），**写在树图之前的正文里说一次**，表列 `级｜节点｜本任务如何处置`——「怎么得到」整列不设。
- **输出侧（第三章）**：表列 `级｜节点｜怎么得到`；逐行取四种来源（承袭／本任务产出／AI 建议+人类确认／目标组织级）；**「本任务如何处置」并入同格**——处置与该级的来历同属"本任务造 Y"这一件事，分两列反而把它劈开。
- **两章都不设「意义」列**——意义随树图（规则十点名"树形结构图"是不复述处）。原「输入侧填它在链上的产出者，如"预处理链产出"」作废。

判据：**列留着不留着，看它有没有行间差异**。一个对整棵树都成立的常量不占列，进正文。

## 二、树图：与 X 同指的末三级只作指认

输出树的末三级若与 X 同指（即"叶由上游直接给出的步"），**注只写「同 X 树的同名节点」**，不重述它们是什么——它们是什么，第二章的树已说过。

## 三、Y 侧规则只收两样

93 §3.3 的「Y 侧规则」= **构建规则**（父节点归组、收敛自查）＋ **形态边界**（交出哪个形态、写到什么深度）。越界的一律归位或删：

- 转换规则（如 cr 的「任务关系引擎化」）→ 第四章；关口（如 cr 的「覆盖自查」）→ 第五章。
- **「叶的独立判定」「不设承接判据」「分解源判据」三条，对"叶由上游直接给出的步"整项不设**——本步既不承接也不分解，槽位本应为空；写进去只能是权威正文（94 §1.3／93 §3.3）的搬运。93 §3.3 的两项应含已按此改写。
- 形态边界写成**按级列**（业务文档／任务节点／用例场景），深化项按**同一顺序**与浅化项对上（封面模式→封面映射、正文实体类型→正文实体结构、支撑引擎候选→引擎权威值）；「结构判定」就地白话一句（判它在树上存在与否、落在哪一级）。

## 四、abr 的 ⑤⑥⑦ 是「本任务产出」

> **本条已被后续轮次有意覆盖（2026-09-22 核）**：abr 表3-2 ⑤⑥⑦ 的来历在 **2026-09-20**（`7d0aa845`，abr 第 73~75 版）由「本任务产出」**翻回「承袭」**，提交信息写明理由——「按 93 §3.3 四来源；**改后该列不再整列常量**」。实质亦合：94 §1.4 明写 `01 → 02`「**整段搬入、无映射**」；abr §1.2「本任务不产出它们」与 §3.1 注「X 给出这批节点，由本任务把它们归并成树」同此。**不要按本条再去改 abr。**

级语义表七行一律「本任务产出」：①②④ 取自 X 的属性、③ 随概要演进（AI 给 E2E职责聚类方案、人类反馈或确认）、**⑤ 或合并或新建、⑥⑦ 逐节点定复用 → 改进 → 新增**。地址锚逐级加长：④ 域·角色 → ⑤ 加 E2E职责 → ⑥ 该业务文档 → ⑦ 该任务节点。原「承袭」与 §5.1.3 的"合并／新建、复用→改进→新增"阶梯相抵。

连带已落：§1.3 条 1 的节点清单加「角色职责」；§5.1.3「节点落定之后」加一档「角色职责随 E2E职责集合重聚类」；§7.2 自检加「角色职责的重聚类已交人类确认」。**该节引块改名「末三级与 X 同指，实体归 Y」**——X 给节点，归并成树由本任务做。（`abp`／`cr` 的末三级确为整段取用，仍写「承袭」，不动。）

## 五、命名与判据（同轮）

- 要素名统一 **「业务文档实现方式」**（cr 原「业务文档方案」、04 原「输出文档方案」）。
- **94 §2.2.1 ③④ 与 §2.2.3 ③**：③＝角色承担的职责清单，是多个 E2E职责的聚类；④＝一个端到端的职责业务，分执行类（从接收需求到需求被确认得到满足）与管理类（PCA）。**「业务对象闭环」仍是概念名**（家 91 §1.4、or01 切分口径、94 §2.0.2），**只换注不换名**。
- 任务类型启动规则去掉自造的「闭环启动机制」，补回 91 R4 的本体澄清（本体是开发/记录类文档，非计划清单）。
- 封面判定给出判据本体（审批流转／版本追溯／派发验收／独立状态变迁），不再挂指针；93 §4.1「结构/领域判据」一行同改。
- **93 §2.4 规则七补半句**：给规则作结的短句里，也不许出现权威里没有的名词（病根是「这是闭环启动机制」）。
- 删 `abp`／`cr` 的 §6.3「判定动作」与「要素不在本清单」注。
