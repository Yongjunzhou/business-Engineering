**人类 2026-09-28 定**：三份试点报告内，级名一族给简称；**每份报告首次出现处写「全称（简称：X）」，其后用简称**。

|------|------|:---:|:---:|:--:|
| 文档级E2E任务 | **文档级任务** | ✓ | ✓ | ✓ |
| 岗位级E2E业务 | **岗位级业务** | ✓ | ✓ | ✓ |

| 构件级E2E业务 | **构件级业务** | — | ✓ | — |

abr／cr 里产品级、构件级两级**只出现在 `所属产品级E2E业务`／`所属构件级E2E业务` 两个字段名中**，字段名保留原值，故这两份不启用、也不定义。

## 只砍「E2E」、保留「级」——不取「岗位业务／职责业务／产品业务」

人类原提后者，我改在「级」上留一个字，理由是四个坑：

1. **职责业务＝R 树根节点的本名**（2026-09-17「角色履职业务」更名而来；活在三份试点的树图根行与 94 §2.2.1／§2.2.3）。取同名会使根与 ③ 同级两名。
2. **文档任务＝末三级的合称**（cr §5.2 就地定义，abr／94 同句沿用）。⑤ 的简称取同形会与它一字之差——现取「文档级任务」，差一个「级」。
3. **构件业务＝业务资产 L3 的现名**（`01-pl4eos-spec`）。「产品级业务」又紧邻「产品数据」（abp 里两者 35／48 处且同段）。
4. **94 有意让「X级E2E业务」＝端到端业务、「X业务」（WBS业务／配置单元业务／配置信息组业务）＝非端到端作业单元与配置实体**，靠收尾方式标出这条缝（见 [[chain-level-name-family]]）。简称把两端收成同形，缝就没了。

保留「级」还有一条方法上的好处：**简称放进任何一段都读得懂**（「岗位级业务」），不生造词，与 93 §2.4「每一段都要自洽」不冲突。

## 全篇只留两处全称

**字段名 `所属X级E2E业务`**（93 §2.4 规则四：字段名保留原值——它是要写进产品数据文件的字面量）与**每个词唯一的那处首现定义**。除此之外全篇用简称——**树图、图里的连线标签、级语义表与级对应表的级名格、表题、表身的说明格，一律缩**。

人类 2026-09-28 收紧：「**每份报告中应该只出现一次**」。三份实测（非字段名的全称只应剩定义那一处）：abr 全称 16＝字段名 13＋定义 3；abp 29＝24＋5；cr 6＝3＋3，**其他残留为零**。

**前一轮为什么是半拉子**：初版用「整行豁免」——某行只要有格是级名，整行不动。后果是同一张表的意义列，带级名的行留全称、不带的行缩（表2-1 的 ③④⑤ 行全称、⑥⑦ 行简称），读起来像没落实。改为**只豁免字段名**后，级名列与说明列各按各的缩，列内一致。

**两处代价，知情接受**：① abr／cr 的 §1.2 链上坐标图里那条连线标签（「同一批文档级任务」）落在定义之前——**简称先于定义出现**，因为该词的首现在图里，而定义只能落在不在代码块里的头一处（把括注塞进连线标签更难看）；② 树图与级语义表不再与 94 的图2-4~2-7／表2-5~2-8 逐字同形，靠首现的括号注对上。

## 两处例外

- **abp 的「职责级E2E业务」不给简称**：全篇只剩一处非正位出现，定义一处、只用一处，不如不定义（规则：非正位出现 ≥2 次才启用）。
- **cr §5.2 补两字**：「本步做三级——用例场景、任务节点、文档级任务，**三级**合称文档任务」——「文档级任务／文档任务」一字之差，补「三级」拆开。

## 依据与登记

简称**不必登记进 94**——93 §2.4 规则七自己就写着「术语按本名写全，**缩写首次出现给全称、其后可用**」，与人类这回给的写法是同一件事。

## 文件头「命名约定」行同轮改掉

三份文件头的第 6 行原写「**本文件内不设任务代号与文档编号简称**——文档一律称其本名，如…；相邻任务按链上位置称呼，如…」。这行**全仓只此三处**，93 §2.5 五 只规定前言块含哪四行、不管内容，故属试点自留地。两处改由：**缺项**——93 §2.4 规则二把文件头定为这份文件里谈命名的唯一一处（正文不许重复它），而最显眼的新约定不在其中；**否定句式**——读者断在破折号前会读成"本文件不设简称"，而正文三行后就出现「（简称：…）」。

改后（三份同式，举例各异）：

> **命名约定**：文档写本名，不写任务代号或文档编号，如……；相邻任务按链上位置称呼，如……；**带「级」的节点名首次出现给全称与简称，其后用简称**。

末一句**不带举例**——原先写的是「（如「岗位级E2E业务」）」，与「每份报告只出现一次」相抵（那会成为 岗位级E2E业务 的第二次出现），故括注撤掉。抓手取「带「级」的节点名」——R／P 两树里带「级」的节点名正好是那五个（业务域、相关方角色、任务节点、用例场景、WBS业务都不带）。用词取「**节点名**」而非「级名」：后者在 91／94 里查不到（91 只有「层级名称」、94 只有「下一级名」），按 93 §2.4 规则七的判据属自造；「节点名」是 91／93／94 三家都在用的词，93 规则四的表里也正是这么写的。「首次出现给全称」照抄 93 规则四原话。「节点名」一词顺带担了过滤——`所属产品级E2E业务` 是属性名不是节点名，故 abr／cr 不启用产品级、构件级简称这件事，这行不构成变相承诺。

**暂不动 93**：[[eos-pilot-authority]] 定「以 biz01abr 为权威，93 和 94 要与之对齐」，先立 93 把顺序倒了；且这条做法只跑了一轮。要铺到 eng／nfr 链那几份指南时（它们的文件头也各有同样四行、都还没有这一条），再在 93 §2.5 五 给命名约定行补内容口径——那是追认，不是发明。
