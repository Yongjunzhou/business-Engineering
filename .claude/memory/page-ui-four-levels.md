**91 号规范的页面层级与业务流程树，2026-09-16 首次钉死四级对应**（91 v5.61 → v5.62 §1.1.1）：

| 页面层级 | 对应树级 | 是什么 |
|---------|---------|--------|
| 菜单标签页 | （无树级） | 浏览器标签页级的容器；点开末级菜单 M4 得到它 |
| 场景标签页 | ④ E2E职责 | 一个场景业务的工作区：单窗／双窗／下钻／面包屑 |
| 窗口标签页 | ⑤ 业务文档 | 顶部多 TAB 中的一个；单个实体数据的展示载体 |
| 表单标签页 | ⑥ 任务节点 | 一份文档的任务流转里的一页（审批页 → 派发页 → 验收页） |
| 功能操作项 | ⑦ 用例场景 | 页面上的一个功能按钮、右键操作项或快捷键 |

**来由**：此前 91 的三级页面（菜单标签页／场景标签页／窗口标签页）**从没和树级对齐过**，而「窗口标签页」自己说了三遍、三遍不一样——§1.1.1 按定义指「单个实体数据」（＝文档）、§3.4 按用法指「输出文档流转顺序」（＝文档）、§7.3 任务 5 按用法指「活动节点」（＝任务节点）。四级模型是**逼它把含糊说清**：拆成窗口标签页（文档级）／表单标签页（任务级），再往下净增一级「功能操作项」（用例场景级）。

**用户自己给出的相邻两级**（2026-09-16）：任务节点「原则上，一个节点对应一个表单标签页」；用例场景「原则上对应着标签页上的一个功能按钮、右键操作项，或一个快捷键所提供的功能」。这两句是四级模型的种子。

**同批修掉的两件**：① 菜单标签页「由若干**场景**标签页组成」→「由若干**窗口**标签页组成」（与 §1.2 的图、§1.3 的 M4↔一条场景业务对上）；② 「七种页面类型」→「九种」（六处，含 §4.1 布局组件对应关系与 §九 页面 NFR）。

**它给 biz 链的东西**：**详细定义的落点是界面**——菜单、窗口标签页、表单标签页、功能操作项四级全挂在 R 树上，所以「逐节点详细定义」这件事只在 R 侧做（产品开发视角止于框架），见 [[biz-chain-renumbering-2026-09-16]]。

## 归属定案：界面四级写在 `04`（业务流程完整态），不写在 `05`

2026-09-16 第二次会话判定。**三个独立权威同时指向 `04`**：

1. **94 v1.26 §2.2**：四级"都挂在 R 树上"，完整态 = R 树的深态，故四级属 `04`；「产品开发视角止于框架（`03`）」。
2. **91 §1.1.1 的对应表**：场景/窗口/表单标签页/功能操作项 ↔ ④⑤⑥⑦——正是 `02`（框架到⑥）与 `04`（完整态到⑦）所写的级。
3. **`05` 数据文件自己**（决定性）：§0.2 写死「**功能表单不属于本树**（2026-09-10 定）」；§3.1 规则 3 说**产物类型（流程定义/表单定义/指标定义等）属产物类型口径，用于配置方案层组织**；§4.1 节点模板只有 节点定义／承接关系／符合性分析／设计指导／复用说明，**一条页面级要素都没有**。94 §2.5 同此：「旧平台对象（功能表单／流程定义…）的产物归属在此收口」。

**关键区分——「产物」与「视角」是两层**：**功能表单是产物类型**（→ 配置方案层，94 §2.5）；**表单标签页是页面层级**（↔ ⑥，挂在 R 树上）。混称一次就会得出"界面归 05"的错结论。

**连带（未落笔，待裁）**：**91 §7.2 任务 5 尾句**「表单标签页序列编排由 wft03 负责」与 **§7.3 任务 1~7**（输出文档实体需求／正文功能表单／表单标签页序列／任务关系需求／支持信息引用需求）是 94 v1.26 之前的切法，须重切；**菜单树与菜单导航**（M0~M4）不算树级、仍归 05。

**刻意没动**：§1.2 交互模式、§1.3 菜单导航、§3.4 三层页面编排（它那句「形成**窗口标签页**序列」正是文档级那个）。菜单树 M1~M3 按什么分组，91 仍未定，**不要替它填**——那是业务配置的实际内容。
