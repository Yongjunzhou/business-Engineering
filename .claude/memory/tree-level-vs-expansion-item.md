**判据（2026-09-10 定，裁 94 树时趟出）：一个节点该不该占树位，看它是不是父节点的「展开项」。**

- **展开项**＝名称级预告 / 内联稳定标签 / 待下游定义的锚点——它挂得住内容，但**撑不起一层**。展开项之间是**平级**的。
- 反面用法：**若一层里本该有的兄弟没出现，多半不是"还没画"，而是"这一级画错了"。** 缺的那一支是坐标错位的示踪剂，不是遗漏。

**EOS 实例**：94 §2.2 原把 A2/Bn 画出 `⑤ 业务输出文档 → ⑥ 文档开发任务节点 → ⑦ 用例场景类操作` 两级，而 biz 链（91 §7.3/§10.6、93 §三.3、02 画像注、04 叶定义、biz01 树一二）一处口径是"输出文档＝枝梢，其下一级＝叶（PL6-A 活动 / PL6-B 条目并列两支）"。三条判据同时命中：① 一个文档 **0 或 1 个任务**（02 §2.1.2）→ 任务是字段不是级；② 02 把「任务主要节点」与「PL6 条目名」并列为枝梢的**分解源判据展开项**，93 §三.3 明说"展开项不是 02 的树节点"；③ 94 的末两级里 **PL6-B 正文条目整支缺失**（biz 链里它是承重概念，02 用"三独立"判其能否成叶）。修订见 94 v1.13：末两级并作一级（⑤ 枝梢 / ⑥ 叶）。

**How to apply**：画或审任何产品的分解树时，逐级自问三句——**这一层的每个节点能各自独立挂一条上游条目吗？它有 ≥2 个合理的兄弟吗？它的兄弟齐了吗？** 三句里有一句答不上，那一层就要复核是不是把字段/展开项提成了级。
