**人类 2026-09-21 定**：abr／abp／93／94 四份文件里的级名与属性名统一到新的一族。旧名零残留（93 号本就不绑具体名词，实为三份）。

## 级名对照

| 旧 | 新 | 位置 |
|----|----|------|
| 产品类型 | **产品级E2E业务** | P 树 ② |
| 产品构件类型／构件类型 | **构件级E2E业务** | P 树 ③ |
| 构件开发WBS（包）／WBS 包 | **WBS业务** | P 树 ④ |
| 角色职责 | **职责级E2E业务** | R 树 ③ |
| E2E职责 | **岗位级E2E业务** | R 树 ④ |
| 业务文档 | **文档级E2E任务** | 两树 ⑤（末三级之首） |
| （P0）构件 | **引擎级E2E业务** | P0 ③ |
| （P0）配置单元 | **配置单元业务** | P0 ④ |
| （P0）配置信息组 | **配置信息组业务** | P0 ⑤ |

业务域、相关方角色、任务节点、用例场景**不变**。「业务文档」到终名经过三次中转：文档生成过程 → 文档业务 → 文档生成任务 → **文档级E2E任务**。

## 属性名（五个坐标之三，改与级名同名）

- 所属E2E职责 → **所属岗位级E2E业务**
- 所属产品类型 → **所属产品级E2E业务**
- 所属产品构件 → **所属构件级E2E业务**

所属业务域、所属主责角色不变。**这是一次 schema 改名**——字段名进了 91 §11 与 02／03／04 数据文件的口径，那几处尚未跟。

## 两处结构性观察

- **末级是"任务"、前四级是"业务"**：业务＝组织承担的一整摊事，任务＝一个人手上的一件活；⑤ 正是两棵树落到"人"上的那一格。
- **④⑤ 不带"级E2E"**（WBS业务／配置单元业务／配置信息组业务）：它们不是端到端业务，是**作业单元**与**配置实体**。名字的收尾方式标出了这条缝。
