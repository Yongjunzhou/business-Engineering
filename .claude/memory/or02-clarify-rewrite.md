## 澄清是什么（模型）

**澄清 ＝ 维护一份问题清单。** 它夹在切分与规范化之间，把需求文档的正文从"能读"做到"能规范化"；树形不动、只消歧；**内容只能来自相关方**，所以只能靠一条环推进：AI 认出说不清处 → 人拿去问相关方 → 答复回来 → AI 写进正文。

**运行不变式**：一轮运行结束，这篇要么**清单空**（`已澄清`），要么**带着一份最新的问题清单等答复**（`澄清中`）。"等答复"就是本轮的结论，不是留给后面的活。

## 四步

`Start 选材` ／ `1 出题`（读正文、按两味判据认清、与既有清单对账、逐处成问汇成清单）／ `2 对话确认与落答`（人确认问题、给答复，AI 就地写回正文并划去该条）／ `3 复核与判定`（重读写回后的正文、并入新条目、**判"清单空＝已澄清／非空＝澄清中"**）／ `End`。

- **1 与 3 是同一个动作**（读并出题），读的文本不同（原文／写回后）；每轮各进一次、只进不退。
- **一次运行只处理一篇需求文档**（Step Start 从候选清单中选定**一篇**，不批量）。
- **人机交接点两处**：Start（选材）＋ Step 2（确认与答复）。

## 关键定案

1. **澄清对象两味**——**表述不清**（术语／主体客体／边界／信息）＋**要素缺席**（缺少定量指标／分支缺对应面／引用对象缺失）；同一处只立一条。原「六类 ＋ 独立结构完整性」归并于此，「闭环缺端」**删**（or01 本轮已定"不要求闭环、上游交碎片闭环由下游长出来"）。**「引用对象缺失」的查法**：范围＝本篇所属那份材料切出的**全部**需求文档（即源材料），按需 grep、命中才读——判据**不收窄成"本篇内"**（收窄会把"已在别片定义过"的引用误报成缺失）。
2. **撤行内标记**——`[⨯]`／`[✓已澄清]` 是为"人类在正文区写 `[✓]`"这条已废通道造的；并进对话单轨后无人写无人读，全撤。问题清单**写在正文区之后**（工作态，澄清完成时清除），条目带状态 `待问`／`待答`。
3. **撤「待处置项 ＋ 裁决」**——澄清里 AI 报出的只有"还没问到"（未完成）与"自己写错"（改掉即可），**没有非人不可的裁量**，裁决步没有对象。
4. **判据收敛成一句**——**复核后清单空**（原三项条件合于此）。
5. **反馈对话单轨**——撤「线下写 `[✓已澄清]`」与状态扫描／登记／`[已处理]`；表 B `人类决策` 列留作选材与终止。线下向相关方澄清退到运行之间，答复经对话进。
6. **无运行内回环**——步骤只进不退；本轮解决不了的标 `待处置` 留待下一轮。
7. **X 与 Y 同树**（94 §2.0.1「树形不动，只消歧」）；二、三两章同图，本任务不增删任何节点。
