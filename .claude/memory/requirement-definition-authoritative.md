**需求权威定义**（[通用设计规范 §1.2](../../00-generalspec/01-generalspec-sysdev.md#12-需求详解)，2026-08-18 链级对齐锚）：

- **需求 = 需求描述 + 性能指标**，两部分构成不可分割；**不可衡量则不成为需求**
- **需求描述** = 功能或非功能需求的定性说明
- **需求性能指标** = 需求被满足的程度和测量方式，分**定量指标**（响应时间 < 200ms、可用性 99.9% 等）与**二元判定指标**（通过认证、满足标准等）两类
- 需求分 **FR**（系统接到什么、做什么、产出什么）与 **NFR**（系统运行的条件或品质：系统性能/接口约束/质量属性/标准合规）；分类基于需求内容本身，与文档角色无关

**链级推论（2026-08-18 or02 v0.27 链级联动）**：
- 任何需求缺"性能指标"中的定量指标部分 → **模糊（缺少定量指标 = or02 第六种子类型）**，FR/NFR 同构适用——AI 均向相关方要 数值+单位+条件
- **NFR 定量指标目标值由相关方经 or02 澄清确认**；wft01-nfr 只记录目标值，wft04-nfr 承接做系统侧指标设计（统计口径/测量方法/验收条件）
- 已废除旧说法「质量诉求不量化、数值留给 wft04-nfr」（曾散布于 or02 纪律 5 / or03 §2.1.4 / 91 §九，均已改）

**How to apply:** 审阅"需求构成、缺指标、NFR 量化"相关时以此为准。**NFR 四元组（关注角色×分类维度×适用对象线索）只是 STR-NFR 归组锚点，不是 NFR 的完整构成**——构成仍是需求描述+性能指标。相关：[[or02-clarify-question-list]] [[or03-normalization-connotation]] [[or02-03-readability-revision-plan]]
