# OR 预处理链 · 链级概览

**目录导航**：本文档描述 `eos-or00-textualize` / `eos-or01-chunk` / `eos-or02-clarify` / `eos-or03-norm` 四份 Skill 的链级关系、各自的运行模式与共用的状态文档约定，供概览查阅。每份 Skill 文档自包含，不强制依赖本文档。

---

## 一、预处理链概览

```
原始材料 (PDF/图片/邮件/纪要)
    │
    ▼
eos-or00-textualize ──── 文本化（非文本 → Markdown）
    │                      产出：文本化文档 `.textualized.md`
    ▼
eos-or01-chunk      ──── 切分（按需求的落点）
    │                      产出：需求文档 `.chunk-{seq}.md`（业务需求文档 / 非功能需求文档 / 引擎需求文档，status=raw）
    ▼
eos-or02-clarify    ──── 需求澄清（人类-in-the-loop）
    │                      产出：已澄清的需求文档（status=clarified）
    ▼
eos-or03-norm       ──── 需求规范化
    │                      产出：01-eos-specified-requirements.md（规范化的相关方需求基线）
    ▼
t01（相关方需求 → 业务流程 开发）
```

## 二、各步运行模式

| Skill | 运行模式 | 人类反馈怎么给 | Step 序列 |
|-------|---------|--------------|----------|
| `eos-or00-textualize` | 对话单轨 | 对话 | Start／1／2／3／4／End |
| `eos-or01-chunk` | 对话单轨 | 对话；选材与终止走状态文档表 A 的 `人类决策` 列 | Start／1／2／3／4／End |
| `eos-or02-clarify` | 对话单轨 | 对话；选材与终止走状态文档表 B 的 `人类决策` 列 | Start／1／2／3／End |
| `eos-or03-norm` | 对话单轨 | 对话；选材与终止走状态文档表 B 的 `人类决策` 列 | Start／1／2／3／End |

> **对话单轨**——AI 产出方案后不结束对话，人类自然语言反馈、AI 即时理解并处理；方案未确认的留在状态值上，由下一轮接着谈。人类不再编辑文档表达反馈。链上四步同此一轨。

## 三、状态文档与同步契约

```
先更新 01-eos-sysdev-status.md 对应子表（权威源）
  → 再推导写入各处理结果文档头部的管理区状态摘要
若检测到不一致 → 以权威源为准重建派生表
```

状态文档是链上各步共用的一张控制面：AI 读它选材、写它落账；人类读它看进度、改它的 `人类决策` 列完成选材与终止。

---

## 四、状态字段职责约定

状态文档的字段按职责分为三类：

| 字段 | 职责 | 使用方式 |
|------|------|---------|
| **生命周期** | 流程状态字段 | 供 AI 和流程判断使用，表示材料当前所处的客观阶段 |
| **人类决策** | 批次控制字段 | 供人类选材和批次控制使用，决定材料是否进入本轮处理 |
| **处置标记** | 叠加标记 | 叠加在生命周期之上，标出「已检出、待裁决」或「缺陷待人工」，供存量节点入口检出 |
| **AI建议** | 提示字段 | 仅供人类快速理解下一步建议，不参与 Step 入口硬判断 |

**通用判定规则**：

- **Step 新增入口**由 `生命周期 + 人类决策` 决定
- **Step 存量节点入口**（遗留方案、待处置项、下游退回）由 `生命周期` 与 `处置标记`（取值 `待处置`／`待人工处置`／`待退回重切`）检出，不占用新增入口
- `AI建议` 只用于行动清单、状态表提示和人工选材参考
- `AI建议` 不得作为自动入口、自动分支或自动执行的硬门槛

**各步入口**：

- `eos-or00-textualize`：`10-raw-files/` 中未文本化的原始材料
- `eos-or01-chunk`：`生命周期=已文本化` + `人类决策=同意切分`
- `eos-or02-clarify`：`生命周期=已切分` + `人类决策=同意澄清`
- `eos-or03-norm`：`生命周期=已澄清` + `人类决策=同意规范化`

## 五、各步对照表

| 方面 | or00-textualize | or01-chunk | or02-clarify | or03-norm |
|------|-----------------|------------|--------------|-----------|
| 处理对象 | 原始材料（任意载体） | 文本化文档 | 需求文档（`status=raw`） | 已澄清的需求文档（`status=clarified`） |
| 输出 | 文本化文档 | 需求文档 | 原地更新同文件（`status=clarified`） | `01-eos-specified-requirements.md` |
| 关键判据 | 转录规则、查重规则 | 句类分流、文档级任务、适用对象与主题、可运行的能力 | 两味判据（表述不清 / 要素缺席） | 分味认支、三支长树、五属性 |
| 方案载体 | 工作副本管理区与正文区 | 切分方案块 | 行内 `[⨯]` 标注 + 标注方案块 | 方案块（对话确认） |
| 状态推进目标 | `已文本化` / `文本化方案待确认` / `已废弃（重复）` | `已切分` / `切分方案待确认` / `已废弃` | `已澄清` | `已规范化` |
