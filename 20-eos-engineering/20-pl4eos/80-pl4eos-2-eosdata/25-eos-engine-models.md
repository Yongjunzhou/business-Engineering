## §1 平台架构总览


### 业务视角层级体系

EOS 平台使用四套视角层级描述业务在不同维度上的组织结构：

| 视角 | 编号 | 自上而下 |
|------|------|---------|
| **ML**（菜单视角） | M0→M4 | 平台 → 一级菜单 → 二级菜单 → 三级菜单 → 末级菜单（→SL5） |
| **SL**（角色场景视角） | SL0→SL6 | 平台 → 业务域 → 产品类型 → 角色 → 角色职责 → 场景业务 → 场景部件/主子表单 |
| **PL**（产品视角） | PL0→PL5 | 平台 → 业务域 → 产品类型 → 构件 → WBS → 输出文档（→SL6） |
| **EL**（引擎视角） | EL1→EL3 | 菜单引擎 → 功能引擎 → 实体引擎 |

> 本文档聚焦 **EL**（引擎视角）和 **SL5**（场景业务）层级。其余视角层级的完整定义见 `23-eos-output-architecture.md` 和 `24-eos-business-assets.md`。
>
> **P0 引擎产品的 PL 树**（对齐 91 §3.1）：平台 → 业务域（流程与IT）→ 产品类型（P0 引擎产品）→ 构件（引擎）→ **CU（配置单元，PL4）→ 配置信息组（PL5，末级节点）**。P0 树无 WBS（P 树 PL4=WBS 保留）；配置信息组是 P0 产品树末级节点（可独立交付/验收的能力单元，对应 P 树 PL5 输出文档），CU 是可独立选配的配置单元（PL4，由配置信息组构成，选配粒度=CU、能力粒度=配置信息组）。

### 1.3 引擎职责与横切规则

**实体引擎**：

- 基于数据库生成物理表，提供增删改查和导入/导出等基本功能。
- 物理表是功能引擎和菜单引擎的元数据基础。

**功能引擎**：

- 将物理表转换为功能表单——功能表单以一定样式展现，并使得物理表中的数据具有运算、流转和被操作的能力。
- 承载四方面能力：① 表单能力——表单结构/字段/布局/校验/行为/发布，是各具体功能引擎的共享展现基础设施；② 功能能力——各具体功能引擎为功能表单增加的功能；③ 组装能力——将一组（1+N 个，N≥0）功能表单按主子业务关系组装为主子表单，基于主表单行数据内容匹配子表单显示规则，动态确定展示子表单集合，支持双击下钻和持续下钻；④ 权限能力——配置行/列级数据访问权限，控制数据行和字段列对角色/人员的可见、可编辑或不可访问。
- 功能引擎分为两个子类（仅为分类口径，非独立引擎资产）：
  - **产品数据类**：流程引擎、工单引擎。流程引擎管理审批流转（对象=文档封面），工单引擎管理派发/处理/验收/关闭（对象=文档封面或正文条目）。封面-正文 1:1 绑定由功能引擎的组装能力统一完成，不设独立文档引擎。
  - **业务管理类**：指标引擎、看板引擎、项目引擎、WBS 引擎、计划引擎、进展引擎、定时任务引擎。支撑过程管理数据的生成与管理。指标引擎管理指标定义/口径/图示双模式展示（列表+2×3网格），看板引擎管理看板布局/视图泳道，计划引擎管理计划任务并作为唯一自启动任务引擎（R6）。

**菜单引擎**（含场景编排）：

- **非末级节点**：定义所属父节点、显示顺序、可见性和可达性权限。
- **末级节点**：定义所包含的主子表单部件、显示顺序和依赖关系——此主子表单序列称为**场景业务**（SL5）；同时定义该末级节点的可见性和可达性权限。
- 场景业务定义后，菜单引擎生成并维护多级菜单树，控制角色/人员的导航可达性。

**权限归属**：

- 菜单节点对角色/人员的可见或不可见规则，由菜单引擎承载。
- 物理表数据行或列对角色/人员的权限，由功能引擎承载。

**配置单元选配模型**：每个引擎包含若干配置单元（可独立选配的 IPO），部分配置单元即可让业务运行——引擎提供能力池，配置人员按业务需要从中挑选组合，非全量必配。

### 1.4 场景业务及输出文档

bpl-biz（业务流程框架架构末级节点）以场景业务为组织单元。场景业务定义见 [91 规范 §1.4](../../10-pl4eos-subpd-sysdev/10-wfsysdev-4-eos/91-eos-biz-eng-spec.md#14-业务场景)，输出文档模型（封面判定/正式与轻量/设计规则/任务关系）见 [91 规范 §二](../../10-pl4eos-subpd-sysdev/10-wfsysdev-4-eos/91-eos-biz-eng-spec.md#二输出文档模型)。

**bpl-biz 的两种类型**（由 AI 根据 规范化的相关方需求 语义判定，同一角色可同时有两种类型）：

| 类型 | 识别词 |
|------|--------|
| **执行类（D）** | 规范化的相关方需求 描述执行活动——创建/提交/审批/交付/验收等动作词 |
| **管理类（PCA）** | 规范化的相关方需求 描述管理活动——计划/监控/分析/纠正/识别等动作词 |

执行类（D）和管理类（PCA）在 wft01/02/03-biz 的处理逻辑上完全同构——都是场景业务→输出文档序列→每个文档有封面+正文+任务+引用。差异仅在正文数据类型（产品数据 vs 管理数据）和典型任务关系。完整定义见 [91 规范 §1.4](../../10-pl4eos-subpd-sysdev/10-wfsysdev-4-eos/91-eos-biz-eng-spec.md#14-业务场景)。

### 1.5 用户界面

用户单击菜单引擎发布的末级菜单进入场景业务，运行时 UI 遵循以下交互模型：

```
│                                                                              │

│ │ ┌────┬────┬────┬────┐                                                    │ │

│ │ └────┴────┴────┴────┘                                                    │ │
│ └──────────────────────────────────────────────────────────────────────────┘ │
└────────────────────────────────────────────────────────────────────────────┘
```

```
│ │ │行1 │    │    │    │    │    │ │ ┌───────┬───────┬───────┬───────┐    │     │

│ │ └────┴────┴────┴────┘    │    │ │ └───────┴───────┴───────┴───────┘    │     │
```

```
┌─────────────────────────────────┬──────────────────────────────────────────────┐
│ 左窗：子业务X                    │ 右窗：子子业务Z                                │

└─────────────────────────────────┴──────────────────────────────────────────────┘
```

**面包屑导航**：页面底部常驻导航条，显示当前层级路径，支持双击任意节点跳转至该层级。

```
场景业务 > 主子表单A > 子业务X > 子子业务Z
```

**交互规则**：

| 规则 | 说明 |
|------|------|
| 初始单窗 | 进入场景业务时为单窗全宽，不下钻不分屏 |
| 主子表单 TAB | 顶部 TAB 对应该场景业务下的多个主子表单 |
| 首次下钻 | 在主表单双击某一行数据触发分屏，右窗显示子表单数据 |
| 递归下钻 | 右窗→左窗，新右窗出现，直到系统层级数限制 |
| 面包屑导航 | 底部常驻，显示当前层级路径；双击任意节点跳转至该层级 |
| 子表单显示规则 | 功能引擎基于主表单行数据内容匹配规则，动态确定展示子表单集合 |

### 1.6 业务生成与引擎推导

**三层引擎生成链**（自底向上，各引擎职责详见 [§1.3](#13-引擎职责与横切规则)）：

- **物理表**（实体引擎）→ **功能表单 / 主子表单**（功能引擎）→ **场景业务 + 菜单树**（菜单引擎）
- 每一层引擎消费上一层的产物，生成下一层的输入，逐级生成直至平台可发布的末级菜单。

**输出文档推导**（自顶向下）：

bpl-biz 架构末级节点是场景业务（详见 [§1.4](#14-场景业务及输出文档)），场景业务由输出文档序列细化定义——每个输出文档描述一件业务输出物的内容、流转关系和功能需求。输出文档按是否条目化且在 EOS 平台上运行管理，分两条路径推导其支撑引擎链（两种生成方式详见 [§1.4](#14-场景业务及输出文档)）：

**内置 CAX**（输出文档条目化且在 EOS 平台运行管理）——沿三层引擎生成链逐级推导：

- **正式文档**：封面实体和正文实体由实体引擎生成物理表，封面由功能引擎的表单能力转为封面表单（单据头样式），正文由对应引擎转为正文功能表单，两者按 1:1 主子关系由功能引擎组装为主子表单
- **轻量文档**：正文实体由实体引擎生成物理表，正文由对应引擎转为功能表单，不产生封面表单和主子组装——正文即文档
- 若该文档与其他文档存在主子业务关系，按 1+N 扩展组装

**外置 CAX**（输出文档非条目化或不在 EOS 平台管理）——不变。

**汇聚**：无论内置或外置 CAX，全部主子表单序列由菜单引擎末级节点编排，并生成平台菜单入口。

## 附录A 规则区与口径区

1. 引擎描述平台能力边界，不替代产品架构组件或代码实现设计。
2. 引擎应能追溯到 `23` 构件类型、`24` 业务或 `04` bpd-eng P0 方案。
3. 同一引擎可被多个业务复用；复用关系记录在索引和追溯区。
4. 外购、自研、自研+外购是架构级实现策略，不代表采购或开发已经完成。
5. 对外接口只记录架构级能力和输入输出摘要，详细 API 规格应在后续产品本体或开发文档中定义。
6. 引擎配置单元类型描述某个引擎可独立配置、校验、发布、复用或版本管理的元数据对象类型；具体业务的配置单元实例不写入本文档，应由 `04-eos-business-detailed.md` 的 P0 bpd-eng 方案或后续 pa-eng / 配置资产承载。
7. `wft02` 生成 P0 引擎配置单元建议时，应优先查询本文档的配置单元类型库，再按当前 P 业务、R 场景业务或公共业务实例化；若本文档不存在可承接的配置单元类型，应形成 25 资产新增 / 扩展建议或引擎能力缺口反馈。
8. **术语统一**：本文档与 wft01 统一使用"配置单元"术语。配置单元的三个核心字段为 Input（配置要素）/ Process（处理说明）/ Output（业务说明）。**层级说明**：25 CU 块的 Input/Process/Output 是 CU 类型级定义；eng 链 wft02-eng 操作活动定义（配置操作/系统处理/运行期能力）是配置信息组级详设（基准 = PDF v1.5.2），两者层级不同——25 记类型级骨架与引用，操作活动定义全文在 04 bpd-eng 节点。
9. **功能表单口径**：功能表单是功能引擎将物理表转换后的产物，以一定样式展现，并使得物理表中的数据具有一定的运算、流转和被操作的能力；实体引擎的产物称为物理表。
10. **三层引擎生成链**：物理表 → 功能表单 / 主子表单 → 末级菜单（含场景业务）是 EOS 平台引擎装配的主链路。
11. **权限配置归属**：不设置独立权限引擎。菜单节点可见 / 不可见规则由菜单引擎承载；物理表数据行 / 列权限由功能引擎承载。
12. **功能引擎两子类**：产品数据类（流程/工单/台账）支撑各类产品数据开发与管理，同一引擎支撑的不同类型产品数据一般对应不同实体；业务管理类（项目/WBS/计划/看板/指标/进展/定时任务）支撑过程管理数据的生成与管理，同一引擎支撑的管理数据一般对应同一实体。两子类仅为分类口径，非独立引擎资产。
13. **以输出文档为引擎推导锚点**：相关方功能需求架构末级节点是业务输出文档（指文档内容而非文档名称）。若输出文档A条目化且在 EOS 平台上运行管理，则：① 输出文档A的条目化内容对应一个实体A，由实体引擎生成物理表；② 输出文档A的内容所需的功能集，由功能引擎赋予（确定支撑其功能集的具体功能引擎）；③ 输出文档A若有其他文档Bi作为其子业务数据，则由功能引擎将A与Bi按1+N组装为主子表单。简言之，由输出文档可识别或定义其对应的实体，由输出文档的需求可确定支撑其功能集的功能引擎，由端到端业务需求可识别和定义其子业务文档。

本文件是引擎资产文档。AI 读取本文件时应先读取引擎总览和索引，再按引擎 ID 定位目标正文块。

## 附录E 业务层级与引擎装配链

EOS 平台的用户可见业务由三层引擎逐级生成生成。物理表是底座，功能引擎负责转换和组装，菜单引擎负责场景编排和导航：

| 装配层 | 产物 | 定义 | EOS 平台体现 | 生成引擎 |
|--------|------|------|-------------|---------|
| P0 | 物理表 | 业务对象的数据结构、物理存储结构和关系约束 | 物理表及其元数据、字段名称 / 类型 / 格式、主键、外键、索引字段、字段业务逻辑、实体关系、生命周期 | 实体引擎 |
| R | 功能表单 / 主子表单 | 物理表经功能引擎转换为功能表单，并按主子关系（1+N）组装为主子表单；功能表单以一定样式展现，使得物理表中的数据具有运算、流转和被操作的能力；主子表单支持主表单行数据双击下钻到子表单 | 功能表单承载样式展现、字段间取值规则、显示规则、校验、行为、发布，以及流程、工单、指标、台账、看板、WBS、项目、定时任务、进展等功能能力；主子表单支持按规则动态展示子表单集合、双击下钻和持续下钻 | 功能引擎 |
| A3 | 末级菜单（含场景业务） | 末级菜单节点定义所包含的主子表单序列即为场景业务（SL5），同时生成菜单树和可见性权限 | 末级菜单；高层菜单分组；场景业务 | 菜单引擎 |

**与设计视角层级的映射**：功能表单及主子表单由功能引擎承接；场景业务（SL5）由菜单引擎末级节点编排；末级菜单由菜单引擎承接并指向单个场景业务。高层菜单节点是菜单分组路径，不直接生成业务内容。
