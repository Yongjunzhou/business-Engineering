## 三 EPUB 表格列宽（同日用户「epub 表格不太正常」查实并修）

- **病因**：`fitTableDashes()` 只改了分隔行横线，但 **pandoc 仅当表格总宽 > `--columns`（默认 72 列）时才按横线比例写 `<colgroup>`**；短表不给列宽，EPUB 里只剩浏览器自动布局。实测全书 **173 表 / 134 表有列宽**，本页两表 2/2 全无。
- **修法**：① `preprocess.mjs` 的 `fitTableDashes()` 等比放大横线到整行 ≥80 列（比例不变、每列最少 3 条、取整缺口补最宽列）；② `assets/book.css` 增 `table { width: 100% }`、`tr { break-inside: avoid }`、`thead { display: table-header-group }`。
- **复验**：EPUB **173/173 表带列宽**（本页两张＝23/31/44、23/23/52），CSS 已入包；PDF 侧不动（`fix-typ.mjs` 仍按内容算、9% 下限）。`成书/README.md` 已记此条。

## 三之二 EPUB 表格再加固（同日用户报「只有文字没有表格，且每格一行」）

- **改两处**：① `th,td` 边框由 `#d8d0c4`（浅到弱屏看不见）加深为 **`#7d7264`**，表外加框、表头下 2px、内边距 4/6；② 新增 `build/table-inline.html`，EPUB 构建加 `--include-in-header`，把同一套表样式**内嵌进每个 xhtml 的 `<head>`**（防阅读器不加载外链 CSS）——实测 26/26 文件带内嵌样式。
- **判断**：EPUB 结构与样式均合规（26 xhtml XML 全通过、CSS 在 manifest、每文件都链接它；用 MuPDF 的排版引擎渲染同构表样例，是三列带框的正常表格）。若用户仍见"每格一行、无线"，是阅读器**不支持 `<table>` 布局**（Kindle 推送转换／部分手机阅读器流式模式），CSS 无解——只能换阅读器或做"表格转图"版。**已向用户求证所用阅读器。**
- **2026-10-19 用户答**：**WPS 与 FBReader 都不对、且病不同**——WPS 会做表格布局但**丢弃样式**（外链 CSS 与内嵌 `<style>` 都不认 → 只剩文字对齐、没有框线）；FBReader **根本不支持 table**（`td` 当块级元素，一格一行）。**已出「表格转图版」**：`build/make-table-images.mjs`（表格块 → pandoc typst → typst 118mm@190ppi PNG → `![](...){width=100%}` 替换）→ `架构师-电子版-表格转图.epub`（**14.78 MB**，169 表转图；附录 4 张超长表保持真表格，单张高逾万像素），标准版 3.89 MB 留用。**代价＝表内文字不可检索**；中间目录 `build-tblimg/` 构建后删除（`node build/make-table-images.mjs . build build-tblimg` 可重生成）。
