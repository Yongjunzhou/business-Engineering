## 三·补 两处下钻的结论（已处理）

**下钻一·两条转化怎么做、怎么判转到位了**（证据：SEH p150／p156／p157／p158／p159 ＋ 附录 C 术语表）：

- **四个转化动作**：① **实体**——架构实体（功能、输入/输出流及流动项、状态和模式、功能和物理接口、节点和链接、计算和通信资源；或企业/项目目标、能力和效果、操作活动、资源功能）及其关系 → **设计元素**；② **特性**——架构特性 → **设计特性**（功能、行为、尺寸、形状、材料、关键质量特性、数据处理结构）；③ **分配**——系统需求 → 系统元素，且"以确保满足所有系统需求**和架构目标**"；④ **接口**——"分析在系统架构中识别和定义的接口……**细化或进一步定义**这些接口"（**只能细化，不能凭空新增**）。
- **五条判据**：完备（[6.4.5.1]＋系统设计描述"将开发为**规范**，以用于采购或实现"）／一致（"设计应与**主导架构描述**保持一致"）／双向可追溯（设计特性 ↔ 架构实体·接口·分析结果）／描述符匹配（"将系统元素及其特定的设计描述符与**整体系统的设计描述符相匹配**是系统设计的关键部分"）／原子换手判据（见下钻二）。
- **术语表两侧对仗**（可直接引）：**系统架构理由**＝"架构选择、技术/技术系统元素选择以及**系统需求和架构实体之间的分配**的理由"；**系统设计原理**＝"设计选择、系统元素选择以及**系统需求与系统元素之间的分配**的理由"；**系统设计特征**（源 15288:2023）＝"与产品或服务的可测量描述相关的设计属性或特征"。
- **一处缝的准确口径**（p159 逐字）："**系统架构识别系统元素，尽管架构描述可能仅识别那些在架构上具有重要意义的元素，但随着更详细设计考虑的出现，其他元素也会逐渐显现**"——故"设计不得引入架构没有的东西"**过强**；须配回流规则（p30 逐字："当这些衍生功能影响目标系统时，相应的衍生需求**应当纳入系统需求基线**"）。

**下钻二·递归换手点**：

- **判据**（p33 引 15288:2023 术语）："如果一个系统元素**只需要用黑盒（不透明箱）表示法来描述它的需求**，并**能够自信而明确地定义其在现实世界中的解决方案**，那么它可以被视为**原子元素**。在这种情况下，可以在不进一步详细说明元素的情况下，自信而明确地做出关于是**购买、制造还是重用**该元素的决策。"
- **位置**（p73 逐字）："直到在某一层级决定是制造、购买还是重用某个系统元素……上一层级的产出会作为下一层级的输入（**在系统定义时往下，在系统实现时往上**）。"
- **交出什么**（p156）：系统设计描述"将开发为**规范**，以用于**采购或实现**组成设计的系统元素"。
- **判据性质**：**信息充分性判据，不是深度／层级判据**——标准没有"分到第几层停"。
- **两条勿混的相邻规则**：层宽启发式 7±2（p34，**可管理性**规则，非停止规则）；**横向集成**（深入研究之前的完整性）／**纵向集成**（各层级之间的一致性）（p73）。
- **收口**：换手点是"这一个元素"的**停止线**，同时是"下一层"的**起跑线**——除非判为原子，那时下一层不启动。
