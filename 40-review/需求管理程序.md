## 1 目的

规范需求**批准并基线化后**的管理活动——基线建立与维护、变更控制、可追溯性、状态跟踪与度量,确保**规定需求**在其生命周期内**受控、可追溯、可验证**,为产品研发提供可靠、稳定的需求基准,并满足质量体系要求。

## 2 适用范围

适用于本公司产品研发项目中,经评审批准的需求(**规定需求**)基线化后的管理。

**本程序不包含需求开发活动**(需求的获取、分析、规格说明与验证),该部分由《需求开发程序》规定;本程序以需求开发产出的《需求规格说明书》(SRS,即规定需求的载体)为输入,管辖其基线化之后的全部活动。

## 3 引用文件

- GB/T 19001—2016《质量管理体系 要求》
- ISO 9000:2015《质量管理体系 基础和术语》
- ISO/IEC/IEEE 29148:2018《系统和软件工程——生命周期过程——需求工程》
- 《需求开发程序》(XX-QP-XX)
- 《需求规格说明书》模板(QR-07)、《变更请求单》模板(QR-16)

## 4 术语与定义

| 术语 | 定义 |
|---|---|
| 规定需求 specified requirement | 被明示的需求,即 SRS 中的条文;**验证的参照** |
| 需求基线 | 经批准冻结的需求版本,变更控制的判定基准 |
| CCB | 变更控制委员会(Change Control Board),需求变更决策机构 |
| 可追溯性 | 需求与其来源、设计、测试之间可双向追溯的程度 |
| 变更级别 | 微小 / 一般 / 重大(见 7.5) |

## 5 职责

| 角色 | 主要职责 |
|---|---|
| 需求管理负责人 | 编制项目需求管理计划;发起变更;编制影响分析;维护追溯矩阵与覆盖分析;发布状态报告 |
| 项目经理(PM) | 一般变更批准;CCB 主任;评审项目需求管理计划 |
| CCB | 重大变更评审决策(批准/拒绝/暂缓) |
| 配置管理员 | 建立与登记基线;维护变更日志 |
| 测试/质量工程师 | 变更再验证;需求度量;过程符合性检查 |
| 干系人 | 提出变更请求 |

## 6 输入与前置条件

### 6.1 输入

本程序以《需求开发程序》的产出为输入:

- 规定需求(经批准的需求规格说明书 SRS, QR-07);
- 需求批准记录(QR-12);
- 需求追溯矩阵初版(QR-09)。

### 6.2 管辖边界

- 本程序的**起点**:需求基线建立(QR-14);
- 本程序管辖:基线 → 变更 → 追溯 → 状态 → 度量;
- 基线之前的需求开发活动不属于本程序范围。

### 6.3 程序文件与项目级计划的层级

- **本程序(组织级规程)**:规定组织内需求管理活动的通用要求;
- **需求管理计划 RMP(项目级计划)**:每个项目启动时,按本程序为该项目编制的具体执行计划(含本项目 CCB 组成、基线策略、变更流程、工具与度量安排)。本程序是 RMP 的编制依据。

### 6.4 文档流转主线

```
QR-13(RMP,项目启动时编制)→ QR-14(基线)→ QR-15(基线登记表)
→ QR-16/17/18/19(变更)→ QR-09·QR-20(追溯·覆盖)→ QR-21/22(状态)→ QR-23(度量)
```

## 7 输出文档管理要求(以过程活动呈现)

每份文档按过程活动五要素描述:**何时 / 谁 / 做什么 / 以什么标准 / 输出·流转**。

### 7.1 QR-13 需求管理计划(RMP)

| 活动要素 | 内容 |
|---|---|
| 何时 | 项目启动时、需求管理活动开始前;重大范围调整时修订 |
| 谁 | 需求管理负责人编制;PM 及 CCB 评审,管理层批准 |
| 做什么 | 按本程序为项目编制需求管理计划:目的范围、角色职责、需求组织规则(编号/分类/属性)、基线策略、变更控制流程(CCB 组成与时限)、追溯与度量安排 |
| 以什么标准 | 内容覆盖上述 6 模块;与 ISO/IEC/IEEE 29148 及本程序一致;批准后受控发布并版本化 |
| 输出·流转 | QR-13;作为本项目全部需求管理活动的执行依据(本程序的落项目版本) |

### 7.2 QR-14 需求基线(冻结版 SRS)

| 活动要素 | 内容 |
|---|---|
| 何时 | 需求经批准(QR-12)后建立;每次变更关闭后更新 |
| 谁 | 配置管理员 |
| 做什么 | 冻结批准的需求版本,标注版本号、日期、覆盖需求清单 |
| 以什么标准 | 未经批准不得建基线;版本规则"主.次"(如 V1.0);现行基线唯一 |
| 输出·流转 | 登记入 QR-15 基线登记表;作为一切变更判定的基准 |

### 7.3 QR-15 基线登记表

| 活动要素 | 内容 |
|---|---|
| 何时 | 每次建立/更新基线时 |
| 谁 | 配置管理员 |
| 做什么 | 登记基线编号、版本、日期、覆盖需求清单、状态、关联 CR、批准人 |
| 以什么标准 | 每次变更留痕;现行/历史状态标注准确;与 CR 记录可对账 |
| 输出·流转 | QR-15;配置审计与追溯的依据 |

### 7.4 QR-16 变更请求单(CR)

| 活动要素 | 内容 |
|---|---|
| 何时 | 基线后任何需求改动发生时 |
| 谁 | 任何干系人提出 |
| 做什么 | 填写变更对象(需求编号)、内容、理由、期望时间,判定变更级别 |
| 以什么标准 | **无 CR 不得实施变更**;CR 编号唯一;级别判定:微小(措辞/格式)、一般(影响部分需求/设计/测试)、重大(改变范围/进度/成本/合规) |
| 输出·流转 | 微小→需求管理负责人批准;一般→PM 批准;重大→QR-18 CCB 评审 |

### 7.5 QR-17 影响分析报告

| 活动要素 | 内容 |
|---|---|
| 何时 | CR 提出后 3 个工作日内完成 |
| 谁 | 需求管理负责人牵头,相关技术角色参与 |
| 做什么 | 经 QR-09 追溯矩阵反查受影响的需求、设计、测试、文档,评估工作量、成本、进度、风险 |
| 以什么标准 | 分析覆盖全部关联项;**不分析不得上会评审** |
| 输出·流转 | QR-17;随 CR 提交 CCB(QR-18) |

### 7.6 QR-18 CCB 评审记录

| 活动要素 | 内容 |
|---|---|
| 何时 | 每周例会,或收到申请后 5 个工作日内 |
| 谁 | CCB:主任(PM)、需求/开发/测试/质量代表;重大变更邀客户或合规代表 |
| 做什么 | 评审 CR 与影响分析,决策:批准 / 拒绝 / 暂缓 |
| 以什么标准 | 重大变更须全体出席;记录须含理由与附带条件 |
| 输出·流转 | 批准→实施变更并同步 SRS、RTM;拒绝/暂缓→退回提出人 |

### 7.7 QR-19 变更验证记录

| 活动要素 | 内容 |
|---|---|
| 何时 | 变更实施完成后 |
| 谁 | 测试工程师 |
| 做什么 | 验证变更后需求符合**新的规定需求**,并回归受影响范围 |
| 以什么标准 | 验证通过方可关闭 CR;遗留问题必须记录在案 |
| 输出·流转 | → 更新基线(QR-15)、登记变更日志(QR-22)、关闭 CR |

### 7.8 QR-09 需求追溯矩阵(管理阶段维护)

| 活动要素 | 内容 |
|---|---|
| 何时 | 每次变更关闭后、每轮测试后同步更新,维护至项目结束 |
| 谁 | 需求管理负责人 |
| 做什么 | 维护需求↔来源、需求↔设计、需求↔测试及验证状态的对应关系(编号沿用《需求开发程序》QR-09) |
| 以什么标准 | 追溯覆盖率 100%;变更关闭后 3 个工作日内完成更新 |
| 输出·流转 | QR-09;支撑影响分析、覆盖分析、审计 |

### 7.9 QR-20 覆盖分析记录

| 活动要素 | 内容 |
|---|---|
| 何时 | 每里程碑 |
| 谁 | 需求管理负责人 |
| 做什么 | 基于 QR-09 核查未实现、未测试、孤儿需求,统计覆盖率 |
| 以什么标准 | 覆盖率 100%;发现的缺口须给出整改措施并跟踪闭环 |
| 输出·流转 | QR-20;报 PM 并纳入项目风险管理 |

### 7.10 QR-21 需求状态报告

| 活动要素 | 内容 |
|---|---|
| 何时 | 每周 / 每里程碑 |
| 谁 | 需求管理负责人 |
| 做什么 | 统计需求状态分布(批准/实现/验证/关闭/删除),标注关键需求进展与风险 |
| 以什么标准 | 状态须与 QR-09 一致;识别出的风险须上报 PM |
| 输出·流转 | QR-21;报 PM 及干系人 |

### 7.11 QR-22 变更日志

| 活动要素 | 内容 |
|---|---|
| 何时 | 随变更流程同步记录 |
| 谁 | 配置管理员 |
| 做什么 | 追加登记时间、CR 编号、需求对象、变更摘要、审批结果、验证状态 |
| 以什么标准 | 只追加不修改;与 CR、CCB、验证记录可对账 |
| 输出·流转 | QR-22;审计时直接调取 |

### 7.12 QR-23 需求度量报告

| 活动要素 | 内容 |
|---|---|
| 何时 | 每季度 |
| 谁 | 质量工程师 |
| 做什么 | 统计变更率、稳定性、追溯覆盖率、变更平均周期及趋势对比 |
| 以什么标准 | 预警阈值:变更率≥15%、稳定性≤80%、覆盖率<100%、周期≥10 天;触发即启动根因分析 |
| 输出·流转 | QR-23;报管理层,驱动过程改进 |

## 8 文档关联与流向

| 文档 | 输入来源 | 输出去向 |
|---|---|---|
| QR-13 | 本程序(编制依据) | 本项目全部需求管理活动 |
| QR-14 → QR-15 | 批准的 SRS(QR-07/12) | 基线登记表 |
| QR-15 → QR-16 | 基线(变更触发) | CR 立案 |
| QR-16/17 → QR-18 | CR、影响分析 | CCB 决策 |
| QR-18 → 实施 → QR-19 | 批准 | 再验证 |
| QR-19 → QR-15/QR-22 | 验证结果 | 更新基线、登记日志 |
| QR-09/QR-20 → QR-21 | 追溯与覆盖核查 | 状态报告 |
